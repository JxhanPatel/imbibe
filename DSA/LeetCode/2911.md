# 2911. Minimum Changes to Make K Semi-palindromes 🔴

**Topics:** String, Dynamic Programming, Math

## Intuition

Imagine you have a row of colored tiles and you need to divide it into $k$ sections. Within each section, you pick a stride size $d$ smaller than the section's length, group tiles that are $d$ steps apart, and make sure every group is symmetric from front to back (like a palindrome). Repainting a tile costs $1$ unit of effort.

Instead of trying to pick cut points and repaint tiles all at once, picture peeling an onion from the outside in. For any candidate section with stride $d$, the leftmost block of $d$ tiles must mirror the rightmost block of $d$ tiles. Once you count how many tiles clash between those two outer blocks, you step inward by $d$ on both ends and repeat until the remaining middle is too short to form another pair. Doing this for every valid stride $d$ tells you the cheapest way to fix any slice on its own. With those slice costs ready, choosing $k$ cuts across the string becomes a clean step-by-step DP over how many pieces you have placed so far.

## Approach

This solution uses precomputed valid strides, memoized recursion to evaluate slice costs, and a dictionary-based DP over the number of partitions. (In the code below, a couple of small copy-paste issues from the draft, such as missing imports, multiplication signs in range bounds, and the final return statement, are completed so the code runs cleanly.)

1. **Collect proper divisors (`divs`):** For each possible stride `step` from `1` to `n - 1`, mark `step` as a valid divisor for every length `ln` from `2 * step` up to `n` in steps of `step`. Starting at `2 * step` ensures `step < ln` and every group has at least $2$ elements when needed, since a length of $1$ has no valid proper divisor.
2. **Peel outer blocks (`strip_crust`):** Given a slice `s[lo:hi]` and a valid stride `step`, if `hi - lo <= step`, no further outer-to-inner pairs remain, so return `0`. Otherwise, compare `s[lo:lo + step]` with `s[hi - step:hi]` element by element using `ne` (not equal) from `operator`, count mismatches, and recurse on `strip_crust(lo + step, hi - step, step)`. Peeling blocks of size `step` inward checks all stride-spaced palindrome pairs across the slice.
3. **Find best slice cost (`slice_fix`):** For a slice `s[lo:hi]`, take the minimum of `strip_crust(lo, hi, step)` across all `step` in `divs[hi - lo]`. Memoizing with `@cache` avoids recomputing the same slice cost across different split choices.
4. **Build partitions with `dp`:** Maintain `dp` mapping each valid split boundary `prev` (representing prefix `s[:prev]`) to the minimum changes needed to form the pieces placed so far, starting with `{0: 0}`.
* For `chunk` from `1` to `k - 1` (each piece before the final one), `span` iterates over valid end positions `end` for the current piece. Each piece needs at least $2$ characters, and the remaining `k - chunk` pieces still need at least $2$ characters each, giving `range(2 * chunk, n - 2 * (k - chunk) + 1)`.
* For each `end` in `span`, consider previous boundaries `prev` in `dp` with `prev <= end - 2` (so the current slice `s[prev:end]` has length at least $2$), and take the minimum of `dp[prev] + slice_fix(prev, end)`.


5. **Finish with the last piece:** After `k - 1` pieces are placed, the `k`-th piece must run from some `prev` in `dp` to `n`. Return `min(dp[prev] + slice_fix(prev, n) for prev in dp)`.

## Example Walkthrough

Let us trace `s = "abcac"` (`n = 5`) and `k = 2`.

1. **Divisors (`divs`):**
* `step = 1` adds `1` to lengths `2, 3, 4, 5`.
* `step = 2` adds `2` to length `4`.


2. **Initial state (`chunk = 1`):**
* `dp = {0: 0}`
* `span = range(2, 5 - 2 * (2 - 1) + 1)` = `range(2, 4)` -> `end` takes values `2` and `3`.
* For `end = 2`: `prev = 0` satisfies `0 <= 0`. `slice_fix(0, 2)` checks `"ab"` with `step = 1`: `'a' != 'b'` gives `1` mismatch. So `dp[2] = 0 + 1 = 1`.
* For `end = 3`: `prev = 0` satisfies `0 <= 1`. `slice_fix(0, 3)` checks `"abc"` with `step = 1`: `'a' != 'c'` gives `1` mismatch. So `dp[3] = 0 + 1 = 1`.
* After `chunk = 1`, `dp` is `{2: 1, 3: 1}`.


3. **Final piece (ending at `n = 5`):**
* `prev = 2`: `dp[2] + slice_fix(2, 5)`. Slice `"cac"` (`s[2:5]`) with `step = 1` compares `'c'` and `'c'`, giving `0` mismatches. Total = `1 + 0 = 1`.
* `prev = 3`: `dp[3] + slice_fix(3, 5)`. Slice `"ac"` (`s[3:5]`) with `step = 1` compares `'a'` and `'c'`, giving `1` mismatch. Total = `1 + 1 = 2`.



The minimum over both choices is `1`.

## Code

```python
class Solution:
    def minimumChanges(self, s: str, k: int) -> int:
        n = len(s)
        divs = [[] for _ in range(n+1)]

        for step in range(1, n):
            for ln in range(2 * step, n + 1, step):
                divs[ln].append(step)

        @cache
        def strip_crust(lo: int, hi: int, step: int) -> int:
            if hi - lo <= step:
                return 0

            mismatches = sum(map(ne, s[lo:lo + step], s[hi - step:hi]))
            return mismatches + strip_crust(lo + step, hi - step, step)

        @cache
        def slice_fix(lo: int, hi: int) -> int:
            return min(strip_crust(lo, hi, step) for step in divs[hi - lo])

        dp = {0: 0}

        for chunk in range(1, k):
            span = range(2 * chunk, n - 2 * (k-chunk) + 1)
            dp = {
                end: min(dp[prev] + slice_fix(prev, end) for prev in dp if prev <= end - 2)
                for end in span
            }

        return min(dp[prev] + slice_fix(prev, n) for prev in dp)
```

## Complexity

* **Time Complexity:** $O(n^3)$ in the worst case. Precomputing `divs` takes $O(n \log n)$ time. There are $O(n^2)$ slices `(lo, hi)`, and across all valid divisors `step` of a slice of length `L`, each character pair is inspected once per divisor, contributing $O(n^3)$ overall work across all slices. The DP runs for $k - 1$ chunks over at most $O(n)$ end positions and $O(n)$ prior cut points, taking $O(k \cdot n^2)$ time, which is bounded by $O(n^3)$ since $k \le n / 2$.
* **Space Complexity:** $O(n^2)$ to store `divs` and the memoized results of `strip_crust` and `slice_fix` across up to $O(n^2)$ index pairs, while the `dp` dictionary holds at most $O(n)$ entries at a time.

## Edge Cases

1. **Already semi-palindromic pieces:**
Input: `s = "aabbaa"`, `k = 3`.
Each piece `"aa"`, `"bb"`, and `"aa"` has `0` mismatches for `step = 1`, so the output is `0`.
2. **Smallest valid string length with one piece:**
Input: `s = "ab"`, `k = 1`.
Length is `2`, the only valid stride is `step = 1`, and changing one character gives `1` change.
3. **Maximum number of pieces (`k = n // 2`):**
Input: `s = "abcd"`, `k = 2`.
Each piece has length `2` (`"ab"` and `"cd"`), requiring `1` change each for a total of `2`.

## Lessons

* **Peeling from both ends simplifies palindrome checks:** Comparing symmetric segments from the outside inward (`lo + step` and `hi - step`) naturally mirrors palindrome symmetry while reusing memoized sub-slices.
* **Pruning the DP search space keeps transitions focused:** Computing exact `span` bounds and requiring `prev <= end - 2` prevents wasting transitions on slices too short to ever become semi-palindromes.
* **Separating local cost from global partitioning makes DP modular:** Treating `slice_fix(lo, hi)` as a standalone cost function lets the partition DP focus purely on where to place boundaries.
