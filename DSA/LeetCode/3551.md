# 3551. Minimum Swaps to Sort by Digit Sum 🟡

**Topics**: Sorting, Permutations, Graph Theory, Array


## Intuition

Imagine you have a line of numbered lockers, and each person currently standing in front of a locker needs to move to their designated target locker based on a new rule. If you trace the path of people moving around, they form closed loops or cycles. For example, person A goes to locker B's position, person B goes to locker C's position, and person C goes back to locker A's position.

To break a cycle of length $K$ and put everyone in their correct locker, you need exactly $K - 1$ swaps. If you have multiple independent cycles, the total minimum swaps required is simply the sum of $(C_i - 1)$ for each cycle $C_i$, which mathematically equals the total number of elements minus the number of independent cycles.


## Approach

1. **Define the Custom Sorting Key**: For each number in the array, compute its digit sum and keep track of its original value. The problem states that the primary sorting key is the digit sum in increasing order, and the secondary sorting key is the numeric value itself in increasing order.
2. **Pair and Sort**: Create a list of tuples containing `(digit_sum, value, original_index)`. Sort this list to determine the target sorted positions for each element.
3. **Map Original Indices to Target Indices**: Since all elements in `nums` are distinct, each element has a unique correct destination index in the sorted array.
4. **Find Cycles Using Visited Tracking**: Use a boolean array to keep track of visited indices. For each unvisited index, traverse the cycle by jumping to the target index repeatedly until we loop back to the start. Each cycle of length $L$ contributes $L - 1$ swaps to our total count.


## Example Walkthrough

Let us trace Example 3 with `nums = [18, 43, 34, 16]`:

* **Step 1: Compute digit sums**
* `18` $\to$ digit sum = $1 + 8 = 9$
* `43` $\to$ digit sum = $4 + 3 = 7$
* `34` $\to$ digit sum = $3 + 4 = 7$
* `16` $\to$ digit sum = $1 + 6 = 7$


* **Step 2: Sort based on digit sum, then value**
Sorted order of items `(digit_sum, value, original_index)`:
* `(7, 16, 3)` at index 0
* `(7, 34, 2)` at index 1
* `(7, 43, 1)` at index 2
* `(9, 18, 0)` at index 3


* **Step 3: Determine target positions**
The original indices mapped to their sorted target indices:
* Original index `0` (`18`) goes to position `3`.
* Original index `1` (`43`) goes to position `2`.
* Original index `2` (`34`) goes to position `1`.
* Original index `3` (`16`) goes to position `0`.


* **Step 4: Trace Cycles**
* Start at index `0`: goes to `3`, then `3` goes to `0`. Cycle length = 2. Swaps needed = $2 - 1 = 1$.
* Start at index `1`: goes to `2`, then `2` goes to `1`. Cycle length = 2. Swaps needed = $2 - 1 = 1$.
* Total swaps = $1 + 1 = 2$.




### Code

```python
def get_digit_sum(x: int) -> int:
    total=0
    while x>0:
        total += x%10
        x //= 10
    return total

class Solution:
    def minSwaps(self, nums: list[int]) -> int:
        n = len(nums)
        
        indexed_nums = sorted((get_digit_sum(val), val, i) for i, val in enumerate(nums))
        
        target_pos = [0]*n
        for sorted_idx, (_, _, orig_idx) in enumerate(indexed_nums):
            target_pos[orig_idx] = sorted_idx
            
        visited = [False] * n
        swaps=0
        
        for i in range(n):
            if visited[i] or target_pos[i] == i:
                continue
                
            curr=i
            cycle_length = 0
            
            while not visited[curr]:
                visited[curr] = True
                curr = target_pos[curr]
                cycle_length += 1
                
            if cycle_length > 1:
                swaps += cycle_length - 1
                
        return swaps
```


## Complexity

* **Time Complexity**: $O(n \log n + n \log (\text{max\_val}))$. Computing the digit sum for each number takes $O(\log(\text{max\_val}))$ time. Sorting $n$ elements takes $O(n \log n)$ time. Traversing and finding cycles takes $O(n)$ time. Thus, the overall time complexity is dominated by the sorting step: $O(n \log n)$.
* **Space Complexity**: $O(n)$ to store the indexed tuples, target position mapping array, and the visited boolean array.


## Edge Cases

* **Already Sorted Array**: When `nums = [22, 14, 33, 7]`, every element is already at its target position (`target_pos[i] == i`). The cycle lengths are all 1, resulting in `0` swaps.
* **Single Element Array**: When `nums.length == 1`, the loop skips and returns `0` swaps correctly.
* **All Elements with Same Digit Sum**: When all elements share the same digit sum, the secondary sorting key (numerical value) ensures a deterministic and correct total order.


## Lessons

* **Permutation Cycles**: Recognizing that sorting an array with distinct elements can be modeled as finding permutation cycles is a powerful pattern for minimum swap problems.
* **Custom Multi-Level Keys**: Using tuples `(digit_sum, value, original_index)` allows Python's built-in `sorted()` function to effortlessly handle primary and secondary sorting criteria.
* **Tracking Original Indices**: Preserving original indices through tuples is essential when mapping elements from their initial positions to their final sorted destinations.
