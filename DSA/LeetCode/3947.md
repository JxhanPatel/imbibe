## 3947. Maximum Number of Items From Sale II 🟡

**Topics:** Array, Greedy, Math, Bit Manipulation, Sorting

## Intuition

Think about shopping at a store where you can always buy plain single items at the lowest available price, `min_p`. Every dollar spent on that baseline item gets you a steady exchange rate of 1 item per `min_p` dollars.

Now suppose a specific item gives you a free bonus item whenever you buy a copy of it, up to `freebies` times (once per distinct valid target item whose factor is a multiple of your item's factor). Each of those first `freebies` copies turns one purchase into **2 items** total: the purchased copy plus 1 free copy.

That 2-for-1 deal beats buying two plain copies at `min_p` each whenever its cost is less than `2 * min_p`. Once you pass `freebies` copies of that item, extra copies do not trigger new freebies, so they only give 1 item each, making the plain `min_p` item just as good or better. To squeeze out the most items before your budget runs out, you should grab the cheapest qualifying 2-for-1 deals first, then put whatever budget is left into the cheapest baseline item.

## Approach

1. **Find the baseline price and item count:** Let `size = len(items)` and `min_p` be the minimum price across all items. Any 2-for-1 deal only beats buying two baseline items if `cost < 2 * min_p` (stored in `cap`).
2. **Count how many items share each factor:** Build `freq` of size `size + 1` and count how many items have each factor `fac`. Since `1 <= factor <= items.length`, `size + 1` covers every possible factor.
3. **Count valid freebie targets per factor:** For each factor `d` from `1` to `size`, `freq[d::d]` slices all multiples of `d` (`d`, `2*d`, `3*d`, ...) in `freq`. Summing them counts all items whose factor is a multiple of `d`, including items at the same factor `d` (which still satisfy `i != j` if multiple items have factor `d`). Subtracting `1` gives `hits[d]`, the number of distinct other items `j != i` whose factor is divisible by `d`.
4. **Pack and sort qualifying deals:** For each item `[fac, cost]` where `hits[fac] > 0` and `cost < cap`, pack `cost` and `hits[fac]` into a single integer using bit shifting (`cost << 17 | hits[fac]`). Because `131071` is $2^{17} - 1$, the lower 17 bits hold `freebies` and the upper bits hold `cost`. Sorting these packed numbers sorts directly by `cost` in ascending order (and breaks ties by `freebies`).
5. **Greedily claim 2-item bundles:** Loop through `packed` and unpack `cost` and `freebies`. Calculate how many pairs you can afford with the remaining budget (`budget - used`), capped at `freebies`. Add `take * cost` to `used` and `take` to `pairs`. If `take < freebies`, you ran out of budget mid-deal, so you can stop early.
6. **Spend remaining budget on cheapest items:** Return `2 * pairs + (budget - used) // min_p`.

## Example Walkthrough

Trace `items = [[1, 6], [2, 4], [3, 5]]` and `budget = 19`.

* `size = 3`, `min_p = 4`, `cap = 8`.
* `freq` after counting factors: `[0, 1, 1, 1]`.
* `hits` calculation:
* `d = 1`: `sum(freq[1::1]) - 1 = (1 + 1 + 1) - 1 = 2`.
* `d = 2`: `sum(freq[2::2]) - 1 = (1) - 1 = 0`.
* `d = 3`: `sum(freq[3::3]) - 1 = (1) - 1 = 0`.


* `packed` list: only item `[1, 6]` has `hits[1] = 2 > 0` and `6 < 8`, so it packs `6` and `2` into `packed`.
* Greedy loop:
* Unpacks `cost = 6`, `freebies = 2`.
* Remaining budget is `19 - 0 = 19`. Affordable copies: `19 // 6 = 3`, capped by `freebies = 2`, so `take = 2`.
* `used` becomes `12`, `pairs` becomes `2`.


* Final calculation: `2 * 2 + (19 - 12) // 4 = 4 + 1 = 5`.

## Code & Comments

```python
class Solution:
    def maximumSaleItems(self, items: List[List[int]], budget: int) -> int:
        size = len(items)
        min_p = min(cost for _, cost in items)
        cap = 2 * min_p
        freq = [0] * (size + 1)
        
        for fac, _ in items:
            freq[fac] += 1
        hits = [0] * (size + 1)

        for d in range(1, size + 1):
            if freq[d]:
                hits[d] = sum(freq[d::d]) - 1

        packed = sorted(cost << 17 | hits[fac] for fac, cost in items if cost < cap and hits[fac])
        used = pairs = 0

        for blob in packed:
            cost = blob >> 17
            freebies = blob & 131071
            take = (budget - used) // cost

            if take > freebies:
                take = freebies
            used += take * cost
            pairs += take

            if take < freebies:
                break

        return 2 * pairs + (budget - used) // min_p

```

## Complexity

* **Time Complexity:** $O(n \log n)$ where $n$ is the number of items. Counting frequencies takes $O(n)$, summing multiples via step slices `freq[d::d]` across $d = 1 \dots n$ takes $\sum_{d=1}^{n} \frac{n}{d} = O(n \log n)$ operations, and sorting `packed` takes $O(n \log n)$.
* **Space Complexity:** $O(n)$ for the `freq`, `hits`, and `packed` arrays.

## Edge Cases

1. **No item unlocks any freebies (`hits[fac] == 0` for all items):**
Input: `items = [[2, 10], [3, 4]]`, `budget = 15`.
Result: `packed` is empty, `pairs = 0`, and the function returns `15 // 4 = 3`.
2. **Freebie-giving item is too expensive (`cost >= 2 * min_p`):**
Input: `items = [[1, 20], [2, 5]]`, `budget = 25`.
Result: Item `0` gives a freebie, but `20 >= 10`, so it is excluded. The function spends the budget on the `5`-cost item and returns `25 // 5 = 5`.
3. **Budget runs out before using all available freebies on a deal:**
Input: `items = [[1, 10], [2, 2], [3, 2]]`, `budget = 15`.
Result: Item `0` has `freebies = 2` at `cost = 10`, so `take = min(2, 15 // 10) = 1`, `used = 10`, `pairs = 1`, and the remaining `5` buys `5 // 2 = 2` baseline items, giving `2 * 1 + 2 = 4`.

## Lessons

* **Compare deals against the best constant-rate baseline:** When a problem lets you pick up a cheap base item repeatedly, any multi-item offer can be judged directly against that baseline rate.
* **Harmonic series for multiples:** Stepping through multiples of `1` through `n` takes $O(n \log n)$ time overall because the sum of reciprocals $1 + \frac{1}{2} + \frac{1}{3} + \dots + \frac{1}{n}$ grows logarithmically.
* **Bit packing for clean sorting:** Combining two small non-negative integers into one value with `<<` and `|` lets you sort by the primary key while keeping secondary data attached without creating tuples.
