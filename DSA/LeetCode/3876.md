# 3876. Construct Uniform Parity Array II 🟡

**Topics:** Array, Math

## Intuition

The main idea is to determine whether we can make **all numbers odd** or **all numbers even**.

The important observation is that:

```text
even - odd = odd
```

So if we have an even number, we can turn it into an odd number by subtracting a smaller odd number.

For example:

```text
6 - 3 = 3
```

Therefore, the most useful number in the array is the **smallest odd number**.

Why?

Suppose the smallest odd number is `3`.

Any even number greater than `3` can subtract `3`:

```text
4 - 3 = 1
8 - 3 = 5
10 - 3 = 7
```

All of them become positive odd numbers.

But if we have an even number smaller than `3`:

```text
2
```

we cannot subtract `3` because:

```text
2 - 3 < 1
```

So the construction becomes impossible.

This gives us a simple rule:

> Find the smallest odd number. If any even number is smaller than it, return `False`. Otherwise, return `True`.


## Approach

We use **two passes** through the array.

### Step 1: Find the smallest odd number

We initialize:

```python
smallest_odd = None
```

Then scan the array.

Whenever we find an odd number, we update `smallest_odd` if:

* We haven't found an odd number yet, or
* The current number is smaller.

For example:

```text
nums1 = [7, 4, 9, 3, 8]
```

The odd numbers are:

```text
7, 9, 3
```

So:

```text
smallest_odd = 3
```


### Step 2: Handle the case with no odd numbers

If:

```python
smallest_odd is None
```

then every number is even.

The array is already uniform in parity.

So we return:

```python
True
```


### Step 3: Check every even number

Now we scan the array again.

For every even number, we check:

```python
n < smallest_odd
```

If this is true, the even number cannot subtract the smallest odd number while remaining positive.

Therefore, construction is impossible:

```python
return False
```

Otherwise, every even number can be converted into an odd number.

At the end:

```python
return True
```


## Example Walkthrough

Consider:

```text
nums1 = [1, 4, 7]
```

### First pass

We look for the smallest odd number.

```text
1 → odd → smallest_odd = 1
4 → even → ignore
7 → odd → 7 > 1 → ignore
```

So:

```text
smallest_odd = 1
```

### Second pass

Now check the even numbers.

```text
1 → odd → ignore
4 → even → 4 < 1? No
7 → odd → ignore
```

There is no problematic even number.

So we return:

```text
True
```

And we can construct:

```text
[1, 3, 7]
```

because:

```text
4 - 1 = 3
```

All numbers are odd.


## Example Where It Fails

Consider:

```text
nums1 = [2, 3]
```

### First pass

The only odd number is:

```text
3
```

Therefore:

```text
smallest_odd = 3
```

### Second pass

We encounter:

```text
2
```

It is even, and:

```text
2 < 3
```

So `2` cannot subtract the smallest odd number.

Therefore:

```python
return False
```


## Code

```python
from typing import List
class Solution:
    def uniformArray(self, nums1: List[int]) -> bool:
        smallest_odd = None


        for n in nums1:
            if n%2 == 1:
                if smallest_odd is None or n < smallest_odd:
                    smallest_odd = n


        if smallest_odd is None:
            return True


        for n in nums1:
            if n%2 == 0 and n < smallest_odd:
                return False


        return True
```


## Why Do We Only Care About the Smallest Odd?

This is the key insight of the problem.

Suppose:

```text
nums1 = [3, 8, 11, 14]
```

The smallest odd number is:

```text
3
```

Every even number is larger than `3`.

So:

```text
8 - 3 = 5
14 - 3 = 11
```

Both become odd.

The existing odd numbers can simply stay unchanged:

```text
3, 11
```

Therefore, we can construct:

```text
[3, 5, 11, 11]
```

All elements are odd.

Now consider:

```text
[2, 3, 8]
```

The smallest odd number is `3`, but `2` is smaller.

There is no smaller odd number available to subtract from `2`.

So we cannot make the array uniform.

That is exactly what the second loop detects.


## Complexity

### Time Complexity

We make two passes through the array.

First pass:

$$
O(n)
$$

Second pass:

$$
O(n)
$$

Therefore:

$$
O(n) + O(n) = O(n)
$$

### Space Complexity

We only use the `smallest_odd` variable.

$$
O(1)
$$


## Edge Cases

### 1. All numbers are even

```text
nums1 = [2, 4, 6, 8]
```

There is no odd number.

The array is already uniform.

```text
True
```


### 2. All numbers are odd

```text
nums1 = [1, 3, 5, 7]
```

They are already uniform.

```text
True
```


### 3. An even number is smaller than the smallest odd

```text
nums1 = [2, 5, 7]
```

Smallest odd:

```text
5
```

But:

```text
2 < 5
```

So the answer is:

```text
False
```


### 4. Smallest odd is `1`

```text
nums1 = [1, 4, 6, 9]
```

Every positive even number is greater than `1`, so every even number can subtract `1`.

```text
4 - 1 = 3
6 - 1 = 5
```

Therefore:

```text
True
```


## Lessons

* When a problem involves odd and even numbers, first write down the **parity rules**.
* The important rule here is:

```text
even - odd = odd
```

* When subtraction must produce a positive number, the **smallest possible subtractor** becomes very important.
* Instead of actually constructing `nums2`, we can determine whether construction is possible.
* The problem can therefore be reduced to:

  1. Find the smallest odd number.
  2. Make sure no even number is smaller than it.
* Two simple linear scans are enough, giving:

$$
O(n)
$$

time and:

$$
O(1)
$$

space.
