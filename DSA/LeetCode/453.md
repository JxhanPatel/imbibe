## 453. Minimum Moves to Equal Array Elements 🟡

**Topics:** Math, Array

### Intuition

Imagine you have a group of friends sharing a pizza sliced into uneven pieces, and your goal is to make all pieces equal in size. The rules say you can take any $n - 1$ pieces and give each of them a tiny bite (increment them by 1). Instead of trying to grow $n - 1$ pieces up to match the largest one, which gets messy and complicated, flip your perspective.

Incrementing $n - 1$ elements by 1 is the exact same as leaving the single smallest element alone and letting everyone else drop down to meet it. By shifting your frame of reference, the problem transforms into finding how far each element is from the absolute smallest element in the array and summing up those distances.

### Approach

1. Find the minimum value in the array.
2. Iterate through each number in the array.
3. Compute the difference between each number and the minimum value.
4. Sum all these differences to get the total number of increments needed to bring every element to parity.
5. Alternatively, the sum of differences can be expressed as the sum of all elements minus $n$ times the minimum element.

### Example Walkthrough

Let us trace `nums = [1, 2, 3]` with $n = 3$:

* The minimum element is `1`.
* Calculate the difference for each element:
* Element `1`: $1 - 1 = 0$
* Element `2`: $2 - 1 = 1$
* Element `3`: $3 - 1 = 2$


* Sum the differences: $0 + 1 + 2 = 3$.
* Output: `3`.

### Code

```python
class Solution:
    def minMoves(self, nums: List[int]) -> int:
        m = min(nums)
        return sum(x-m for x in nums)

```

### Complexity

* **Time Complexity:** $O(n)$ where $n$ is the length of the array. We scan the array to find the minimum and compute the total sum of differences in linear time.
* **Space Complexity:** $O(1)$ as we only maintain a few scalar variables without allocating any auxiliary data structures.

### Edge Cases

* **All elements are already equal** (e.g., `[1, 1, 1]`): The minimum is `1`, differences are all `0`, and total moves equal `0`.
* **Negative numbers included** (e.g., `[-1, 0, 1]`): Minimum is `-1`. Differences are `-1 - (-1) = 0`, `0 - (-1) = 1`, and `1 - (-1) = 2`. Sum is `3`. The arithmetic holds across negative domains.
* **Two elements** (e.g., `[1, 10]`): Minimum is `1`. Difference is $10 - 1 = 9$ moves.

### Lessons

* **Inversion of perspective:** When a problem describes modifying the majority of elements ($n-1$), consider how the complement operation affects the system.
* **Mathematical reduction:** Translating a dynamic simulation process into a static arithmetic formula reduces time complexity from exponential or simulation heavy approaches down to optimal linear time.
