# 3116. Kth Smallest Amount With Single Denomination Combination 🔴


**Topics:** Array, Math, Bit Manipulation, Binary Search, Inclusion-Exclusion

## Intuition

Imagine each coin denomination creates its own sequence of amounts.

For example, with:

```text
coins = [2, 5]
```

we get:

```text
2:  2, 4, 6, 8, 10, 12, ...
5:  5, 10, 15, 20, ...
```

We need the `kth` smallest number in the union of these sequences.

The difficult part is that some amounts appear in multiple sequences. For example, `10` is both a multiple of `2` and `5`, but it should only be counted once.

So instead of generating amounts one by one, we ask a more useful question:

> How many valid amounts are less than or equal to `x`?

If we can calculate that count, we can use binary search to find the smallest `x` containing at least `k` valid amounts.

To avoid counting duplicates, we use the **Inclusion-Exclusion Principle**.


## Approach

### 1. Binary search on the answer

For any value `x`, define:

```text
count(x) = number of distinct valid amounts <= x
```

This function is monotonic:

```text
x increases -> count(x) never decreases
```

Therefore, we can binary search for the smallest `x` such that:

```text
count(x) >= k
```

That `x` is our answer.


### 2. Count multiples using Inclusion-Exclusion

For one coin `c`, the number of multiples less than or equal to `x` is:

$$
\left\lfloor \frac{x}{c} \right\rfloor
$$

For example, if `x = 12`:

```text
multiples of 2 = 6
multiples of 5 = 2
```

So we might write:

```text
6 + 2 = 8
```

But this counts `10` twice.

To fix this, we subtract numbers divisible by both `2` and `5`.

Numbers divisible by both must be multiples of:

$$
operatorname{lcm}(2, 5) = 10
$$

There is:

$$
\left\lfloor \frac{12}{10} \right\rfloor = 1
$$

such number.

Therefore:

$$
count(12)=
\left\lfloor \frac{12}{2} \right\rfloor
+
\left\lfloor \frac{12}{5} \right\rfloor-
\left\lfloor \frac{12}{10} \right\rfloor
$$

$$
= 6 + 2 - 1 = 7
$$

For more coins, we examine every non-empty subset:

* Odd-sized subset: add its count.
* Even-sized subset: subtract its count.

For each subset, we calculate the LCM of its coins.

Since there are at most `15` coins, there are at most:

$$
2^{15} - 1 = 32767
$$

non-empty subsets, which is manageable.


## Example Walkthrough

Consider:

```text
coins = [5, 2]
k = 7
```

The valid amounts are:

```text
2, 4, 5, 6, 8, 10, 12, ...
```

We want the `7th` smallest amount.

### Check `x = 10`

Multiples of `2`:

```text
2, 4, 6, 8, 10
```

Count:

```text
10 // 2 = 5
```

Multiples of `5`:

```text
5, 10
```

Count:

```text
10 // 5 = 2
```

But `10` appears in both sequences.

The LCM is:

```text
lcm(2, 5) = 10
```

Common multiples:

```text
10 // 10 = 1
```

Using inclusion-exclusion:

$$
count(10) = 5 + 2 - 1 = 6
$$

So `10` is too small because we need `7` valid amounts.


### Check `x = 12`

```text
12 // 2 = 6
12 // 5 = 2
12 // lcm(2,5) = 12 // 10 = 1
```

Therefore:

$$
count(12) = 6 + 2 - 1 = 7
$$

Now we have exactly `7` valid amounts.

So:

```text
Answer = 12
```

Binary search finds this smallest value where:

```text
count(x) >= 7
```


## Code

```python
from typing import List
from math import gcd


class Solution:
    def findKthSmallest(self, coins: List[int], k: int) -> int:
        n = len(coins)

        def count_le(x: int) -> int:
            total=0
            
            for mask in range(1, 1 << n):
                subset_lcm=1
                bit_count=0
                too_big=False

                for i in range(n):
                    if not (mask & (1 << i)):
                        continue

                    bit_count += 1
                    subset_lcm = subset_lcm // gcd(subset_lcm, coins[i]) * coins[i]

                    if subset_lcm > x:
                        too_big = True
                        break

                if too_big:
                    continue

                cnt = x // subset_lcm
                if bit_count%2:
                    total += cnt

                else:
                    total -= cnt


            return total

        lo, hi = 1, min(coins)*k

        while lo < hi:
            mid = (lo+hi) // 2

            if count_le(mid) >= k:
                hi = mid
                
            else:
                lo = mid+1

        return lo
```

## Complexity

Let:

$$
n = \text{len(coins)}
$$

For every binary search step, we process all subsets:

$$
O(2^n)
$$

For each subset, we may process up to `n` coins.

So one `count(x)` call takes:

$$
O(n \cdot 2^n)
$$

Binary search performs:

$$
O(\log(k \cdot \min(coins)))
$$

iterations.

Therefore, the total time complexity is:

$$
O\left(n \cdot 2^n \cdot \log(k \cdot \min(coins))\right)
$$

Space complexity:

$$
O(1)
$$

excluding the input array.

## Edge Cases

1. **Only one denomination**

```text
coins = [7]
k = 5
```

The amounts are:

```text
7, 14, 21, 28, 35
```

Answer:

```text
35
```

The answer is simply:

$$
7 \times 5
$$

2. **One denomination divides another**

```text
coins = [3, 6, 9]
k = 3
```

Every multiple of `6` and `9` is already part of the multiples of `3`.

The valid sequence is:

```text
3, 6, 9, 12, ...
```

Answer:

```text
9
```

Inclusion-exclusion correctly removes all duplicate counts.

3. **Large `k`**

```text
k = 2 * 10^9
```

Generating amounts directly is impossible.

Binary search works efficiently because we only check how many valid amounts exist up to a candidate value.

4. **Subset LCM becomes very large**

While building the LCM, it may become larger than the current `x`.

Once:

```text
lcm > x
```

that subset contributes:

```text
x // lcm = 0
```

So we can stop processing that subset early.

## Lessons

* When asked for the `kth` smallest value in an implicit sorted set, consider **binary search on the answer**.

* A useful transformation is to ask:

  > How many valid values are less than or equal to `x`?

* When several sequences overlap and values must be counted only once, think about the **Inclusion-Exclusion Principle**.

* For divisibility problems, the overlap between multiple sequences is determined using their **LCM**.

* With at most `15` elements, iterating through all:

$$
2^n
$$

subsets is often practical.

* The combination of **binary search + counting function + inclusion-exclusion** is a powerful pattern for solving hard counting problems.
