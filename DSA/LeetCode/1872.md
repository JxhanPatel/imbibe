# 1872. Stone Game VIII 🔴

**Topics:** Array, Math, Dynamic Programming, Game Theory, Prefix Sum

## Intuition

At first, this game seems to have many possible moves.

On each turn, a player can choose any `x > 1` and merge the first `x` stones. That sounds like we may need to simulate many different game states.

But there is an important observation.

After merging the first `x` stones, their sum becomes a new stone at the front. So the game always has this form:

```text
[prefix sum, remaining stones...]
```

For example:

```text
stones = [-1, 2, -3, 4, -5]
```

If we merge the first `3` stones:

```text
[-1, 2, -3] -> -2
```

The new state becomes:

```text
[-2, 4, -5]
```

Notice that `-2` is exactly:

```text
prefix[2]
```

So every possible first move is determined by a prefix sum.

Think of it like a stack of money.

A player can take a prefix of the stack, collect its total value, and compress it into one new item. The next player then faces the same type of decision.

Instead of storing the entire array after every move, we only need to know the best score difference possible from each prefix position.

The key recurrence is:

$$
dp[i] = \max(prefix[i] - dp[i+1],\ dp[i+1])
$$

But we can simplify this even further.

Since:

$$
dp[i+1] \ge prefix[i+1]
$$

the optimal transition becomes:

$$
dp[i] = \max(dp[i+1], prefix[i])
$$

This means we can solve the problem by scanning the prefix sums from right to left.

## Approach

### Step 1: Build prefix sums

Let:

$$
prefix[i] = stones[0] + stones[1] + \cdots + stones[i]
$$

For:

```text
[-1, 2, -3, 4, -5]
```

the prefix sums are:

```text
[-1, 1, -2, 2, -3]
```

If a player merges the first `i + 1` stones, they gain `prefix[i]`.

### Step 2: Understand the DP state

Let `best` represent the maximum score difference the current player can guarantee.

Initially, the smallest valid game state involves the first two stones:

```text
best = prefix[n - 1]
```

Then process possible prefix sums from right to left.

For every position `i`:

```python
best = max(best, prefix[i])
```

Why?

The current player has two effective choices:

1. Take the current prefix sum and end up with the advantage represented by that prefix.
2. Leave the previously computed best strategy available.

So we keep the maximum.

### Step 3: Process from right to left

We start at:

```text
prefix[n - 1]
```

and move backward until index `1`.

Index `0` is never considered because a move must remove at least two stones.

## Example Walkthrough

Consider:

```text
stones = [-1, 2, -3, 4, -5]
```

### Step 1: Calculate prefix sums

```text
prefix[0] = -1
prefix[1] = 1
prefix[2] = -2
prefix[3] = 2
prefix[4] = -3
```

So:

```text
[-1, 1, -2, 2, -3]
```

### Step 2: Start from the right

Initially:

```text
best = prefix[4] = -3
```

Now move from right to left.

### `i = 3`

```text
prefix[3] = 2

best = max(-3, 2)
     = 2
```

### `i = 2`

```text
prefix[2] = -2

best = max(2, -2)
     = 2
```

### `i = 1`

```text
prefix[1] = 1

best = max(2, 1)
     = 2
```

This direct prefix comparison alone needs one subtle DP interpretation: the right-to-left value represents the optimal score difference after accounting for alternating turns.

A cleaner implementation uses the standard recurrence directly:

$$
dp[i] = \max(dp[i+1], prefix[i] - dp[i+1])
$$

However, for this problem it simplifies to maintaining:

```text
best = max(best, prefix[i])
```

with the correct initialization and right-to-left traversal.

For this example, the optimal result is:

```text
5
```

The optimal sequence is:

```text
Alice gains 2
Bob gains -3
```

Therefore:

$$
2 - (-3) = 5
$$

**Output**

```text
5
```

## Code

```python
class Solution:
    def stoneGameVIII(self, stones: List[int]) -> int:
        n = len(stones)
        prefix = stones

        for i in range(1, n):
            prefix[i] += prefix[i-1]

        best = prefix[-1]
        for i in range(n-2,0,-1):
            take = prefix[i] - best
            
            if take > best:
                best = take

        return best
```

### Why does `stones[i] - best` work?

Suppose the current player chooses the first `i + 1` stones.

They immediately gain:

```text
prefix[i]
```

After that move, the opponent can play optimally and obtain a score advantage of:

```text
best
```

Since this is a zero-sum score difference game, the current player's final advantage becomes:

$$
prefix[i] - best
$$

So at every position:

$$
dp[i] = \max(dp[i+1], prefix[i] - dp[i+1])
$$

This is why the update is:

```python
best = max(best, stones[i] - best)
```

The right-to-left traversal lets us store only one DP value instead of an entire array.

## Complexity

**Time Complexity**

Building prefix sums:

$$
O(n)
$$

Dynamic programming traversal:

$$
O(n)
$$

Overall:

$$
O(n)
$$

**Space Complexity**

$$
O(1)
$$

We reuse the `stones` array to store prefix sums.

## Edge Cases

### 1. Only two stones

```text
stones = [-10, -12]
```

Alice must take both stones:

```text
-10 + -12 = -22
```

Answer:

```text
-22
```

### 2. All positive values

```text
stones = [1, 2, 3, 4]
```

Taking a larger prefix may be beneficial, but the DP still checks every valid decision optimally.

### 3. All negative values

```text
stones = [-5, -2, -8, -1]
```

A player may be forced to gain a negative score.

This is important because we cannot assume taking more stones always gives a better result.

### 4. Mixed positive and negative values

```text
stones = [-1, 2, -3, 4, -5]
```

The best move is not necessarily taking all stones.

The example demonstrates why greedy choices based only on the current prefix sum can fail.

### 5. Large input

```text
n = 10^5
```

Trying every possible game state directly would be too slow.

The prefix sum plus optimized DP solution runs in:

$$
O(n)
$$

which fits the constraint.

## Lessons

* When repeated operations merge elements into their sum, prefix sums are often hiding inside the problem.
* Game theory problems can frequently be expressed as a score difference DP.
* A useful recurrence for two-player zero-sum games is:

$$
current\ gain - opponent's\ best\ result
$$

* Processing DP from right to left can reduce an $O(n)$ DP array to $O(1)$ extra space.
* Do not try to simulate every possible game sequence when the game states have a mathematical structure.
* The key pattern here is:

```text
Prefix Sum + Minimax DP + Space Optimization
```

The recurrence is the most important part to understand:

$$
dp[i] = \max(dp[i+1], prefix[i] - dp[i+1])
$$

This lets us transform a difficult-looking game with many possible moves into a simple linear scan.
