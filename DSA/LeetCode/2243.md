## 2243. Calculate Digit Sum of a String 🟢

**Topics:** String, Simulation

## Intuition

Think of this problem like packing long rows of numbers into boxes of size `k`, crushing each box down into the sum of its digits, and lining those sums up side by side. If the new line of text is still longer than `k`, you repeat the whole packing and crushing process until the string is short enough to fit within the limit.

Because each round replaces a group of up to `k` characters with a single number string (usually just one or two digits), the string shrinks quickly and is guaranteed to stop once its length is no longer greater than `k`.

## Approach

We can solve this directly by simulating the rounds described in the problem:

1. **Loop condition:** Keep running rounds while the current length of `s` is greater than `k`.
2. **Slice into chunks of size `k`:** Step through `s` using `range(0, len(s), k)` and take `s[i : i + k]`. Python slicing naturally handles the last chunk even when fewer than `k` characters remain.
3. **Sum the digits:** Convert each character in the chunk to an integer, add them together, and convert the total back into a string.
4. **Rebuild `s`:** Join the summed pieces together to form the string for the next round. Once `len(s)` is less than or equal to `k`, return `s`.

This direct simulation matches the rules word for word and avoids tricky math shortcuts that could miscount multi-digit sums like `13`.

## Example Walkthrough

Let's trace `s = "11111222223"` and `k = 3`:

* **Initial state:** `s = "11111222223"` (length is `11`, which is greater than `3`).

**Round 1:**

* Slice index `0`: `"111"` -> $1 + 1 + 1 = 3$ -> `"3"`
* Slice index `3`: `"112"` -> $1 + 1 + 2 = 4$ -> `"4"`
* Slice index `6`: `"222"` -> $2 + 2 + 2 = 6$ -> `"6"`
* Slice index `9`: `"23"` -> $2 + 3 = 5$ -> `"5"`
* **After Round 1:** `s = "3465"` (length is `4`, still greater than `3`).

**Round 2:**

* Slice index `0`: `"346"` -> $3 + 4 + 6 = 13$ -> `"13"`
* Slice index `3`: `"5"` -> $5$ -> `"5"`
* **After Round 2:** `s = "135"` (length is `3`, not greater than `3`).

The loop stops and returns `"135"`.

## Code

```python
class Solution:
    def digitSum(self, s: str, k: int) -> str:
        while len(s) > k:
            squished=[]

            for idx in range(0, len(s), k):
                chunk = s[idx : idx + k]

                yum = sum(int(ch) for ch in chunk)
                squished.append(str(yum))
                
            s = "".join(squished)
        return s
```

## Complexity

* **Time Complexity:** $O(n)$ in typical cases (with a conservative upper bound of $O(n \log n)$), where $n$ is the initial length of `s`. Each round inspects every character once to form chunks and sum digits. After the first round, the string length drops to at most $2 \lceil n / k \rceil$, and subsequent rounds operate on progressively smaller strings until the length is at most `k`.
* **Space Complexity:** $O(n)$ to store the new list of summed chunks and construct the updated string during each round.

## Edge Cases

1. **String already within limit `k`:**
* Input: `s = "42"`, `k = 3`
* Expected Output: `"42"` (length is `2`, so zero rounds run).


2. **All zero digits:**
* Input: `s = "00000000"`, `k = 3`
* Expected Output: `"000"` (`"000"`, `"000"`, `"00"` each sum to `0`, giving `"000"` of length `3`).


3. **Repeated multi-digit sums with small `k`:**
* Input: `s = "99999"`, `k = 2`
* Expected Output: `"99"` (`"99999"` -> `"18189"` -> `"999"` -> `"189"` -> `"99"`).



## Lessons

* **Simulate when constraints are small:** With `s.length` up to `100`, straightforward simulation is clean, bug-free, and fast enough without overcomplicating the logic.
* **Range step slicing (`range(0, len(s), k)`) is a clean idiom for fixed-size windowing:** It handles uneven tail slices automatically without extra boundary checks.
* **Always re-check loop exit conditions after mutations:** Because summing digits like `3 + 4 + 6 = 13` can produce two characters instead of one, the string might stay above length `k` for more rounds than you might guess at first glance.
