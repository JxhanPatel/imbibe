# 3841: Palindromic Path Queries in a Tree 🔴
**Topics**: Tree, Bit Manipulation, Heavy-Light Decomposition, Segment Tree

## Intuition

Imagine string characters as colored beads threaded along tree branches. A sequence of beads can form a symmetric palindrome if every color appears an even number of times, except possibly one color that appears an odd number of times in the center. Instead of tracking the exact count of all twenty-six alphabet letters along a path, we can assign each character a 26-bit mask where each bit represents parity. Since XORing numbers twice cancels them out, the bitwise XOR sum of all node masks along a path tells us the exact parity of every character. Checking if this XOR sum forms a palindrome reduces to checking if the binary representation has at most one set bit. To handle updates and path queries efficiently across tree structures, we use Heavy-Light Decomposition combined with a Segment Tree.

## Approach

* **Bitmask Representation:** Represent each character $c$ as $1 \ll (c - 'a')$. The parity of any character on a path is the XOR sum of masks of all nodes on that path.
* **Palindrome Condition:** A bitmask $m$ represents a valid palindrome configuration if $m == 0$ or $(m \& (m - 1)) == 0$ (meaning at most one bit is set).
* **Tree Decomposition (HLD):** Flatten the tree into contiguous linear segments using Heavy-Light Decomposition so that path queries between any two nodes $u$ and $v$ are broken down into $O(\log n)$ chain ranges.
* **Segment Tree:** Maintain the XOR sums over ranges in a Segment Tree. Point updates update the mask of a single node in $O(\log n)$ time, and range XOR queries retrieve the path XOR sum in $O(\log^2 n)$ time.

## Example Walkthrough

Consider Example 1: `n = 3, edges = [[0,1],[1,2]], s = "aac"`, queries:

1. `query 0 2`: Path $0 \rightarrow 1 \rightarrow 2$ gives characters `a`, `a`, `c`. Parity masks are `1`, `1`, `4`. XOR sum equals $1 \oplus 1 \oplus 4 = 4$. Binary `100` has one set bit, so it forms a palindrome (`aca`), returning `true`.
2. `update 1 b`: Node 1 changes from `a` to `b`. Now $s =$ `"abc"`.
3. `query 0 2`: Path $0 \rightarrow 1 \rightarrow 2$ gives characters `a`, `b`, `c`. XOR sum equals $1 \oplus 2 \oplus 4 = 7$ (binary `111`, three bits set). Cannot form a palindrome, returning `false`.

## Code

```python
class Solution:
    def palindromePath(self, n: int, edges: list[list[int]], s: str, queries: list[str]) -> list[bool]:
        adj = [[] for _ in range(n)]
        for u, v in edges:
            adj[u].append(v)
            adj[v].append(u)
        
        parent = [0] * n
        depth = [0] * n
        heavy = [-1] * n
        head = [0] * n
        pos = [0] * n
        sz = [0] * n
        
        def dfs1(u, p, d):
            parent[u] = p
            depth[u] = d
            sz[u] = 1
            max_sub = 0
            h_child = -1


            for v in adj[u]:
                if v != p:
                    dfs1(v, u, d + 1)
                    sz[u] += sz[v]


                    if sz[v] > max_sub:
                        max_sub = sz[v]
                        h_child = v
            heavy[u] = h_child
            return sz[u]
        
        dfs1(0, -1, 0)
        

        curr_pos = 0
        def dfs2(u, h):
            nonlocal curr_pos
            head[u] = h
            pos[u] = curr_pos
            curr_pos += 1


            if heavy[u] != -1:
                dfs2(heavy[u], h)


            for v in adj[u]:
                if v != parent[u] and v != heavy[u]:
                    dfs2(v, v)
        
        dfs2(0, 0)
        
        tree = [0] * (4*n)
        
        def build(node, l, r):
            if l == r:
                return


            mid = (l+r) // 2
            build(2 * node, l, mid)
            build(2 * node + 1, mid+1, r)
        
        build(1, 0, n-1)
        
        def update_tree(node, l, r, idx, val):
            if l == r:
                tree[node] = val
                return
            mid = (l + r) // 2


            if idx <= mid:
                update_tree(2 * node, l, mid, idx, val)


            else:
                update_tree(2 * node + 1, mid + 1, r, idx, val)
            tree[node] = tree[2 * node] ^ tree[2 * node + 1]
            
        def query_tree(node, l, r, ql, qr):
            if ql > r or qr < l:
                return 0


            if ql <= l and r <= qr:
                return tree[node]

            mid = (l + r) // 2
            return query_tree(2 * node, l, mid, ql, qr) ^ query_tree(2 * node + 1, mid + 1, r, ql, qr)

            
        chars = list(s)
        for i in range(n):
            update_tree(1, 0, n-1, pos[i], 1 << (ord(chars[i]) - ord('a')))
            
        ans = []


        for q in queries:
            parts = q.split()


            if parts[0] == "update":
                u = int(parts[1])
                c = parts[2]
                chars[u] = c
                update_tree(1, 0, n - 1, pos[u], 1 << (ord(c) - ord('a')))


            else:
                u = int(parts[1])
                v = int(parts[2])
                res = 0


                while head[u] != head[v]:
                    if depth[head[u]] < depth[head[v]]:
                        u, v = v, u

                    res ^= query_tree(1, 0, n - 1, pos[head[u]], pos[u])
                    u = parent[head[u]]
                    

                if depth[u] > depth[v]:
                    u, v = v, u
                res ^= query_tree(1, 0, n - 1, pos[u], pos[v])
                ans.append(res == 0 or (res & (res - 1)) == 0)

        return ans
```

## Complexity

* **Time Complexity:** Preprocessing takes $O(n \log n)$ for HLD and segment tree building. Each update and query takes $O(\log^2 n)$ time, resulting in an overall time complexity of $O(n + q \log^2 n)$ for $q$ queries.
* **Space Complexity:** $O(n)$ auxiliary space to store tree adjacency lists, HLD mapping arrays, and segment tree nodes.

## Edge Cases

* **Single Node Tree ($n = 1$):** Path queries between node 0 and itself correctly evaluate to true since a single character is always a palindrome.
* **All Characters Identical:** Every path XOR mask results in either 0 or a power of two, returning true for all path queries.
* **Repeated Updates on the Same Node:** Segment tree correctly updates individual node parities without desynchronizing chain mappings.

## Lessons

* Bitwise XOR efficiently tracks character parities along paths because operations are associative and reversible.
* Heavy-Light Decomposition simplifies tree path queries into contiguous array range queries.
* Segment trees provide fast point updates and range XOR accumulation.
