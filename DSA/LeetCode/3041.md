## **3041. Maximize Consecutive Elements in an Array After Modification** 🔴

**Topics:** Array, Dynamic Programming, Sorting, Pattern Matching

## Intuition

Think of building a staircase out of Lego bricks where each brick can either stay at its current height or snap onto a riser that raises its height by `1`. Once you sort the bricks by their starting height, you only ever look at the gap between the current brick `n` and the previous brick `prev`. Because consecutive numbers in a valid final sequence must step up by `1` with no duplicates, tracking just two running streak lengths (`stay` and `up`) lets you tell how far your current staircase can climb without needing a full hash map.

## Approach

This implementation sorts `nums` in ascending order and walks through it with a sentinel `prev = -10` (any value well below `min(nums) - 2`). At each element `n`, it inspects `n - prev` to transition two state variables:

* `stay`: the longest consecutive sequence ending at value `n` (where `n` is kept as `n`).
* `up`: the longest consecutive sequence ending at value `n + 1` (where `n` is bumped to `n + 1`).

Here is how each gap `n - prev` behaves:

1. `case 0` (`n == prev`): We have a duplicate of the previous number. Since `stay` already accounts for a sequence ending at `n` (or `prev`), bumping this duplicate `n` up to `n + 1` extends a streak of length `stay` by one more element: `up = stay + 1`. Meanwhile, `stay` remains unchanged because we cannot use another duplicate to end at the same value `n` again in a strictly consecutive set.
2. `case 1` (`n == prev + 1`): The previous element had `stay` ending at `prev` and `up` ending at `prev + 1`. Since `n` equals `prev + 1`, `n` can stay as `n` to extend the `stay` chain (`stay + 1`), and `n + 1` can extend the `up` chain (`up + 1`).
3. `case 2` (`n == prev + 2`): The previous `up` chain ended at `prev + 1` (which equals `n - 1`). Keeping `n` as `n` seamlessly extends that chain (`stay = up + 1`). Bumping `n` to `n + 1` leaves a gap from `prev + 1`, so `up` resets to `1`.
4. `case _` (gap greater than `2`): Even with a `+1` bump, `n` cannot connect to any prior sequence. Both `stay` and `up` reset to `1`.

After updating `stay` and `up`, `ans` records the maximum streak seen so far, and `prev` advances to `n`.

## Example Walkthrough

Trace `nums = [2, 1, 5, 1, 1]`:

* Initial state: `ans = 1`, `stay = 1`, `up = 1`, `prev = -10`.
* Sorted array: `[1, 1, 1, 2, 5]`.

1. `n = 1`, `n - prev = 11` (`case _`):
* `stay = 1`, `up = 1`
* `ans = 1`, `prev = 1`


2. `n = 1`, `n - prev = 0` (`case 0`):
* `up = stay + 1 = 2` (`stay` stays `1`)
* `ans = 2`, `prev = 1`


3. `n = 1`, `n - prev = 0` (`case 0`):
* `up = stay + 1 = 2` (`stay` stays `1`)
* `ans = 2`, `prev = 1`


4. `n = 2`, `n - prev = 1` (`case 1`):
* `stay = stay + 1 = 2`, `up = up + 1 = 3`
* `ans = 3`, `prev = 2`


5. `n = 5`, `n - prev = 3` (`case _`):
* `stay = 1`, `up = 1`
* `ans = 3`, `prev = 5`



Final answer: `3`.

## Code & Comments

```python
class Solution:
    def maxSelectedElements(self, nums: list[int]) -> int:
        ans=stay=up=1

        prev = -10

        for n in sorted(nums):
            match n - prev:
                case 0: up = stay + 1
                case 1: stay, up = stay + 1, up + 1
                case 2: stay, up = up + 1, 1
                case _: stay = up = 1
                
            ans, prev = max(ans, stay, up), n
        return ans

```

## Complexity

* **Time Complexity:** $O(n \log n)$, where $n$ is the length of `nums`. Sorting `nums` dominates the runtime at $O(n \log n)$, while the single pass over the sorted elements takes $O(n)$.
* **Space Complexity:** $O(n)$ for the new sorted list created by `sorted(nums)` (or $O(1)$ auxiliary state if `nums` is sorted in place with `nums.sort()`).

## Edge Cases

1. **All identical values (`nums = [7, 7, 7]`):**
After the first `7` sets `stay = 1, up = 1`, subsequent `7`s hit `case 0`, keeping `up = 2`. The output is `2` (representing consecutive elements `7, 8`).
2. **Single element (`nums = [1]`):**
The loop runs once with `n - prev = 11`, keeping `stay = 1, up = 1, ans = 1`. The output is `1`.
3. **Adjacent numbers with no duplicates (`nums = [1, 2, 3, 4]`):**
Each step after the first hits `case 1`, growing `stay` and `up` up to `4`. The output is `4`.

## Lessons

* **State compression on sorted data:** When transitions only depend on the previous value and its gap to the current value, you can replace a dictionary with a few state variables.
* **Careful duplicate handling:** Repeated elements in a sorted stream require distinct rules from strictly increasing elements so you do not double-count values that cannot appear twice in a consecutive sequence.
* **Structural pattern matching:** `match` statements on gap differences (`n - prev`) can make case-by-case state transitions easy to read once the invariants are clear.
