# 2029. Stone Game IX 🟡

**Topics:** Game Theory, Math, Greedy, Counting

## Intuition

The actual value of each stone is not important. What matters is its **remainder when divided by 3**.

Every stone falls into one of three groups:

* `0` → `stone % 3 == 0`
* `1` → `stone % 3 == 1`
* `2` → `stone % 3 == 2`

So instead of tracking every stone, we can simply count how many stones belong to each group.

```text
cnt[0] = number of stones with remainder 0
cnt[1] = number of stones with remainder 1
cnt[2] = number of stones with remainder 2
```

The game depends on how these three groups interact with the running sum modulo `3`.

A remainder `0` stone does not change the current remainder, but it does consume a turn. Therefore, the **parity** of the number of remainder `0` stones becomes important.

## Approach

First, count the stones according to their remainder modulo `3`.

```python
cnt = [0, 0, 0]

for s in stones:
    cnt[s % 3] += 1
```

Then unpack the counts:

```python
zeros, ones, twos = cnt
```

There are two cases.

### Case 1: Even number of remainder-0 stones

If `zeros` is even, the remainder-0 stones do not give either player a lasting turn advantage.

Alice can win as long as there is at least one stone from both non-zero groups:

```python
return ones > 0 and twos > 0
```

Why do we need both?

A stone with remainder `1` and a stone with remainder `2` can counterbalance each other modulo `3`. If one group is completely missing, Alice cannot maintain a safe sequence of moves.

### Case 2: Odd number of remainder-0 stones

If `zeros` is odd, the remainder-0 stones give Bob the turn advantage.

Alice can only overcome this when one of the non-zero groups has sufficiently more stones than the other.

The condition is:

```python
abs(ones - twos) > 2
```

If the difference is `2` or less, Bob can force Alice into a losing position.

## Example Walkthrough

Consider:

```text
stones = [5, 1, 2, 4, 3]
```

Calculate the remainder of every stone:

```text
5 % 3 = 2
1 % 3 = 1
2 % 3 = 2
4 % 3 = 1
3 % 3 = 0
```

So the counts are:

```text
zeros = 1
ones  = 2
twos  = 2
```

Since `zeros` is odd, we use:

```python
abs(ones - twos) > 2
```

Substitute the values:

```text
abs(2 - 2) > 2
0 > 2
```

This is false.

Therefore, Alice cannot force a win.

```text
Output: false
```

## Code

```python
from typing import List
class Solution:
    def stoneGameIX(self, stones: List[int]) -> bool:
        cnt = [0,0,0]

        for s in stones:
            cnt[s%3] += 1

        zeros, ones, twos = cnt

        if zeros%2 == 0:
            return ones>0 and twos>0

        return abs(ones - twos) > 2
```

## Complexity

We visit every stone exactly once.

**Time Complexity**

$$
O(n)
$$

**Space Complexity**

$$
O(1)
$$

The `cnt` array always contains exactly three elements.

## Edge Cases

### 1. Only one stone

```text
stones = [2]
```

Counts:

```text
zeros = 0
ones = 0
twos = 1
```

`zeros` is even, but `ones` is `0`.

Therefore:

```text
Answer: false
```

### 2. One stone from each non-zero group

```text
stones = [1, 2]
```

Counts:

```text
zeros = 0
ones = 1
twos = 1
```

Both `ones` and `twos` are present, so:

```text
Answer: true
```

### 3. Only remainder-0 stones

```text
stones = [3, 6, 9]
```

Counts:

```text
zeros = 3
ones = 0
twos = 0
```

There are no stones from either non-zero group, so Alice cannot satisfy the winning condition.

```text
Answer: false
```

## Lessons

* When only divisibility matters, reduce numbers using `%`.
* Instead of tracking individual values, group them by their remainder.
* In turn-based games, the **parity** of certain groups can determine who has the advantage.
* This problem reduces from a large game with up to `10^5` stones to just **three counters**.
* The important winning conditions are:

```text
zeros is even:
    ones > 0 and twos > 0

zeros is odd:
    abs(ones - twos) > 2
```

The main trick is recognizing that the actual stone values are irrelevant once we know their remainder modulo `3`.
