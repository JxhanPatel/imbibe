## 2567. Minimum Score by Changing Two Elements 🟡

**Topics:** Array, Greedy, Sorting

## Intuition

Imagine you are hosting a group of guests at a party, and the "spread" (high score) is the age difference between the oldest and youngest guest, while the "tightest pairing" (low score) is the smallest age gap between any two guests. You can ask two guests to leave or change their ages to fit right in with someone already there.

First, notice that if we change two elements to match an existing value already in the array (for example, setting them equal to another element), we can always create two identical numbers. Two identical numbers have an absolute difference of $0$. Since absolute differences are never negative, the **low score** can always be brought down to $0$!

That means minimizing the total score boils down to minimizing the **high score** (the difference between the largest and smallest remaining values) using our two edits. Since we only have two edits and want to shrink the range `[min, max]` as much as possible, we should trim extremes from the sorted array: either drop the two largest values, drop the two smallest values, or drop one smallest and one largest value.

## Approach

1. Sort `nums` in ascending order so the smallest values are at the front and the largest values are at the back.
2. Since we can always set two elements equal to make the minimum absolute difference equal to $0$, the low score is always $0$. Thus, the score is simply the high score (`max_val - min_val`) after removing two elements from consideration.
3. Consider the three ways to discard two extreme elements from the sorted array of length $n$:
* Discard the two largest elements (`nums[-1]` and `nums[-2]`): the new maximum is `nums[-3]` and the minimum stays `nums[0]`.
* Discard the two smallest elements (`nums[0]` and `nums[1]`): the new minimum is `nums[2]` and the maximum stays `nums[-1]`.
* Discard one smallest (`nums[0]`) and one largest (`nums[-1]`): the new range is `nums[-2] - nums[1]`.


4. Return the minimum among these three differences.

## Example Walkthrough

Consider `nums = [1, 4, 7, 8, 5]`:

* Sorted array: `[1, 4, 5, 7, 8]` ($n = 5$)
* Low score can always be made $0$ (for instance, changing `1` and `4` to `5` gives `[5, 5, 5, 7, 8]`, where $\vert{}5 - 5\vert{} = 0$).
* Candidate 1 (drop two largest, `8` and `7`): `nums[4] - nums[0]`? No, new max is `nums[2] = 5`, min is `nums[0] = 1` -> `5 - 1 = 4`.
* Candidate 2 (drop two smallest, `1` and `4`): new min is `nums[2] = 5`, max is `nums[4] = 8` -> `8 - 5 = 3`.
* Candidate 3 (drop smallest `1` and largest `8`): new min is `nums[1] = 4`, new max is `nums[3] = 7` -> `7 - 4 = 3`.

The minimum score is `3`.

## Code

```python
class Solution:
    def minimizeSum(self, nums: list[int]) -> int:
        spuds = sorted(nums)
        a = spuds[-3] - spuds[0]
        b = spuds[-1] - spuds[2]
        c = spuds[-2] - spuds[1]

        return min(a, b, c)

```

## Complexity

* **Time Complexity:** $O(n \log n)$, where $n$ is the length of `nums`. Sorting the array dominates the runtime, while computing the three differences takes $O(1)$ time.
* **Space Complexity:** $O(n)$ in Python for Timsort's auxiliary space (or $O(\log n)$ depending on implementation details), and $O(1)$ extra space for the final comparison.

## Edge Cases

* **Minimum array length (`n = 3`):** For `nums = [1, 4, 3]`, sorting gives `[1, 3, 4]`. All three options (`nums[0] - nums[0]`, `nums[2] - nums[2]`, `nums[1] - nums[1]`) yield `0`, returning `0`.
* **Already identical elements:** For `nums = [5, 5, 5, 5]`, all differences are `0`, so the result is `0`.
* **Large spread with tight middle cluster:** For `nums = [1, 10, 11, 12, 1000]`, sorted is `[1, 10, 11, 12, 1000]`. Dropping both ends (`12 - 10 = 2`) beats dropping two highs (`12 - 1 = 11`) and dropping two lows (`1000 - 11 = 989`), returning `2`.

## Lessons

* When a problem allows changing values freely and asks to minimize a minimum-difference metric, check if you can force that minimum difference to $0$ using duplicates.
* Extremum problems on arrays often simplify once sorted, because the maximum possible spread always lives between boundary elements.
* With a small budget of edits (like two changes), enumerating all ways to trim the ends of a sorted array is clean, bug-free, and easy to reason about.
