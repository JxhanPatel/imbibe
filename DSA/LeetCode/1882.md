## 1882: Process Tasks Using Servers 🟡

**Topics:** Array, Heap (Priority Queue)

### Intuition

Think of running a busy print shop where incoming print jobs arrive every second. Each machine has a specific weight representing its capability and a unique index. When jobs arrive, you want to assign them to available machines. If multiple machines are free, you pick the cheapest one with the lowest weight, breaking ties by choosing the smaller index. If all machines are busy, the incoming job must wait. Instead of manually ticking through every second of idle time, we can maintain two priority queues: one for idle machines and one for busy machines tracking when they finish their tasks.

### Approach

1. **Idle Heap (`idle`):** Stores all available servers as tuples of `(weight, index)`. Python's heap implementation automatically prioritizes by weight, then by index.
2. **Busy Heap (`active`):** Stores servers currently processing tasks as tuples of `(free_time, weight, index)`.
3. **Iteration and Time Management:** As we iterate through each task arriving at second `t`, we first release any servers in the busy heap whose completion time is less than or equal to `t`, pushing them back into the idle heap.
4. **Assignment:** If any server is idle, we pop the best available server and assign the task starting at current time `t`. If no servers are free, we fast-forward our simulation to the earliest completion time in the busy heap, using that server immediately.
5. **Tracking:** We push the updated server back into the busy heap with its new release time (`start + job`), and record its index in our results array.

### Example Walkthrough

Let us trace `servers = [3, 3, 2]` and `tasks = [1, 2]`.

* **Initial State:** `idle = [(2, 2), (3, 0), (3, 1)]`, `active = []`, `out = []`.
* **At Second `t = 0`, Task `1`:**
* `active` is empty.
* `idle` is not empty, so we pop server `2` (weight `2`).
* `start = 0`.
* Push `(0 + 1, 2, 2)` into `active`.
* Result: `out = [2]`.


* **At Second `t = 1`, Task `2`:**
* `active` has `(1, 2, 2)`. Since `1 <= 1`, server `2` finishes and returns to `idle`.
* `idle` is not empty, so we pop server `2`.
* `start = 1`.
* Push `(1 + 2, 2, 2)` into `active`.
* Result: `out = [2, 2]`.



### Code and Comments

```python
class Solution:
    def assignTasks(self, servers: list[int], tasks: list[int]) -> list[int]:
        idle = [(w, i) for i, w in enumerate(servers)]
        heapify(idle)
        
        out=[]
        active=[]
        
        for t, job in enumerate(tasks):
            while active and active[0][0] <= t:
                _, w, idx = heappop(active)
                heappush(idle, (w, idx))
            

            if idle:
                w, idx = heappop(idle)
                start = t

            else:
                end_time, w, idx = heappop(active)
                start = end_time
            

            heappush(active, (start+job, w, idx))
            out.append(idx)
            
        return out
```

### Complexity

* **Time Complexity:** $O((n + m) \log n)$, where $n$ is the number of servers and $m$ is the number of tasks. Initializing the idle heap takes $O(n \log n)$ time. Each of the $m$ tasks performs heap push and pop operations on both the idle and busy heaps, taking $O(\log n)$ time per operation.
* **Space Complexity:** $O(n)$ auxiliary space. The two heaps store at most $n$ servers each at any given time, and the output array takes $O(m)$ space.

### Edge Cases

1. **All Servers Busy:** When every server is occupied, the algorithm correctly jumps forward in time to the completion time of the earliest finishing server.
2. **Multiple Servers Freeing Simultaneously:** The `while` loop processes all servers whose completion time is less than or equal to current time `t`, returning all of them to the idle pool before making an assignment.
3. **Tasks Arriving Faster Than Processing Capacity:** Long task durations accumulate in the active heap, causing subsequent tasks to wait for the earliest available server.

### Lessons

* **Dual Heap Pattern:** Managing available resources and active resources with separate priority queues is an effective pattern for scheduling problems.
* **Time Fast-Forwarding:** Skipping idle simulation steps by jumping directly to event completion times avoids timeouts on large constraints.
* **Tie-Breaking with Tuples:** Python tuples compare elements from left to right, allowing multi-criteria priority sorting without custom classes.
