# 2333. Minimum Sum of Squared Difference 🟡

**Topics:** Array, Greedy, Counting, Frequency Array

## Intuition

Imagine you have several pairs of numbers, and each pair has a difference. Your goal is to minimize the sum of their squared differences by reducing these differences using a limited number of operations.

For example, consider these differences:

```text
[5, 3, 1]
```

The sum of squares is:

$$
5^2 + 3^2 + 1^2 = 35
$$

Reducing `5` to `4` saves `9`, while reducing `1` to `0` saves only `1`.

This means reducing larger differences first gives us the greatest benefit.

Now imagine that instead of tracking every difference individually, we maintain a frequency array. The index represents a difference value, and the value at that index tells us how many elements have that difference.

For example:

```text
Differences: [3, 3, 2, 1]

freq[1] = 1
freq[2] = 1
freq[3] = 2
```

Whenever we reduce a difference by one, we move its frequency from one index to the previous index. This lets us process multiple equal differences together.

## Approach

We use a **greedy strategy with a frequency array**.

### 1. Calculate the operation budget

Both arrays can be modified independently, but either operation can reduce an absolute difference by one.

Therefore, combine the available operations:

```python
budget = k1 + k2
```

### 2. Calculate absolute differences

For every corresponding pair of elements, calculate:

$$
d_i = |nums1[i]-nums2[i]|
$$

```python
diffs = [abs(a-b) for a, b in zip(nums1, nums2)]
```

If the total difference is no greater than the budget, every difference can be reduced to zero, so return `0`.

### 3. Build the frequency array

Find the largest difference and create a frequency array that can represent every possible difference.

```python
top = max(diffs)
freq = [0] * (top+1)
```

Count how many times each difference occurs:

```python
for x in diffs:
    freq[x] += 1
```

For example, if the differences are `[4, 2, 4, 1]`, the frequency array records two occurrences of `4`, one of `2`, and one of `1`.

### 4. Reduce the largest differences first

Start at the largest difference, `top`, and work downward.

At each level:

1. `freq[lvl]` tells us how many differences currently have this value.
2. `moved = min(budget, freq[lvl])` determines how many can be reduced using the remaining operations.
3. Remove those differences from the current frequency.
4. Add them to the frequency of the next smaller value.
5. Decrease the budget by the number of operations used.

```python
moved = min(budget, freq[lvl])
freq[lvl] -= moved
freq[lvl-1] += moved
budget -= moved
```

Each moved difference costs exactly one operation.

We continue until the budget is exhausted or every difference has reached zero.

### 5. Calculate the final sum

After all possible reductions, each difference value `v` appears `freq[v]` times.

Therefore, the final answer is:

$$
\sum_{v=0}^{top} v^2 \cdot freq[v]
$$

```python
return sum(v*v*c for v, c in enumerate(freq))
```

## Example Walkthrough

**Input**

```text
nums1 = [1, 4, 10, 12]
nums2 = [5, 8, 6, 9]
k1 = 1
k2 = 1
```

### Step 1: Calculate differences

```text
diffs = [4, 4, 4, 3]
budget = 2
```

### Step 2: Build the frequency array

```text
Difference:  0  1  2  3  4
Frequency:   0  0  0  1  3
```

### Step 3: Reduce the largest differences

At level `4`, there are three differences, but only two operations are available.

```text
moved = min(2, 3) = 2
```

Move two occurrences from level `4` to level `3`:

```text
Difference:  0  1  2  3  4
Frequency:   0  0  0  3  1
```

The budget becomes zero, so the loop stops.

The resulting differences are equivalent to:

```text
[3, 3, 3, 4]
```

### Step 4: Calculate the answer

$$
3^2+3^2+3^2+4^2=43
$$

**Output**

```text
43
```

## Code

```python
class Solution:
    def minSumSquareDiff(self, nums1: List[int], nums2: List[int], k1: int, k2: int) -> int:
        budget = k1+k2
        diffs = [abs(a-b) for a, b in zip(nums1, nums2)]

        if sum(diffs) <= budget:
            return 0

        top = max(diffs)
        freq = [0] * (top+1)

        for x in diffs:
            freq[x] += 1

        lvl = top
        while lvl > 0 and budget > 0:
            moved = min(budget, freq[lvl])
            freq[lvl] -= moved
            freq[lvl-1] += moved
            budget -= moved
            lvl -= 1

        return sum(v*v*c for v, c in enumerate(freq))
```

## Complexity

Let `n` be the array length and `D` be the maximum absolute difference.

**Time complexity:**

$$
O(n+D)
$$

Building the differences and frequency array takes \(O(n+D)\) time. The greedy loop processes each difference level at most once, taking \(O(D)\) time. Calculating the final sum takes another \(O(D)\) time.

**Space complexity:**

$$
O(n+D)
$$

The differences array uses \(O(n)\) space, while the frequency array uses \(O(D)\) space.

## Edge Cases

1. **No operations available**

   If `k1 = 0` and `k2 = 0`, the original squared difference sum is returned.

2. **All differences are already zero**

   The total difference is zero, so the early return produces `0`.

3. **Enough operations to eliminate every difference**

   If `budget >= sum(diffs)`, all differences can become zero.

4. **Many identical differences**

   The frequency array processes multiple equal differences together instead of repeatedly searching through the original array.

5. **Very large operation budget**

   The algorithm does not iterate once per operation. Its running time depends on the maximum difference, not on the potentially billions of available operations.

## Lessons

- Greedy algorithms work well when reducing the largest values gives the greatest immediate benefit.
- Frequency arrays are useful when values fall within a manageable integer range.
- Moving frequencies between adjacent indices efficiently simulates reducing multiple values by one.
- Combining `k1` and `k2` simplifies the problem because either array can be adjusted to reduce the same absolute difference.
- Always check whether the entire difference can be eliminated before performing more work.
- Frequency-based optimization can replace expensive element-by-element operations when many values are identical.
