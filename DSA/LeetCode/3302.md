# 3302. Find the Lexicographically Smallest Valid Sequence 🟡

**Topics:** Greedy, String, Two Pointers, Prefix/Suffix

## Intuition

Imagine you are trying to build `word2` by picking characters from `word1`.

You must pick the indices in increasing order, and you are allowed to make **at most one mismatch**.

The main challenge is not just finding *any* valid sequence. We need the **lexicographically smallest sequence of indices**.

That means we should always try to take the smallest possible index.

But before taking an index as the one allowed mismatch, we need to make sure that the remaining characters of `word2` can still be matched.

This is where `suffOk` helps.

It tells us how many characters from the end of `word2` can be matched using a suffix of `word1`.

So while scanning from left to right:

* If the current characters match, take the index.
* If they do not match, we can use our one allowed mismatch only if the remaining part can still be matched.
* Otherwise, skip the current index and try the next one.

This gives us a greedy solution.


## Approach

The solution has three main parts:

1. Build the suffix matching information.
2. Greedily construct the answer.
3. Check whether we successfully selected all characters.

### Step 1: Build `suffOk`

We create:

```python
suffOk = [0] * n
```

For every position `i`, `suffOk[i]` represents the maximum number of characters from the **suffix of `word2`** that can be matched using `word1[i:]`.

We start from the end of both strings:

```python
i, j = n - 1, m - 1
```

Whenever:

```python
word1[i] == word2[j]
```

we record:

```python
suffOk[i] = m - j
```

This tells us how much of the suffix of `word2` has been matched.


### Step 2: Propagate the best suffix value

After the first pass, some positions may not contain the best possible value.

For example, if a suffix starting at `i + 1` can match more characters than the suffix starting at `i`, then `i` should also be able to use that information.

So we propagate the maximum from right to left:

```python
for i in range(n - 2, -1, -1):
    if suffOk[i + 1] > suffOk[i]:
        suffOk[i] = suffOk[i + 1]
```

After this step:

```text
suffOk[i]
```

contains the best suffix match available from position `i` onward.


## Step 3: Greedily build the sequence

We now scan `word1` from left to right.

```python
res = []
usedSkip = False
i = j = 0
```

Here:

* `i` is the current index in `word1`.
* `j` is the current index in `word2`.
* `usedSkip` tells us whether we have already used our one mismatch.

### Case 1: Characters match

If:

```python
word1[i] == word2[j]
```

we should immediately take this index.

```python
res.append(i)
i += 1
j += 1
```

Because we are constructing the answer from left to right, taking this earliest valid index helps guarantee the lexicographically smallest sequence.


### Case 2: Characters do not match

Suppose:

```python
word1[i] != word2[j]
```

We could use this position as our one allowed mismatch.

The number of characters still required after choosing this position is:

```python
left = m - j - 1
```

We can use the mismatch only when:

```python
not usedSkip
```

and the remaining suffix of `word1` can provide all the remaining characters:

```python
suffOk[i + 1] >= left
```

If that is possible, we choose the current index:

```python
res.append(i)
i += 1
j += 1
usedSkip = True
```

Otherwise, we simply skip this index:

```python
i += 1
```


## Why `suffOk` Makes the Greedy Choice Safe

Consider a mismatch at index `i`.

We want to know:

> "If I use `i` as my one mismatch, can I still finish `word2`?"

Checking this by scanning the rest of the strings every time would be too slow.

Instead, `suffOk[i + 1]` already tells us how many characters can be matched from the remaining suffix.

So this condition:

```python
suffOk[i + 1] >= left
```

acts as our feasibility check.

If it is true, we can safely take the current index.

If it is false, taking the index would make the sequence impossible, so we skip it.


## Extra Early-Break Check

After processing an index, we check:

```python
if n - i < m - j:
    break
```

This means:

> There are fewer characters remaining in `word1` than the number of characters still needed from `word2`.

If that happens, completing the sequence is impossible, so we stop early.


## Example Walkthrough

Consider:

```text
word1 = "bacdc"
word2 = "abc"
```

We need three indices.

Initially:

```text
i = 0
j = 0
usedSkip = False
res = []
```

### Index 0

```text
word1[0] = 'b'
word2[0] = 'a'
```

They do not match.

We could use index `0` as our mismatch, but the suffix check tells us that the remaining characters cannot be completed correctly.

So we skip it:

```text
i = 1
```


### Index 1

```text
word1[1] = 'a'
word2[0] = 'a'
```

They match.

Take index `1`:

```text
res = [1]
i = 2
j = 1
```


### Index 2

```text
word1[2] = 'c'
word2[1] = 'b'
```

They do not match.

We have not used our mismatch yet.

The remaining target is:

```text
"c"
```

and `suffOk` tells us that this remaining character can be matched.

So we use index `2` as our mismatch:

```text
res = [1, 2]
usedSkip = True
```


### Continue

At index `4`:

```text
word1[4] = 'c'
word2[2] = 'c'
```

They match.

Take index `4`:

```text
res = [1, 2, 4]
```

We have selected all three characters.

Therefore:

```text
[1, 2, 4]
```

is returned.


## Code

```python
class Solution:
    def validSequence(self, word1: str, word2: str) -> List[int]:
        n, m = len(word1), len(word2)
        suffOk = [0]*n

        i, j = n-1, m-1

        while i >= 0 and j >= 0:
            if word1[i] == word2[j]:
                suffOk[i] = m-j
                j -= 1
            i -= 1


        for i in range(n-2,-1,-1):
            if suffOk[i+1] > suffOk[i]:
                suffOk[i] = suffOk[i + 1]

        res=[]
        usedSkip = False
        i=j=0


        while i < n and j < m:
            if word1[i] == word2[j]:
                res.append(i)
                i += 1
                j += 1
                continue

            left = m-j-1

            if not usedSkip and i+1 < n and suffOk[i+1] >= left:
                res.append(i)
                i += 1
                j += 1
                usedSkip = True
            else:
                i += 1


            if n - i < m - j:
                break

        return res if len(res) == m else []
```

## Complexity

Let:

* $n = \text{len(word1)}$
* $m = \text{len(word2)}$

The first pass to build `suffOk` takes:

$$
O(n)
$$

The suffix propagation also takes:

$$
O(n)
$$

The greedy construction scans `word1` once:

$$
O(n)
$$

Therefore, the total time complexity is:

$$
\boxed{O(n)}
$$

The `suffOk` array requires:

$$
\boxed{O(n)}
$$

space.


## Edge Cases

### 1. Exact match

```text
word1 = "abc"
word2 = "ab"
```

No mismatch is required.

Output:

```text
[0, 1]
```


### 2. One mismatch is required

```text
word1 = "vbcca"
word2 = "abc"
```

The first character can be changed from `'v'` to `'a'`.

Output:

```text
[0, 1, 2]
```


### 3. No valid sequence exists

```text
word1 = "aaaaaa"
word2 = "aaabc"
```

There are not enough matching characters to complete `word2` with only one mismatch.

Output:

```text
[]
```


### 4. The earliest index cannot be used

A smaller index is not automatically valid.

If choosing it prevents the remaining characters from being matched, we must skip it and try a later index.

This is exactly why `suffOk` is important.


## Lessons

* For lexicographically smallest index sequences, build the answer from **left to right**.
* Always try the earliest possible index first.
* Greedy choices need a way to verify that the remaining problem is still solvable.
* Suffix preprocessing can turn repeated "can I finish from here?" checks into $O(1)$ operations.
* A limited resource, such as **one allowed mismatch**, can be tracked with a simple boolean.
* The overall pattern is:

```text
Precompute future feasibility
            ↓
Scan from left to right
            ↓
Take the earliest feasible index
            ↓
Use the special operation at most once
```

The important idea is not simply "use greedy". It is **greedy + suffix feasibility**. That combination lets us get the lexicographically smallest valid sequence efficiently.
