# 3518. Smallest Palindromic Rearrangement II 🔴

**Topics:** String, Greedy, Combinatorics, Math, Counting

## Intuition

Think of building a palindrome like designing a symmetrical bridge.

Once you decide how the **left half** of the bridge looks, the **right half** is automatically determined because it must be a mirror image. If the palindrome has an odd length, there is also one fixed center character.

For example,

```text
abba
```

is completely determined by its left half:

```text
ab
```

Similarly,

```text
baab
```

is determined by

```text
ba
```

So instead of generating entire palindromes, we only need to generate the left half.

The problem now becomes finding the **k-th lexicographically smallest unique permutation** of the left half.

Rather than generating every permutation, we count **how many valid permutations start with each possible character**. This lets us skip entire groups of permutations and directly build the desired answer one character at a time.


## Approach

We use a **greedy construction** combined with **combinatorics**.

### Step 1: Count character frequencies

Since the input is already a palindrome:

* Every character contributes `count // 2` copies to the left half.
* If a character appears an odd number of times, it becomes the middle character.

For example,

```text
s = "aabbccbccbbaa"

Counts

a : 4
b : 6
c : 4
```

Left half becomes

```text
a : 2
b : 3
c : 2
```

There is no middle character because all frequencies are even.


### Step 2: Count remaining permutations

Suppose the remaining left-half counts are

```text
a : 2
b : 1
c : 3
```

The number of unique permutations is

$$
\frac{6!}{2!\times1!\times3!}
$$

Instead of computing large factorials directly, we use

$$
\binom{6}{2}
\times
\binom{4}{1}
\times
\binom{3}{3}
$$

This is mathematically equivalent and can be computed efficiently using `math.comb()`.

To avoid unnecessarily huge numbers, every count is capped at

```text
1_000_001
```

Since

```text
k ≤ 1,000,000
```

we never need values larger than this cap.


### Step 3: Build the answer greedily

At every position of the left half:

1. Try characters in lexicographical order.
2. Temporarily place one character.
3. Count how many permutations remain.
4. If that count is at least `k`, this character belongs in the answer.
5. Otherwise, skip all those permutations by subtracting the count from `k` and try the next character.

After constructing the left half, simply mirror it.

## Code

```python
from collections import Counter
from math import comb

class Solution:
    def smallestPalindrome(self, s: str, k: int):

        CAP = 1_000_001  # Avoid counting beyond what we need

        char_counts = Counter(s)
        half_counts = {}
        mid_char = ""

        # Build left-half frequencies and find middle character
        for ch, n in char_counts.items():
            half_counts[ch] = n // 2
            if n % 2 == 1:
                mid_char = ch

        # Count distinct permutations of the remaining left half
        def perms_remaining(counts):
            total = sum(counts.values())
            result = 1
            left = total

            for ch in sorted(counts):
                c = counts[ch]
                if c == 0:
                    continue

                result *= comb(left, c)

                # No need to count past the cap
                if result >= CAP:
                    return CAP

                left -= c

            return result

        # Not enough palindromes
        if perms_remaining(half_counts) < k:
            return ""

        half_len = sum(half_counts.values())
        result_chars = []

        # Build the left half greedily
        for _ in range(half_len):

            for ch in sorted(half_counts):

                if not half_counts[ch]:
                    continue

                half_counts[ch] -= 1
                remaining = perms_remaining(half_counts)

                if remaining >= k:
                    result_chars.append(ch)
                    break

                k -= remaining
                half_counts[ch] += 1

        left_half = "".join(result_chars)

        # Mirror to form the palindrome
        return left_half + mid_char + left_half[::-1]
```


## Complexity

Let:

* (n) be the length of the string.
* The left half has length (n/2).
* There are at most **26** distinct lowercase letters.

**Time Complexity**

For each position in the left half, we try at most 26 characters, and counting permutations also iterates over at most 26 characters.

$$
O(26 \times 26 \times n)
$$

Since 26 is a constant,

$$
O(n)
$$


**Space Complexity**

The frequency tables store at most 26 characters.

$$
O(26)=O(1)
$$

## Edge Cases

1. **Single character**

```text
s = "a"
k = 1
```

Output

```text
a
```


2. **Only one possible palindrome**

```text
s = "aa"
k = 2
```

There is only one unique palindrome.

Output

```text
""
```


3. **Odd-length palindrome**

```text
s = "bacab"
k = 1
```

The middle character remains fixed while only the left half is rearranged.

Output

```text
abcba
```


4. **k exceeds total permutations**

```text
s = "aaaa"
k = 5
```

There is only one unique palindrome.

Output

```text
""
```


## Lessons

* A palindrome is uniquely determined by its left half and, optionally, one middle character.
* When asked for the k-th lexicographical arrangement, think about **counting permutations instead of generating them**.
* Multiset permutations can be counted efficiently using combinations instead of factorial formulas.
* Greedily fixing one character at a time while counting the remaining possibilities is a powerful pattern that also appears in k-th permutation problems.
* Capping large counts is a useful optimization whenever only comparisons against a fixed limit are needed.
