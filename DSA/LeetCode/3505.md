## 3505. Minimum Operations to Make Elements Within K Subarrays Equal 🔴
**Topics:** Array, Dynamic Programming, Sliding Window, Ordered Set

### Intuition

Imagine you are adjusting temperatures across $k$ separate production zones in a factory, where each zone requires exactly $x$ consecutive rooms. To make all rooms in a zone equal with minimum total adjustment effort, statistics tells us that the optimal target temperature for any group of numbers is their median. Adjusting all values to the median minimizes the sum of absolute deviations. To solve this efficiently, we can break the problem into two parts: first, use a sliding window with an ordered list to find the minimum cost to equalize every possible subarray of size $x$; second, use dynamic programming with array accumulation to pick $k$ non-overlapping subarrays that minimize the total cost.

### Approach

* **Sliding Window Median Tracking (`SlidWin` class):** As we slide a window of size $x$ across the array, we maintain a sorted collection of the elements inside the window. By tracking the sum of the lower half of these sorted elements, we can compute the exact cost to equalize all elements to the median in $O(1)$ time per slide, while adding and removing elements from the sorted container takes $O(\log x)$ time.
* **Dynamic Programming with Accumulation (`Solution` class):** We precompute the cost for every window of size $x$ ending at each index. Then, we use a dynamic programming array `dp` where `dp[i]` represents the minimum cost to form valid windows up to index `i`. By iterating $k$ times and utilizing `itertools.accumulate` with the minimum function, we efficiently transition across valid non-overlapping subarray choices without redundant nested loops.

### Example Walkthrough

Consider `nums = [9, -2, -2, -2, 1, 5]`, `x = 2`, `k = 2`.

* First, we evaluate the cost of all windows of size $2$:
* Windows start from each index: `[9, -2]`, `[-2, -2]`, `[-2, -2]`, `[-2, 1]`, `[1, 5]`.
* For example, the window `[-2, 1]` has median `-2`. Changing $1$ to `-2` requires $3$ operations.


* The dynamic programming step iterates $k = 2$ times, accumulating the minimum costs of picking non-overlapping windows.
* The algorithm successfully identifies the optimal windows `[-2, -2]` and `[-2, -2]`, resulting in a minimum total operation count of $3$.

### Code & Comments

```python
from sortedcontainers import SortedList
from itertools import accumulate
from math import inf
from typing import List

class SlidWin:
    def __init__(self, vals):
        self.h = len(vals) // 2
        self.odd = len(vals) & 1
        self.s = SortedList(vals)
        self.low = sum(self.s[:self.h])
        self.tot = sum(vals)

    @property
    def cost(self):
        return self.tot - 2 * self.low - self.odd * self.s[self.h]

    def slide(self, out_val, new_val):
        s, h = self.s, self.h
        if new_val < s[h - 1]:
            self.low += new_val - s[h - 1]
        s.add(new_val)
        if out_val <= s[h - 1]:
            self.low += s[h] - out_val
        s.remove(out_val)
        self.tot += new_val - out_val
        return self.cost

class Solution:
    def minOperations(self, nums: List[int], x: int, k: int) -> int:
        w = SlidWin(nums[:x])
        c_list = [w.cost] + [w.slide(o, n) for o, n in zip(nums, nums[x:])]
        dp = [0] * (len(nums) + 1)
        for _ in range(k):
            dp = list(accumulate([inf] * x + [b + c for b, c in zip(dp, c_list)], min))
        return dp[-1]
```

### Complexity

* **Time Complexity:** $O(n \log x + n \cdot k)$, where $n$ is the length of `nums`. Each window slide updates the sorted container in $O(\log x)$ time, and the dynamic programming loop runs $k$ passes of length $n$.
* **Space Complexity:** $O(n + k)$ to store the window costs, sorted window elements, and dynamic programming state arrays.

### Edge Cases

* **Insufficient Elements ($k \times x > n$):** When the required total length across all $k$ subarrays exceeds the length of `nums`, non-overlapping placement is impossible, and the algorithm correctly resolves via infinity propagation.
* **Negative Numbers:** Elements can be negative. The absolute deviation formula and median selection handle negative coordinates correctly without modification.
* **Already Equal Elements:** When elements in windows are already identical, operational cost evaluates to $0$, returning $0$ if valid non-overlapping configurations exist.

### Lessons

* **Median Optimality:** The median minimizes the sum of absolute differences, making it the theoretical target for uniform element conversions.
* **SlidWin Maintenance:** Maintaining a sorted data structure alongside lower-half sum updates allows $O(\log x)$ window sliding instead of re-sorting from scratch.
* **Optimized DP Transitions:** Combining iterator zips with running minimum accumulations (`itertools.accumulate`) streamlines interval dynamic programming without heavy inner loops.
