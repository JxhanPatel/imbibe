# 3882: Minimum XOR Path in a Grid 🟡

**Topics:** Dynamic Programming, Bitwise XOR, Matrix, Space Optimization

## Intuition

When searching for the path with the minimum total XOR value in a grid, standard shortest-path dynamic programming fails because XOR does not preserve order. A cell value with a higher running XOR sum might produce a lower final XOR sum later when XORed with subsequent numbers.

Because grid elements are bounded within a small numerical range, the set of all possible XOR path sums reaching any cell remains small. Instead of tracking only the minimum value at each step, we can maintain the set of **all possible XOR sums** reachable at each position. By using a 1D DP array that updates row by row, we achieve maximum space efficiency while finding all reachable path sums at the final cell.

## Approach

1. **Space-Optimized DP Array:** Use a 1D array `stuff` of size equal to the number of columns (`w`). `stuff[j]` maintains the set of all possible XOR values reachable at column `j` for the current row.
2. **Base Initialization:** Initialize `stuff[0]` with `{0}` to account for the initial calculation before entering the grid, while all other columns start with empty sets.
3. **Row-by-Row Transition:**
* Iterate through each cell `(row, idx)` with value `val`.
* The incoming paths to cell `(row, idx)` can originate either from above (represented by the existing `stuff[idx]`) or from the left (represented by `stuff[idx - 1]`).
* Combine these incoming path sets using set union (`combo = stuff[idx] | stuff[idx - 1]`).
* Compute the new possible XOR sums for column `idx` by applying XOR with `val` across all accumulated values in `combo`.


4. **Final Result:** After processing the bottom-right cell at the last column, `stuff[-1]` contains all valid path XOR values reaching $(m-1, n-1)$. Return `min(stuff[-1])`.

## Example Walkthrough

Consider `grid = [[1, 2], [3, 4]]`:

* **Initialization:** `w = 2`, `stuff = [{0}, set()]`
* **Processing Row 0 (`[1, 2]`):**
* `idx = 0, val = 1`: `combo = {0}`, `stuff[0] = {0 ^ 1} = {1}`
* `idx = 1, val = 2`: `combo = set() | stuff[0] = {1}`, `stuff[1] = {1 ^ 2} = {3}`
* `stuff` after Row 0: `[{1}, {3}]`


* **Processing Row 1 (`[3, 4]`):**
* `idx = 0, val = 3`: `combo = stuff[0] = {1}`, `stuff[0] = {1 ^ 3} = {2}`
* `idx = 1, val = 4`: `combo = stuff[1] | stuff[0] = {3} | {2} = {2, 3}`, `stuff[1] = {2 ^ 4, 3 ^ 4} = {6, 7}`
* `stuff` after Row 1: `[{2}, {6, 7}]`


* **Output:** `min(stuff[-1])` returns `min({6, 7}) = 6`.

## Code

```python
class Solution:
    def minCost(self, grid: list[list[int]]) -> int:
        w = len(grid[0])
        stuff = [{0}] + [set() for _ in range(w-1)]

        for row in grid:
            for idx, val in enumerate(row):
                combo = stuff[idx] | (stuff[idx-1] if idx else set())
                stuff[idx] = {x ^ val for x in combo}

        return min(stuff[-1])
```

## Complexity

* **Time Complexity:** $O(m \cdot n \cdot K)$, where $m$ is the number of rows, $n$ is the number of columns, and $K$ is the maximum number of unique XOR states at any cell ($K \le 1024$). Given $m \cdot n \le 1000$, total operations remain well within execution limits.
* **Space Complexity:** $O(n \cdot K)$, requiring storage only for a single row's worth of column XOR sets rather than the entire grid.

## Edge Cases

1. **$1 \times 1$ Grid:** Works directly as `stuff[0]` starts at `{0}` and evaluates `{0 ^ grid[0][0]}`, returning `grid[0][0]`.
2. **Single Row Grid ($1 \times n$):** Correctly moves exclusively to the right since `stuff[idx]` from above remains empty.
3. **Single Column Grid ($m \times 1$):** Correctly moves exclusively downwards as `idx` is always `0`, avoiding any left-side set references.

## Lessons

* **Rolling Array State Reduction:** When state transitions only depend on the immediate previous cell and the cell directly above, full grid DP tables can be compressed into a 1D state array.
* **Set Union for Nondeterministic Path Accumulation:** Combining states using sets prevents redundant recalculations while capturing all valid non-monotonic path costs.
