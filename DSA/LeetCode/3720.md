# 3720. Lexicographically Smallest Permutation Greater Than Target 🟡

**Topics:** Greedy, String, Sorting, Counting

## Intuition

Imagine you have a bag containing all the characters of `s`, and you need to arrange them into the smallest possible string that is still strictly greater than `target`.

To make the answer as small as possible, we want to match `target` for as long as we can.

For example:

```text
target = bba
```

If we can use:

```text
b
```

we should use it, because choosing something larger immediately would make the answer unnecessarily large.

Then we try to match the next character too.

But eventually, one of two things happens:

1. We cannot continue matching `target`.
2. We decide to make the current character slightly larger than `target[i]`.

The key greedy idea is:

> Keep the prefix equal to `target` as long as possible. Then, at the latest possible position, replace `target[i]` with the smallest available character greater than it. Finally, put all remaining characters in sorted order.

Why the **latest possible position**?

Because changing an earlier character has a much bigger effect on lexicographical order.

For example:

```text
bca...
```

is always smaller than:

```text
c...
```

So we should preserve the equal prefix for as long as possible.


## Approach

We count the frequency of every character in `s`.

Then we first greedily try to build a prefix exactly equal to `target`.

For every position `i`:

* If `target[i]` is available, use it and continue.
* Otherwise, we cannot match the prefix anymore.

While matching, we store each position where we may later "increase" the character.

At position `i`, if there is any available character strictly greater than `target[i]`, then this position can potentially become the first position where our answer becomes greater than `target`.

After finding the longest possible matching prefix, we work backwards from the latest possible position:

1. Restore the character used to match `target[i]`, if we used it.
2. Find the smallest available character greater than `target[i]`.
3. Use that character.
4. Append all remaining characters in ascending order.

Working from right to left ensures that we change the string as late as possible, which gives the lexicographically smallest valid answer.


## Example Walkthrough

Consider:

```text
s = "abc"
target = "bba"
```

Character counts:

```text
a: 1
b: 1
c: 1
```

### Step 1: Match the first character

```text
target[0] = 'b'
```

We have `'b'`, so use it.

```text
answer = "b"
remaining = {a: 1, c: 1}
```

Also, `'c'` is available and:

```text
c > b
```

So position `0` is a possible place where we can make the answer greater.


### Step 2: Try to match the second character

```text
target[1] = 'b'
```

But there is no `'b'` remaining.

So we cannot continue matching.

Now we go back to the latest possible position.

At position `0`, we restore `'b'`:

```text
remaining = {a: 1, b: 1, c: 1}
```

Find the smallest character greater than `'b'`:

```text
c
```

Use it:

```text
answer = "c"
```

Append the remaining characters in sorted order:

```text
ab
```

Result:

```text
"cab"
```

But this shows why we must carefully preserve all possible matching states and choose the latest valid increase point.

A better way to think about Example 1 is to search backward over the matched prefix and choose the smallest valid increase. The resulting answer is:

```text
"bca"
```

because:

```text
"bca" > "bba"
```

and no smaller permutation of `"abc"` satisfies the condition.


## Code

```python
class Solution:
    def lexGreaterPermutation(self, s: str, target: str) -> str:
        avail = [0]*26

        for ch in s:
            avail[ord(ch)-97] += 1

        used=[]
        n=len(s)
        pos=0

        while pos < n:
            idx = ord(target[pos]) - 97

            if avail[idx] == 0:
                break

            avail[idx] -= 1
            used.append(idx)
            pos += 1

        j=pos

        while j >= 0:
            if j < pos:
                avail[used[j]] += 1

            if j != n:
                bump_from = ord(target[j]) - 97+1

                for c in range(bump_from, 26):
                    if avail[c] <= 0:
                        continue

                    avail[c] -= 1
                    prefix = target[:j] + chr(c+97)
                    suffix_parts = []

                    for k, cnt in enumerate(avail):
                        if cnt:
                            suffix_parts.append(chr(k+97) * cnt)

                    return prefix + "".join(suffix_parts)

            j -= 1

        return ""
```

## Complexity

There are only 26 lowercase English characters.

**Time Complexity**

$$
O(n + 26n)
$$

Since the alphabet size is constant, this simplifies to:

$$
O(n)
$$

**Space Complexity**

$$
O(n)
$$

We use the matched prefix and the result string.


## Edge Cases

1. **No valid permutation exists**

```text
s = "baba"
target = "bbaa"
```

The largest possible permutation is:

```text
"bbaa"
```

It is equal to `target`, not strictly greater.

Answer:

```text
""
```


2. **The smallest permutation is already greater**

```text
s = "leet"
target = "code"
```

The smallest permutation is:

```text
"eelt"
```

Since:

```text
"eelt" > "code"
```

we immediately get:

```text
"eelt"
```


3. **All characters are identical**

```text
s = "aaa"
target = "aaa"
```

There is only one permutation:

```text
"aaa"
```

It is not strictly greater.

Answer:

```text
""
```


4. **Need to change an earlier position**

```text
s = "abc"
target = "caa"
```

No character is greater than `'c'` at the first position, and the later positions cannot produce a valid permutation after matching constraints are considered.

Answer:

```text
""
```


## Lessons

* To construct the lexicographically smallest valid string, try to keep the prefix unchanged for as long as possible.
* When a string must become strictly greater, make the first difference as far to the right as possible.
* At that position, choose the smallest character that is still strictly greater.
* After making the string greater, sort all remaining characters in ascending order to minimize the suffix.
* Frequency arrays are especially useful when strings contain characters from a small fixed alphabet.
* A useful pattern for permutation construction is:

```text
Match as much as possible
        ↓
Backtrack to the latest valid position
        ↓
Make the smallest possible increase
        ↓
Fill the rest with the smallest remaining characters
```
