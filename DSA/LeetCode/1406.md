# 1406. Stone Game III 🔴

**Topics:** Dynamic Programming, Array, Game Theory

## Intuition

Imagine two players are taking turns picking coins from a row.

On every turn, a player can take **1, 2, or 3 coins** from the front. The goal is not just to collect as many coins as possible, but also to leave your opponent in the worst possible position.

Think of it like a tug of war. Every stone you take increases your score, but whatever remains gives your opponent another chance to gain points. So instead of tracking each player's score separately, it is much easier to track the **score difference** between the current player and the opponent.

If the current player can finish a turn with a score difference of `+5`, it means they are guaranteed to end the game 5 points ahead assuming both players play optimally.

## Approach

We use **top-down Dynamic Programming with memoization**.

Define:

* `best_diff(idx)` = the maximum score difference the current player can achieve starting from index `idx`.

At each position, the player has three choices:

1. Take one stone.
2. Take two stones.
3. Take three stones.

As we try each option:

* Keep a running sum of the stones taken.
* The opponent then plays optimally from the next position.
* Since `best_diff()` returns the opponent's best score difference, we subtract it from our current running sum.

The recurrence becomes:

```text
best_diff(idx) =
max(
    take1 - best_diff(idx+1),
    take2 - best_diff(idx+2),
    take3 - best_diff(idx+3)
)
```

Memoization stores the answer for every index so each state is computed only once.

Finally:

* Positive difference → Alice wins.
* Negative difference → Bob wins.
* Zero difference → Tie.

## Example Walkthrough

**Input**

```text
stoneValue = [1,2,3,7]
```

Start from index `0`.

### Option 1

Take `1`.

```text
Current score = 1
Difference = 1 - best_diff(1)
```

### Option 2

Take `1 + 2 = 3`.

```text
Difference = 3 - best_diff(2)
```

### Option 3

Take `1 + 2 + 3 = 6`.

```text
Difference = 6 - best_diff(3)
```

The recursive calls determine which option gives the largest score difference.

Eventually,

```text
best_diff(0) < 0
```

So Bob can always finish with a higher score.

**Output**

```text
"Bob"
```

## Code

```python
class Solution:
    def stoneGameIII(self, stoneValue: List[int]) -> str:
        n = len(stoneValue)
        cache={}

        def best_diff(idx):
            if idx >= n:
                return 0

            if idx in cache:
                return cache[idx]

            running_sum=0
            max_diff = float('-inf')

            for k in range(3):
                if idx + k >= n:
                    break

                running_sum += stoneValue[idx+k]
                diff = running_sum - best_diff(idx+k+1)
                
                if diff > max_diff:
                    max_diff = diff

            cache[idx] = max_diff
            return max_diff

        result = best_diff(0)

        if result > 0:
            return "Alice"
        if result < 0:
            return "Bob"
        return "Tie"
```

## Complexity

**Time Complexity**

$$
O(n)
$$

Each index is solved only once, and each state considers at most three choices.

**Space Complexity**

$$
O(n)
$$

The memoization dictionary stores one value per index, and the recursion stack can also grow up to `n`.

## Edge Cases

1. **Single stone**

```text
stoneValue = [5]
```

Alice takes the only stone.

Output:

```text
"Alice"
```

2. **All negative stones**

```text
stoneValue = [-1,-2,-3]
```

Players try to minimize their losses by choosing the best possible move.

3. **Perfect tie**

```text
stoneValue = [1,2,3,-6]
```

Both players finish with the same score.

Output:

```text
"Tie"
```

4. **Less than three stones remaining**

```text
stoneValue = [4,5]
```

The loop automatically stops when there are no more stones to take.

## Lessons

* Many game theory problems become much simpler by tracking the **score difference** instead of individual scores.
* Define the DP state from the perspective of the **current player**, allowing the same recurrence to work for both players.
* When both players play optimally, subtracting the opponent's best result naturally models the minimax strategy.
* Memoization is an effective way to optimize recursive game simulations by avoiding repeated calculations.
* Whenever a player has a small fixed number of choices at each step, recursive DP with memoization is often a natural solution.
