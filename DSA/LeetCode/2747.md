## 2747. Count Zero Request Servers 🟡

**Topics:** Array, Sorting, Sliding Window, Hash Table

### Intuition

Imagine you manage a fleet of delivery trucks across a city, and you have a log of every delivery timestamp for each truck. You want to audit several checkpoints throughout the day and answer a recurring question: "How many trucks received zero delivery orders during the $x$-minute window leading up to checkpoint $t$?"

Instead of scanning all logs from scratch for every single checkpoint (which would be inefficient when there are hundreds of thousands of queries and logs), we can sort our checkpoints in chronological order. As our time window slides forward to cover the next checkpoint, we only need to add new log entries entering the window on the right and remove old log entries sliding out of the window on the left. By keeping track of active servers in real time, we can answer each query in near constant amortized time.

### Approach

1. **Sort Queries with Original Indices:** Since queries arrive in any order, we pair each query with its original index so we can output the results in the correct initial order. Then we sort the queries by time in ascending order.
2. **Sort Logs by Time:** We sort all log entries by their timestamp. This allows us to use a two-pointer sliding window technique.
3. **Sliding Window Pointers:** Maintain two pointers, `l` and `r`, representing the start and end indices of the logs that fall within the current query time window $[Q - x, Q]$.
4. **Track Server Frequencies:** Use a hash map to count how many active requests each server currently has in the active window. Keep track of how many unique servers have at least one request.
5. **Answer Queries:** For each query, advance the window pointers to include all logs up to time $Q$, and remove logs with timestamps less than $Q - x$. The number of zero-request servers for that query is $n$ minus the count of active servers.

### Example Walkthrough

Consider:
$n = 3$, `logs` = `[[1,3],[2,6],[1,5]]`, $x = 5$, `queries` = `[10,11]`

* Sort logs by time: `[[1,3], [1,5], [2,6]]`
* Sort queries with indices: `[(10, 0), (11, 1)]`

**Query 1 (`Q = 10`, window `[5, 10]`):**

* Advance `r` to include logs with time $\le 10$. Logs at time 3, 5, and 6 fall within `[5, 10]`.
* Active servers receiving requests: Server 1 (times 3, 5) and Server 2 (time 6). Total active servers = 2.
* Zero-request servers: $3 - 2 = 1$ (Server 3). Result for index 0 is `1`.

**Query 2 (`Q = 11`, window `[6, 11]`):**

* Advance `r` to include log at time 11 (none). Advance `l` to drop logs with time $< 6$ (log at time 3 and 5 fall out).
* Active logs in `[6, 11]`: Log at time 6 (Server 2).
* Active servers receiving requests: Server 2. Total active servers = 1.
* Zero-request servers: $3 - 1 = 2$ (Servers 1 and 3). Result for index 1 is `2`.

Final output: `[1, 2]`

### Code

```python
class Solution:
    def countServers(self, n: int, logs: List[List[int]], x: int, queries: List[int]) -> List[int]:
        logs.sort(key=lambda t: t[1])
        qs = sorted((q, i) for i, q in enumerate(queries))
        
        ans = [0] * len(queries)
        counts = {}
        l=0
        r=0
        m = len(logs)
        
        for q, idx in qs:
            start = q - x
            while r < m and logs[r][1] <= q:
                srv = logs[r][0]
                counts[srv] = counts.get(srv, 0) + 1
                r += 1
                
            while l < m and logs[l][1] < start:
                srv = logs[l][0]
                counts[srv] -= 1
                if counts[srv] == 0:
                    del counts[srv]
                l += 1
                
            ans[idx] = n - len(counts)
            
        return ans

```

### Complexity

* **Time Complexity:** $O(M \log M + Q \log Q)$, where $M$ is the number of logs and $Q$ is the number of queries. Sorting logs takes $O(M \log M)$ and sorting queries takes $O(Q \log Q)$. The sliding window traverses each log at most once from both ends, taking $O(M)$ time overall.
* **Space Complexity:** $O(N + M + Q)$ to store the sorted queries, frequency dictionary, and log structures.

### Edge Cases

1. **Window Contains No Logs:** If $Q - x$ is larger than all log times, the frequency map becomes empty, and all $n$ servers are reported as zero-request servers.
2. **All Servers Active:** If every server receives at least one request within the window, the count of active servers equals $n$, resulting in `0` zero-request servers.
3. **Multiple Requests per Server:** Handled correctly by maintaining an exact frequency count and only removing servers from the active map when their request count drops to zero.

### Lessons

* **Offline Query Processing:** When queries can be sorted without violating problem constraints, sorting queries alongside sliding windows turns time-range search problems into efficient amortized linear scans.
* **Two-Pointer Frequency Tracking:** Maintaining a sliding window map with active entity counts lets you instantly query aggregate metrics like active item counts without full rescanning.
