# 1510. Stone Game IV 🔴

**Topics:** Dynamic Programming, Game Theory, Math

## Intuition

Imagine Alice and Bob are playing with a pile of stones.

On each turn, a player can remove any **perfect square** number of stones:

```text
1, 4, 9, 16, ...
```

The player who cannot make a move loses.

The important idea is to think about every possible number of stones as a **game state**.

For each `total`, we ask:

> Can the current player make a move that leaves the opponent in a losing position?

If the answer is yes, then the current player can force a win.

For example:

```text
2 -> 1 -> 0
```

With `2` stones, Alice can only remove `1`, leaving `1` stone for Bob.

Bob removes the last stone and wins.

Therefore:

```text
can_win[2] = False
```

But with `3` stones:

```text
3 -> 2
```

Alice can leave Bob with `2` stones, which is a losing position.

Therefore:

```text
can_win[3] = True
```

This gives us the main game-DP rule:

> A state is winning if there is at least one move that sends the opponent to a losing state.

## Approach

We use **Dynamic Programming**.

Let:

```text
can_win[i]
```

represent whether the current player can win when there are exactly `i` stones remaining.

We initialize:

```python
can_win = [False] * (n + 1)
```

This also gives us the base case:

```text
can_win[0] = False
```

With zero stones, there are no legal moves, so the current player loses.

### Step 1: Process every number of stones

We calculate the result for every state from `1` to `n`:

```python
for total in range(1, n + 1):
```

### Step 2: Try every perfect square

For the current state, generate:

```text
1, 4, 9, 16, ...
```

using:

```python
k = 1

while k * k <= total:
```

### Step 3: Calculate the remaining stones

If we remove `k * k` stones:

```python
remaining = total - k * k
```

The opponent now has `remaining` stones.

### Step 4: Look for a losing state

If:

```python
can_win[remaining] == False
```

then the opponent cannot force a win from that state.

Therefore, the current player can win:

```python
can_win[total] = True
```

We can immediately stop checking other moves:

```python
break
```

If every possible square leaves the opponent in a winning state, then `can_win[total]` remains `False`.

## Example Walkthrough

Consider:

```text
n = 5
```

We calculate the states one by one.

### `total = 1`

Possible move:

```text
1 - 1 = 0
```

Since:

```text
can_win[0] = False
```

Alice can win.

```text
can_win[1] = True
```

### `total = 2`

Only square available:

```text
1
```

Remaining:

```text
2 - 1 = 1
```

But:

```text
can_win[1] = True
```

So Alice cannot force a win.

```text
can_win[2] = False
```

### `total = 3`

Try removing `1`:

```text
3 - 1 = 2
```

We already know:

```text
can_win[2] = False
```

Therefore Alice can leave Bob with a losing position.

```text
can_win[3] = True
```

### `total = 4`

Alice can remove the square `4`:

```text
4 - 4 = 0
```

Since `can_win[0]` is `False`:

```text
can_win[4] = True
```

### `total = 5`

Try removing `1`:

```text
5 - 1 = 4
```

But:

```text
can_win[4] = True
```

Try removing `4`:

```text
5 - 4 = 1
```

And:

```text
can_win[1] = True
```

Every possible move gives the opponent a winning state.

Therefore:

```text
can_win[5] = False
```

The resulting states are:

```text
can_win = [False, True, False, True, True, False]
```

So for `n = 5`:

```text
False
```

## Code

```python
class Solution:
    def winnerSquareGame(self, n: int) -> bool:
        can_win = [False] * (n+1)

        for total in range(1, n+1):
            k=1
            while k*k <= total:
                remaining = total - k*k

                if not can_win[remaining]:
                    can_win[total] = True
                    break
                k+= 1

        return can_win[n]
```

## Complexity

For every `total`, we try all perfect squares up to `total`.

There are approximately $\sqrt{total}$ such squares.

Therefore, the total time complexity is:

$$
O(n\sqrt{n})
$$

The DP array stores one value for every number of stones from `0` to `n`.

Space complexity:

$$
O(n)
$$

## Edge Cases

### 1. One stone

```text
n = 1
```

Alice removes `1` stone and wins.

```text
True
```

### 2. Two stones

```text
n = 2
```

Alice removes `1`, leaving Bob with `1`.

Bob wins.

```text
False
```

### 3. Perfect square

```text
n = 4
```

Alice can remove all `4` stones immediately.

```text
True
```

### 4. Large input

```text
n = 100000
```

The DP solution handles this by reusing previously calculated states instead of solving the same smaller games repeatedly.

## Lessons

* Game problems can often be converted into **winning and losing states**.
* A state is winning if there is **at least one move to a losing state**.
* A state is losing if **every possible move leads to a winning state**.
* Dynamic programming lets us reuse the results of smaller game states.
* When the available moves follow a mathematical pattern, such as perfect squares, generate those moves directly instead of storing them separately.
* The most important pattern is:

```text
Current state
      |
      v
Try every possible move
      |
      v
Can we reach a losing state?
      |
   Yes -> Winning
   No  -> Losing
```
