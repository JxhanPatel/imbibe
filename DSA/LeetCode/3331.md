# 3331. Find Subtree Sizes After Changes 🟡

**Topics:** Tree, Depth-First Search, Hash Table, Recursion

## Intuition

Picture a company org chart where every employee wears a color-coded badge (a lowercase letter) and reports to a manager above them. During a one-time reorganization, each employee checks their direct chain of command above them for the nearest supervisor wearing the exact same badge color. If one exists, they switch to reporting directly to that matching supervisor; otherwise, they stay put.

Notice how clean this rule is: an employee only ever moves up to someone who was already above them in the original hierarchy. No loops can form, and any changes made to a manager's reporting line are already visible as we travel down into their subordinates. That lets us find each node's final parent and roll up subtree sizes in a single depth-first walk.

## Approach

This solution uses a single recursive depth-first search (`walk`) over the original tree:

1. **Build the initial tree (`kids`):** Because the input only gives `parent[i]`, we construct a child adjacency list `kids` for nodes `1` through `n - 1` so we can traverse top-down from root `0`.
2. **Track the nearest matching ancestor (`seen` and `prev`):** We initialize `ans` with `1` for every node (since every node counts itself in its own subtree) and `seen` as an empty dictionary mapping a character to the deepest ancestor along the current root-to-node path that has that character.
3. **Traverse down, then accumulate up:**
* When entering node `u` with character `ch = s[u]`, we look up `prev = seen.get(ch, -1)`. This `prev` is the closest ancestor of `u` with the same character, or `-1` if none exists.
* We update `seen[ch] = u` so any descendants inside `u`'s subtree will see `u` as the closest ancestor with character `ch`.
* We recursively call `walk(v)` for each child `v` in `kids[u]`.
* Before leaving `u`, we restore `seen[ch] = prev` (backtracking) so sibling subtrees are not affected by `u`.
* Finally, for any non-root node `u` (`if u:`), we pick its final parent `dest = prev if prev >= 0 else parent[u]` and add `ans[u]` to `ans[dest]`. Because child calls finish before parent accumulation runs, `ans[u]` already holds the complete size of `u`'s final subtree.



## Example Walkthrough

Trace `parent = [-1, 0, 0, 1, 1, 1]` and `s = "abaabc"`:

* Initial `kids`: `0 -> [1, 2]`, `1 -> [3, 4, 5]`, others `[]`. Initial `ans = [1, 1, 1, 1, 1, 1]`, `seen = {}`.
* Enter `u = 0` (`ch = 'a'`): `prev = -1`, `seen = {'a': 0}`.
* Enter `u = 1` (`ch = 'b'`): `prev = -1`, `seen = {'a': 0, 'b': 1}`.
* Enter `u = 3` (`ch = 'a'`): `prev = 0`, `seen = {'a': 3, 'b': 1}`. No children. Restore `seen['a'] = 0`. Since `prev >= 0`, `dest = 0`, so `ans[0] += ans[3]` (`ans[0]` becomes `2`).
* Enter `u = 4` (`ch = 'b'`): `prev = 1`, `seen = {'a': 0, 'b': 4}`. No children. Restore `seen['b'] = 1`. Since `prev >= 0`, `dest = 1`, so `ans[1] += ans[4]` (`ans[1]` becomes `2`).
* Enter `u = 5` (`ch = 'c'`): `prev = -1`, `seen = {'a': 0, 'b': 1, 'c': 5}`. No children. Restore `seen['c'] = -1`. Since `prev == -1`, `dest = parent[5] = 1`, so `ans[1] += ans[5]` (`ans[1]` becomes `3`).


* Back at `u = 1`: restore `seen['b'] = -1`. `dest = parent[1] = 0`, so `ans[0] += ans[1]` (`ans[0]` becomes `5`).
* Enter `u = 2` (`ch = 'a'`): `prev = 0`, `seen = {'a': 2}`. No children. Restore `seen['a'] = 0`. `dest = 0`, so `ans[0] += ans[2]` (`ans[0]` becomes `6`).


* Back at `u = 0`: restore `seen['a'] = -1`. Node `0` is the root, so no parent to add to.

Final `ans`: `[6, 3, 1, 1, 1, 1]`.

## Code & Comments

```python
class Solution:
    def findSubtreeSizes(self, parent: list[int], s: str) -> list[int]:
        kids = [[] for _ in s]

        for i in range(1, len(s)):
            kids[parent[i]].append(i)

        ans = [1] * len(s)
        seen = {}

        def walk(u: int) -> None:
            ch = s[u]
            prev = seen.get(ch, -1)
            seen[ch] = u

            for v in kids[u]:
                walk(v)
            seen[ch] = prev
            
            if u:
                dest = prev if prev >= 0 else parent[u]
                ans[dest] += ans[u]

        walk(0)
        return ans

```

## Complexity

* **Time Complexity:** $O(n)$. Building `kids` takes $O(n)$ time, and `walk` visits each of the $n$ nodes once while iterating over each edge once, doing $O(1)$ work per step.
* **Space Complexity:** $O(n)$. The `kids` adjacency list and `ans` array each use $O(n)$ space, `seen` stores at most $26$ lowercase letters ($O(1)$), and the recursion call stack uses up to $O(n)$ space on a skewed tree.

## Edge Cases

* **Single-node tree:** `parent = [-1]`, `s = "a"` produces `ans = [1]`. There are no non-root nodes to re-parent, and the root's subtree size is `1`.
* **All distinct characters:** `parent = [-1, 0, 1, 2]`, `s = "abcd"` produces `ans = [4, 3, 2, 1]`. Every `prev` lookup returns `-1`, so every node keeps its original parent and subtree sizes remain unchanged.
* **Identical characters along a chain:** `parent = [-1, 0, 1, 2]`, `s = "aaaa"` produces `ans = [4, 1, 1, 1]`. Nodes `1`, `2`, and `3` all find node `0` as their closest ancestor with `'a'`, attaching directly to `0`.

## Lessons

* **Single-pass post-order aggregation:** When changes only redirect edges upward toward ancestors, you do not need to rebuild the modified graph explicitly to sum subtree sizes. Computing `ans[u]` before adding it to `ans[dest]` works in one pass.
* **Path-scoped state with backtracking:** Saving `prev` before mutating `seen[ch]` and restoring `seen[ch] = prev` on exit is a clean, reliable way to query ancestor information during DFS without walking up the tree repeatedly.
