# 3525. Find X Value of Array II 🔴

**Topics:** Segment Tree, Modular Arithmetic, Range Query, Dynamic Updates

## Intuition

Imagine each segment of the array as a box.

For every box, we want to remember two things:

1. The product of all elements in the box modulo `k`.
2. How many non-empty prefixes of the box produce each possible remainder.

Since `k <= 5`, there are only a few possible remainders:

```text
0, 1, ..., k - 1
```

For example, if:

```text
k = 3
```

a segment can store:

```text
cnt = [2, 1, 0]
```

which means:

* 2 prefixes have product remainder `0`
* 1 prefix has product remainder `1`
* 0 prefixes have product remainder `2`

This information can be combined efficiently using a segment tree.

The important observation is that when two segments are joined, every prefix of the combined segment is either:

* completely inside the left segment, or
* the entire left segment followed by a prefix of the right segment.

That gives us a simple way to merge two nodes.

## Approach

We use a **segment tree** where every node stores:

```python
[product, count]
```

where:

* `product` is the product of the entire segment modulo `k`.
* `count[r]` is the number of non-empty prefixes whose product has remainder `r`.

### 1. Create a leaf

For one value `val`, there is only one non-empty prefix:

```text
[val]
```

Its remainder is:

```python
val % k
```

So:

```python
c[val % k] = 1
```

The leaf becomes:

```python
[val % k, c]
```

### 2. Merge two nodes

Suppose we have:

```text
left = [lp, lc]
right = [rp, rc]
```

The complete product is:

```python
(lp * rp) % k
```

Now consider the prefixes.

All prefixes entirely inside the left segment are already stored in:

```python
lc
```

So we start with:

```python
merged_cnt = lc[:]
```

For a prefix from the right segment, we must first include the **entire left segment**.

If:

```text
left product % k = lp
```

and a right prefix has remainder:

```text
r
```

then the combined remainder is:

```text
(lp * r) % k
```

Therefore:

```python
for r in range(k):
    if rc[r]:
        merged_cnt[(lp * r) % k] += rc[r]
```

This gives all prefix counts for the combined segment.

### 3. Build the segment tree

The leaves represent individual array elements:

```python
for i, v in enumerate(nums):
    tree[n+i] = make_leaf(v)
```

Then we build the internal nodes from bottom to top:

```python
i = n-1
while i >= 1:
    tree[i] = merge(tree[2*i], tree[2*i + 1])
    i -= 1
```

### 4. Handle updates

Every query first changes one value permanently.

We update the corresponding leaf:

```python
pos += n
tree[pos] = make_leaf(val)
```

Then we recalculate all of its ancestors:

```python
while pos >= 1:
    tree[pos] = merge(tree[pos*2], tree[pos*2+1])
    pos //= 2
```

Only `O(log n)` nodes need to be rebuilt.

### 5. Handle a range query

For a query:

```text
[start, n)
```

we need information about:

```text
nums[start:]
```

The `query()` function uses the standard iterative segment-tree range query.

Two temporary nodes are maintained:

```python
lnode
rnode
```

This is important because segment order matters for multiplication and prefix construction.

The left part is merged from left to right:

```python
merge(lnode, tree[lo])
```

while the right part is merged from right to left:

```python
merge(tree[hi], rnode)
```

Finally, both parts are joined:

```python
return merge(lnode, rnode)
```

The resulting node contains the prefix counts for `nums[start:]`.

Therefore, the answer for remainder `x` is simply:

```python
node[1][x]
```

## Example Walkthrough

Consider:

```text
nums = [1, 2, 3, 4, 5]
k = 3
```

Suppose:

```text
start = 3
```

The relevant range is:

```text
[4, 5]
```

The possible non-empty prefixes are:

```text
[4]
[4, 5]
```

Their products modulo `3` are:

```text
4 % 3 = 1

4 * 5 % 3 = 2
```

So the segment stores:

```text
count = [0, 1, 1]
```

If:

```text
x = 2
```

then:

```python
node[1][2]
```

returns:

```text
1
```

because exactly one prefix has product remainder `2`.

## Code

```python
from typing import List


class Solution:
    def resultArray(self, nums: List[int], k: int, queries: List[List[int]]) -> List[int]:
        n = len(nums)
        tree = [[1, [0] * k] for _ in range(2*n)]

        def make_leaf(val):
            c = [0]*k
            c[val % k] = 1
            return [val%k, c]

        def merge(left, right):
            lp, lc = left
            rp, rc = right

            merged_cnt = lc[:]
            for r in range(k):
                if rc[r]:
                    merged_cnt[(lp * r) % k] += rc[r]

            return [(lp*rp) % k, merged_cnt]

        for i, v in enumerate(nums):
            tree[n+i] = make_leaf(v)

        i = n-1
        while i >= 1:
            tree[i] = merge(tree[2*i], tree[2*i + 1])
            i -= 1

        def update(pos, val):
            pos += n
            tree[pos] = make_leaf(val)
            pos //= 2

            while pos >= 1:
                tree[pos] = merge(tree[pos*2], tree[pos*2+1])
                pos //= 2

        def query(lo, hi):
            lo += n
            hi += n
            lnode = rnode = None

            while lo < hi:
                if lo%2 == 1:
                    lnode = tree[lo] if lnode is None else merge(lnode, tree[lo])
                    lo += 1
                    
                if hi%2 == 1:
                    hi -= 1
                    rnode = tree[hi] if rnode is None else merge(tree[hi], rnode)
                lo //= 2
                hi //= 2

            if lnode is None:
                return rnode

            if rnode is None:
                return lnode
            return merge(lnode, rnode)


        res = []
        for idx, val, start, x in queries:
            update(idx, val)
            node = query(start, n)
            res.append(node[1][x])

        return res
```

## Complexity

Let:

$$
n = \text{len(nums)}
$$

Each merge examines at most `k` remainders.

Since:

$$
k \leq 5
$$

the merge operation is effectively constant time.

### Build

There are `O(n)` tree nodes:

$$
O(nk)
$$

which becomes:

$$
O(n)
$$

because `k <= 5`.

### Update

A point update changes one leaf and its ancestors:

$$
O(k\log n)
$$

With small constant `k`:

$$
O(\log n)
$$

### Query

A range query visits:

$$
O(\log n)
$$

nodes, and each merge costs `O(k)`:

$$
O(k\log n)
$$

Therefore, for `q` queries:

$$
O(nk + qk\log n)
$$

Since `k <= 5`:

$$
O(n + q\log n)
$$

Space complexity:

$$
O(nk)
$$

which is effectively:

$$
O(n)
$$

for this problem.

## Edge Cases

### 1. `k = 1`

There is only one possible remainder:

```text
0
```

Every product has remainder `0`.

### 2. Product becomes divisible by `k`

For example:

```text
nums = [2, 2]
k = 4
```

The prefixes have products:

```text
[2]     -> 2
[2, 2]  -> 0
```

The tree correctly stores the prefix producing remainder `0`.

### 3. `start` is the last index

Only one element remains.

For example:

```text
nums = [1, 2, 3]
start = 2
```

The only possible remaining array after removing a suffix is:

```text
[3]
```

So each remainder can have a count of either `0` or `1`.

### 4. Update before querying

The update must happen first:

```python
update(idx, val)
node = query(start, n)
```

because every update persists for all future queries.

## Lessons

* A segment tree can store much more than simple sums or minimums.
* The key is designing a node state that can be **merged efficiently**.
* For this problem, each node stores:

  * the product of the whole segment modulo `k`
  * the number of prefixes for every possible remainder
* The constraint `k <= 5` is extremely important because it keeps the node state small.
* When combining two segments, remember that a prefix is either:

  * completely inside the left segment
  * the entire left segment followed by a prefix of the right segment
* For ordered data, the direction of merging matters. This is why the query keeps separate `lnode` and `rnode`.
* The general pattern is:

```text
Point update
      +
Range query
      +
Small state that can be merged
      =
Segment Tree
```
