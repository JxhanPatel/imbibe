# 3348. Smallest Divisible Digit Product II 🔴

**Topics:** Greedy, Backtracking, Number Theory, Prime Factorization, Digit Manipulation

## Intuition

Imagine you have a number written on a board, and you need to change it into the **smallest possible number** whose digits multiply to a value divisible by `t`.

The key observation is that we do not actually need to calculate the entire digit product.

Every digit from `1` to `9` can be broken into prime factors:

```text
2 = 2
3 = 3
4 = 2 × 2
5 = 5
6 = 2 × 3
7 = 7
8 = 2 × 2 × 2
9 = 3 × 3
```

Since all digits only contain the primes `2, 3, 5, 7`, we can represent the requirement from `t` using counts of these four primes.

For example:

```text
t = 72
72 = 2 × 2 × 2 × 3 × 3
```

So we need:

```text
2 → 3 times
3 → 2 times
5 → 0 times
7 → 0 times
```

Now the problem becomes:

> Can we choose digits that provide enough prime factors while making the resulting number as small as possible?

The solution builds the answer from left to right. When necessary, it backtracks and increases an earlier digit, then fills the remaining positions with the smallest possible digits.


## Approach

### 1. Factorize `t`

We only need to check the primes that can appear inside digits `1` through `9`:

```python
PRIMES = (2, 3, 5, 7)
```

We repeatedly divide `t` by these primes and store how many of each factor are required.

If something remains after removing all four primes, then `t` contains a factor such as `11` or `13`.

No digit from `1` to `9` can provide that factor, so the answer is immediately:

```text
-1
```


### 2. Represent every digit by its prime factors

The `PRIME_FACTORS` table lets us quickly update our factor counts.

For example:

```text
4 → [2, 2]
6 → [2, 3]
8 → [2, 2, 2]
9 → [3, 3]
```

The helper:

```python
add(v, delta)
```

adds or removes the prime factors contributed by a digit.

A negative `delta` means:

> This digit satisfies some of the required factors.

A positive `delta` means:

> We are removing this digit from the current solution, so those factors are needed again.


### 3. Calculate the minimum number of digits still needed

The most important helper is:

```python
min_extra_needed()
```

It calculates the minimum number of digits required to satisfy the remaining prime-factor requirements.

For example:

```text
Need 3 twos
```

One `8` provides all three:

```text
8 = 2 × 2 × 2
```

so only one digit is needed.

Similarly, two `3`s can be combined into:

```text
9 = 3 × 3
```

The function therefore tries to combine factors into digits as efficiently as possible.

This gives us a powerful feasibility check:

```python
min_extra_needed() <= remaining_positions
```

If this is true, the remaining positions are enough.


### 4. Keep the existing number whenever possible

We scan the digits of `num` from left to right and subtract their factors from the required count.

However, `0` cannot be used in the product because:

```text
0 × anything = 0
```

So once we encounter the first zero, we stop treating the remaining suffix as part of the current valid prefix.

We store its position in:

```python
first_zero
```


### 5. Fill the remaining positions greedily

Starting from the first position that needs to change, we try digits:

```text
1, 2, 3, ..., 9
```

For every candidate, we temporarily subtract its factors and check whether the remaining positions are still enough.

If they are, we keep that digit.

This gives the smallest possible digit at that position.


### 6. Backtrack when necessary

Sometimes the current prefix cannot be completed.

In that case, we move backward through the number.

For each earlier digit, we try increasing it:

```text
current + 1, current + 2, ..., 9
```

The first candidate that makes the remaining suffix feasible is chosen.

Then we greedily fill everything after it with the smallest possible digits.

This is what allows us to find the **smallest number greater than or equal to `num`**.


### 7. Increase the length if necessary

If no number with the same number of digits works, the answer must contain more digits.

We append a digit and continue building the smallest valid number.

The final filling step constructs the smallest possible number satisfying the remaining prime-factor requirements.


## Example Walkthrough

Consider:

```text
num = "123"
t = 12
```

### Step 1: Factorize `t`

```text
12 = 2 × 2 × 3
```

Required factors:

```text
2 → 2
3 → 1
5 → 0
7 → 0
```

### Step 2: Process the digits

The first digit is `1`.

It contributes nothing.

The next digit is `2`:

```text
2 = 2
```

So one required `2` is satisfied.

Remaining:

```text
2 → 1
3 → 1
```

The next digit is `3`:

```text
3 = 3
```

Now only one `2` remains.

We could use a `2` as the final digit.

So:

```text
123
```

already has a digit product of:

```text
1 × 2 × 3 = 6
```

which is not divisible by `12`.

Therefore, the current number cannot satisfy the requirement.

The algorithm backtracks and tries a larger digit at an earlier position, while checking whether the remaining positions can still provide the required factors.

The important part is that it does not blindly enumerate numbers. It uses prime-factor counts to determine whether a candidate prefix can possibly be completed.


## Code

```python
PRIME_FACTORS = [[], [], [2], [3], [2, 2], [5], [2, 3], [7], [2, 2, 2], [3, 3]]
PRIMES = (2, 3, 5, 7)

class Solution:
    def smallestNumber(self, num: str, t: int) -> str:
        
        cnt = [0]*10
        for p in PRIMES:
            while t%p == 0:
                cnt[p] += 1
                t //= p
        if t!=1:
            return "-1"

        digits = [int(ch) for ch in num]

        def add(v, delta):
            for p in PRIME_FACTORS[v]:
                cnt[p] += delta

        def min_extra_needed():
            n2, n3, n5, n7 = (max(cnt[p], 0) for p in PRIMES)
            needed = n3//2 + n5 + n7
            if n3%2:
                needed += 1
                n2 -= 1
            return needed + (n2+2) // 3

        # remove digits from the count until we hit the first 0 (can't use 0s)
        first_zero = len(digits)
        for i, d in enumerate(digits):
            if d==0:
                first_zero = i
                break
            add(d,-1)

        def fill_from(idx):
            for i in range(idx, len(digits)):
                for cand in range(1, 10):
                    add(cand,-1)
                    if min_extra_needed() <= len(digits) - 1-i:
                        digits[i] = cand
                        break
                    add(cand, 1)

            return ''.join(map(str, digits))


        if min_extra_needed() <= len(digits) - first_zero:
            return fill_from(first_zero)

        # backtrack and try bumping earlier digits up
        for i in range(first_zero - 1, -1, -1):
            add(digits[i], 1)
            for cand in range(digits[i] + 1, 10):
                add(cand, -1)
                if min_extra_needed() <= len(digits) - 1-i:
                    digits[i] = cand
                    return fill_from(i+1)
                add(cand, 1)

        # nothing worked, just grow the number by a digit
        digits.append(0)
        while len(digits) < min_extra_needed():
            digits.append(0)
            
        return fill_from(0)
```

## Complexity

Let $n$ be the number of digits in `num`.

Prime factorization is effectively constant time because we only divide by four primes:

$$
O(\log t)
$$

The main work scans the digits and tries at most `9` candidates per position.

Since the number of candidate digits is constant:

$$
O(n)
$$

Space complexity:

$$
O(n)
$$

because the digits of `num` are stored in a list.


## Edge Cases

### 1. `t` contains an impossible prime factor

```text
num = "123"
t = 11
```

No digit from `1` to `9` contains a factor of `11`.

Therefore:

```text
-1
```


### 2. `t = 1`

Every positive digit product is divisible by `1`.

The main challenge is simply finding the smallest number that is at least `num`.


### 3. `num` contains zero

For example:

```text
num = "120"
```

A zero cannot be used in the digit product because it makes the product zero.

The algorithm stops at the first zero and constructs a valid suffix using digits `1` through `9`.


### 4. The current number of digits is insufficient

Sometimes no valid number with the same length exists.

The algorithm then increases the length and constructs the smallest valid number with more digits.


## Lessons

* **Prime factorization can simplify digit-product problems.** Instead of calculating potentially huge products, track the required factors.
* Digits `1` through `9` only contain the prime factors `2, 3, 5, 7`.
* **Greedy construction** works well when building the smallest valid number from left to right.
* When a greedy prefix becomes impossible, **backtracking from the rightmost position** lets us increase the number by the smallest possible amount.
* The `min_extra_needed()` helper is a useful feasibility test. It tells us whether the remaining positions are enough to satisfy the factor requirements.
* Combining factors into digits is important:

  * `2 × 2 × 2 → 8`
  * `3 × 3 → 9`
  * `2 × 3 → 6`
