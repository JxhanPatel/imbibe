# 2904. Shortest and Lexicographically Smallest Beautiful String 🟡

**Topics:** String, Sliding Window

## Intuition

Imagine you are looking at a section of a road that contains exactly `k` important checkpoints, where every checkpoint is represented by a `1`.

Your goal is to choose the shortest possible section of road containing exactly `k` checkpoints.

The `0`s are like empty spaces. They do not affect how many checkpoints are inside the section.

So once we have exactly `k` ones:

* Any unnecessary `0`s at the beginning can be removed.
* Removing those `0`s gives the shortest possible substring for the current ending position.
* If multiple shortest substrings have the same length, we choose the lexicographically smallest one.

We use a sliding window to efficiently keep track of exactly `k` ones.

## Approach

We maintain:

* `lo`: left boundary of the sliding window.
* `hi`: right boundary of the sliding window.
* `one_cnt`: number of `1`s inside the current window.
* `result`: the best beautiful substring found so far.

For every `hi`:

### 1. Add the current character

If `s[hi]` is `1`, increase `one_cnt`.

```python
if s[hi] == "1":
    one_cnt += 1
```

### 2. Remove extra `1`s

If the window contains more than `k` ones, move `lo` forward until there are at most `k` ones.

```python
while one_cnt > k:
    if s[lo] == "1":
        one_cnt -= 1
    lo += 1
```

This ensures the window never contains more than `k` ones.

### 3. Check whether we have exactly `k` ones

If we have fewer than `k` ones, the current window cannot be beautiful yet.

```python
if one_cnt != k:
    continue
```

### 4. Trim leading zeros

When the window has exactly `k` ones, leading `0`s are unnecessary.

For example:

```text
0001101
```

contains three `1`s, but:

```text
1101
```

contains the same three `1`s and is shorter.

So we use a temporary pointer `trim`:

```python
trim = lo

while s[trim] == "0":
    trim += 1
```

We do not change `lo` here because `lo` still represents the original sliding window boundary. `trim` is only used to create the shortest candidate.

### 5. Compare with the answer

Create the candidate:

```python
cand = s[trim:hi + 1]
```

Update `result` if:

1. No answer has been found yet.
2. `cand` is shorter.
3. Both have the same length, but `cand` is lexicographically smaller.

```python
if not result or len(cand) < len(result) or (
    len(cand) == len(result) and cand < result
):
    result = cand
```

Finally, return `result`.

If no substring contains exactly `k` ones, it remains an empty string.

## Example Walkthrough

Consider:

```text
s = "100011001"
k = 3
```

We need a substring containing exactly three `1`s.

### Step 1: Expand the window

Eventually, we reach:

```text
100011
```

The window contains:

```text
1 + 1 + 1 = 3 ones
```

There are no leading zeros to trim, so:

```text
cand = "100011"
result = "100011"
```

### Step 2: Continue expanding

Later, we find another window with exactly three `1`s:

```text
011001
```

Now we trim the leading zero:

```text
011001
^
remove this zero
```

The candidate becomes:

```text
11001
```

Compare it with the current result:

```text
"100011"  -> length 6
"11001"   -> length 5
```

Since `"11001"` is shorter:

```text
result = "11001"
```

After processing the entire string, the answer is:

```text
"11001"
```

## Code

```python
class Solution:
    def shortestBeautifulSubstring(self, s: str, k: int) -> str:

        n = len(s)
        lo=0
        one_cnt=0
        result = ""

        for hi in range(n):
            if s[hi] == "1":
                one_cnt += 1


            while one_cnt > k:
                if s[lo] == "1":
                    one_cnt -= 1
                lo += 1

            if one_cnt != k:
                continue

            trim = lo

            while s[trim] == "0":
                trim += 1


            cand = s[trim:hi + 1]
            if not result or len(cand)<len(result) or (len(cand)==len(result) and cand<result):
                result=cand

        return result
```

## Complexity

Let $n$ be the length of `s`.

**Time Complexity**

The `lo` pointer moves forward at most $n$ times, and `hi` also moves forward $n$ times.

The trimming loop and substring comparisons can add extra work, so with this implementation the worst-case complexity is:

$$
O(n^2)
$$

Given:

$$
n \leq 100
$$

this is easily efficient enough.

**Space Complexity**

The stored answer and candidate substrings can use up to:

$$
O(n)
$$

Therefore:

$$
O(n)
$$

extra space.

## Edge Cases

### 1. No `1` exists

```text
s = "000"
k = 1
```

We never reach `one_cnt == k`.

Output:

```text
""
```

### 2. `k` is larger than the total number of ones

```text
s = "10100"
k = 3
```

There are only two `1`s, so no beautiful substring exists.

Output:

```text
""
```

### 3. A single `1` is required

```text
s = "00100"
k = 1
```

Although substrings such as `"001"` and `"100"` are valid, the shortest one is:

```text
"1"
```

Output:

```text
"1"
```

### 4. Multiple answers have the same length

When two beautiful substrings have the same minimum length, we compare them directly:

```python
cand < result
```

Python performs lexicographical comparison automatically, so the smaller string is chosen.

## Lessons

* Sliding windows are very useful when a substring must contain exactly `k` occurrences of something.
* Keep a count of the important characters, here the number of `1`s.
* When the count becomes too large, shrink the window from the left.
* Once the window is valid, remove unnecessary characters that do not affect validity.
* A temporary pointer like `trim` can help optimize a candidate without disturbing the main sliding window.
* When a problem has multiple priorities, compare them in order:

  1. Shortest length.
  2. Lexicographically smallest among equal lengths.
* The condition:

```python
not result
or len(cand) < len(result)
or (len(cand) == len(result) and cand < result)
```

is a useful pattern for selecting the best answer when there are multiple comparison rules.
