# 835. Image Overlap 🟡
**Topics:** Array, Hash Table, Geometry

## Intuition

Imagine two transparent sheets with dots drawn on them.

You can slide one sheet in any direction, but you cannot rotate it. The goal is to position the sheets so that the maximum number of dots overlap.

Instead of actually trying every possible movement, we can look at the positions of the `1`s.

Suppose a `1` in `img1` is at:

```text
(r1, c1)
```

and a `1` in `img2` is at:

```text
(r2, c2)
```

To make these two points overlap, we need to shift the first point by:

```text
(r2 - r1, c2 - c1)
```

So every pair of `1`s gives us a possible shift.

If the **same shift appears many times**, it means many pairs of `1`s can overlap using that shift.

Therefore, we count how frequently every shift occurs and return the largest count.

## Approach

We use a **hash map with `Counter`** to count how many pairs of points require the same translation.

### 1. Find all `1` positions

First, create two lists containing the coordinates of every `1`.

```python
pts1 = [(r, c) for r in range(n) for c in range(n) if img1[r][c]]
pts2 = [(r, c) for r in range(n) for c in range(n) if img2[r][c]]
```

For example:

```text
img1:
1 0
0 1
```

gives:

```text
pts1 = [(0,0), (1,1)]
```

We do the same for `img2`.

### 2. Handle empty images

If either image has no `1`s, there can be no overlap.

```python
if not pts1 or not pts2:
    return 0
```

### 3. Count every possible shift

For every point in `img1`, compare it with every point in `img2`.

```python
for r1, c1 in pts1:
    for r2, c2 in pts2:
        shift = (r2-r1, c2-c1)
        shift_counts[shift] += 1
```

The shift:

```text
(r2-r1, c2-c1)
```

tells us how much `img1` needs to move for the two points to overlap.

For example:

```text
img1 point = (1,2)
img2 point = (3,5)
```

Then:

```text
shift = (3-1, 5-2)
      = (2,3)
```

So `img1` needs to move **2 rows down and 3 columns right**.

### 4. Find the most common shift

After counting all shifts, the shift with the highest count produces the maximum overlap.

Your code manually finds that maximum:

```python
best = 0

for cnt in shift_counts.values():
    if cnt > best:
        best = cnt
```

Finally:

```python
return best
```

## Example Walkthrough

Consider:

```text
img1 = [
    [1,1,0],
    [0,1,0],
    [0,1,0]
]

img2 = [
    [0,0,0],
    [0,1,1],
    [0,0,1]
]
```

The coordinates are:

```text
pts1 = [(0,0), (0,1), (1,1), (2,1)]

pts2 = [(1,1), (1,2), (2,2)]
```

Now compare pairs.

For example:

```text
(0,0) -> (1,1)
```

requires:

```text
shift = (1-0, 1-0)
      = (1,1)
```

Another pair:

```text
(0,1) -> (1,2)
```

requires:

```text
shift = (1-0, 2-1)
      = (1,1)
```

Another pair:

```text
(1,1) -> (2,2)
```

requires:

```text
shift = (2-1, 2-1)
      = (1,1)
```

So the shift:

```text
(1,1)
```

appears three times.

That means shifting `img1` one row down and one column right creates **3 overlapping `1`s**.

Therefore:

```text
Output = 3
```

## Code

```python
from collections import Counter
from typing import List

class Solution:
    def largestOverlap(self, img1: List[List[int]], img2: List[List[int]]) -> int:
        
        n = len(img1)

        pts1 = [(r, c) for r in range(n) for c in range(n) if img1[r][c]]
        pts2 = [(r, c) for r in range(n) for c in range(n) if img2[r][c]]

        if not pts1 or not pts2:
            return 0

        shift_counts = Counter()

        for r1, c1 in pts1:
            for r2, c2 in pts2:
                shift = (r2-r1, c2-c1)
                shift_counts[shift] += 1

        best=0
        
        for cnt in shift_counts.values():
            if cnt > best:
                best = cnt

        return best
```

## Complexity

Let `k` be the number of `1`s in each image.

Finding all points requires checking every cell:

$$
O(n^2)
$$

Then we compare every `1` in `img1` with every `1` in `img2`:

$$
O(k^2)
$$

Therefore, the total time complexity is:

$$
O(n^2 + k^2)
$$

Since at most $n^2$ cells can contain `1`s:

$$
k \leq n^2
$$

So the worst-case time complexity is:

$$
O(n^4)
$$

The `pts1`, `pts2`, and `shift_counts` structures require:

$$
O(k^2)
$$

space in the worst case.

## Edge Cases

### 1. Both images contain no `1`s

```text
img1 = [[0]]
img2 = [[0]]
```

There is nothing to overlap.

Output:

```text
0
```

### 2. One image contains no `1`s

```text
img1 = [
    [1,0],
    [0,0]
]

img2 = [
    [0,0],
    [0,0]
]
```

No matter how we translate `img1`, there can be no overlap.

Output:

```text
0
```

### 3. Single-cell images

```text
img1 = [[1]]
img2 = [[1]]
```

The two `1`s already overlap.

Output:

```text
1
```

## Lessons

* When an object can be **translated**, coordinate differences are often more useful than simulating the movement.
* A translation can be represented as:

```text
(row difference, column difference)
```

* If the same translation occurs multiple times, all those points can overlap simultaneously.
* `Counter` is useful when we need to find the most frequent transformation.
* Instead of checking every possible image position directly, we can compare the meaningful points and let their differences represent all possible shifts.
* This is a useful pattern for problems involving **coordinate matching, translations, and geometric alignment**.
