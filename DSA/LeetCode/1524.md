# 1524. Number of Sub-arrays With Odd Sum 🟡

**Topics:** Array, Dynamic Programming, Math, Prefix Sum

## Intuition

Imagine you are juggling two buckets of colorful balls at a carnival: one bucket holds **odd-sum** subarrays ending right where you are standing, and the other bucket holds **even-sum** subarrays ending at that same spot.

Whenever you walk up to a new number in the array, you are extending every subarray that ended at the previous position by tacking this new number onto the end (plus starting a brand-new single-element subarray with just this number). Parity math acts like a light switch:

* Adding an **even** number keeps the parity of a sum unchanged. Odd stays odd, and even stays even.
* Adding an **odd** number flips the parity of a sum. Odd becomes even, and even becomes odd.

Because you only care whether a sum is odd or even, you never need to compute the actual sums of subarrays. Counting how many valid subarrays end at each step with an odd sum gives you the answer in a single pass.

## Approach

Checking every subarray one by one takes $O(n^2)$ time, which is too slow when `arr.length` can reach $10^5$. Instead, we use dynamic programming on parity (odd vs. even).

As we scan through `arr` from left to right, we track two counts for subarrays ending at the current index:

1. `odd_count`: how many subarrays ending at the current element have an **odd** sum.
2. `even_count`: how many subarrays ending at the current element have an **even** sum.

For each element `num` in `arr`:

* **If `num` is even**:
* Existing odd-sum subarrays stay odd when `num` is appended.
* Existing even-sum subarrays stay even when `num` is appended, and `[num]` itself adds one more even-sum subarray.
* So `odd_count` stays the same, and `even_count` increases by `1`.


* **If `num` is odd**:
* Existing even-sum subarrays flip to **odd** when `num` is appended, and `[num]` itself is a new odd-sum subarray. So the new `odd_count` becomes old `even_count + 1`.
* Existing odd-sum subarrays flip to **even** when `num` is appended. So the new `even_count` becomes old `odd_count`.



After updating `odd_count` and `even_count` for the current position, we add `odd_count` to our running `total` and take modulo $10^9 + 7$.

## Example Walkthrough

Let's trace `arr = [1, 3, 5]`. We start with `odd_count = 0`, `even_count = 0`, and `total = 0`.

1. **Element `1` (odd)**:
* New `odd_count` = old `even_count + 1` = `0 + 1` = `1` (representing `[1]`).
* New `even_count` = old `odd_count` = `0`.
* Add `odd_count` (`1`) to `total`. Now `total = 1`.


2. **Element `3` (odd)**:
* New `odd_count` = old `even_count + 1` = `0 + 1` = `1` (representing `[3]`).
* New `even_count` = old `odd_count` = `1` (representing `[1, 3]`).
* Add `odd_count` (`1`) to `total`. Now `total = 2`.


3. **Element `5` (odd)**:
* New `odd_count` = old `even_count + 1` = `1 + 1` = `2` (representing `[1, 3, 5]` and `[5]`).
* New `even_count` = old `odd_count` = `1` (representing `[3, 5]`).
* Add `odd_count` (`2`) to `total`. Now `total = 4`.



We reach the end of the array and return `4`.

## Code

```python
class Solution:
    def numOfSubarrays(self, arr: list[int]) -> int:
        mod = 10**9 + 7
        odd_dude=0
        even_dude=0
        spicy_total=0

        for snack in arr:
            if snack % 2 == 0:
                even_dude = even_dude + 1
            
            else:
                odd_dude, even_dude = even_dude + 1, odd_dude
            spicy_total = (spicy_total + odd_dude) % mod

        return spicy_total
```

## Complexity

* **Time Complexity:** $O(n)$, where $n$ is the length of `arr`. We iterate through the array once and perform constant-time arithmetic at each step.
* **Space Complexity:** $O(1)$. We only store a handful of integer counters regardless of how large the input array gets.

## Edge Cases

1. **All even numbers**: `arr = [2, 4, 6]`
Every element is even, so `odd_dude` remains `0` at every step. Expected result: `0`.
2. **Single element**: `arr = [7]` or `arr = [8]`
For `[7]`, there is one subarray (`[7]`) with an odd sum, so the result is `1`. For `[8]`, the only subarray has an even sum, so the result is `0`.
3. **Large count triggering modulo**: `arr = [1] * 100000`
With $10^5$ ones, the total number of odd-sum subarrays exceeds $10^9 + 7$. Applying `% mod` on every iteration keeps numbers small and returns the exact modular answer.

## Lessons

* **Parity compression**: When a problem asks about odd or even sums, you rarely need exact sums. Tracking counts of odd and even states captures all the information you need.
* **Subarray ending-at-index DP**: Counting subarrays by asking "how many valid subarrays end right here?" often avoids nested loops and turns quadratic brute force into a linear pass.
* **Early modulo**: Applying `% (10**9 + 7)` inside the loop prevents intermediate values from growing unnecessarily large.
