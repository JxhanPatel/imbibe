# 3904. Smallest Stable Index II 🟡

**Topics:** Array, Prefix Maximum, Suffix Minimum

## Intuition

Imagine standing at index `i` in an array.

You want to compare two things:

* The **strongest value you have seen from the beginning** up to `i`.
* The **smallest value you can find from `i` to the end**.

The instability score is:

$$
\text{max(nums[0..i])} - \text{min(nums[i..n-1])}
$$

An index is stable if this difference is at most `k`.

The important observation is that we need two types of information:

1. A **prefix maximum** to know the largest value on the left.
2. A **suffix minimum** to know the smallest value on the right.

We can precompute the suffix minimums once, then scan from left to right to find the first stable index.

## Approach

We use a **suffix minimum array** and maintain the prefix maximum while scanning.

### Step 1: Build suffix minimums

Let:

```text
suffix_min[i] = minimum value from i to n - 1
```

For example:

```text
nums = [5, 0, 1, 4]
```

The suffix minimum array is:

```text
[0, 0, 1, 4]
```

Because:

```text
suffix_min[0] = min(5,0,1,4) = 0
suffix_min[1] = min(0,1,4)   = 0
suffix_min[2] = min(1,4)     = 1
suffix_min[3] = 4
```

We can build this from right to left.

### Step 2: Scan from left to right

While scanning, maintain:

```python
prefix_max
```

At every index:

```python
prefix_max = max(prefix_max, nums[i])
```

Now we have both values needed for the instability score:

```python
score = prefix_max - suffix_min[i]
```

If:

```python
score <= k
```

then `i` is stable.

Because we scan from left to right, the first stable index is automatically the smallest one.

## Example Walkthrough

**Input**

```text
nums = [5, 0, 1, 4]
k = 3
```

### Step 1: Build suffix minimums

```text
nums:        [5, 0, 1, 4]
suffix_min:  [0, 0, 1, 4]
```

### Step 2: Check each index

At index `0`:

```text
prefix_max = 5
suffix_min = 0

score = 5 - 0 = 5
```

`5 > 3`, so index `0` is not stable.

At index `1`:

```text
prefix_max = 5
suffix_min = 0

score = 5 - 0 = 5
```

Not stable.

At index `2`:

```text
prefix_max = 5
suffix_min = 1

score = 5 - 1 = 4
```

Not stable.

At index `3`:

```text
prefix_max = 5
suffix_min = 4

score = 5 - 4 = 1
```

Since:

```text
1 <= 3
```

index `3` is stable.

Therefore:

```text
Output: 3
```

## Code

```python
from typing import List

class Solution:
    def firstStableIndex(self, nums: list[int], k: int) -> int:
        
        n = len(nums)
        suf_min = [0]*n

        suf_min[n-1] = nums[n-1]
        i = n-2

        while i >= 0:
            suf_min[i] = nums[i] if nums[i] < suf_min[i+1] else suf_min[i+1]
            i -= 1

        pmax = nums[0]
        
        for idx, v in enumerate(nums):
            if v > pmax:
                pmax = v

            diff = pmax - suf_min[idx]
            if diff <= k:
                return idx

        return -1
```

## Complexity

We build the suffix minimum array in one traversal and then scan the array once more.

**Time Complexity**

$$
O(n)
$$

**Space Complexity**

$$
O(n)
$$

The extra space is used by the `suffix_min` array.

## Edge Cases

### 1. Single element

```text
nums = [0]
k = 0
```

At index `0`:

```text
max = 0
min = 0

score = 0
```

Since `0 <= 0`, the answer is:

```text
0
```

### 2. No stable index

```text
nums = [3, 2, 1]
k = 1
```

For every index:

```text
max = 3
min = 1

score = 2
```

Since `2 > 1`, no index is stable.

Answer:

```text
-1
```

### 3. First index is stable

```text
nums = [5, 5, 5]
k = 0
```

At index `0`:

```text
max = 5
min = 5

score = 0
```

So we immediately return:

```text
0
```

This is why scanning from left to right is useful.

## Lessons

* When a problem asks about `nums[0..i]`, think about a **prefix**.
* When it asks about `nums[i..n-1]`, think about a **suffix**.
* A running maximum can be maintained while scanning from left to right.
* A suffix minimum can be precomputed by scanning from right to left.
* Since we need the **smallest** valid index, scan indices from left to right and return immediately when the condition is satisfied.
* This is a common pattern for problems that combine information from the left and right sides of an array.

The key pattern to remember is:

```text
Prefix information + Suffix information
```

Here specifically:

```text
prefix maximum - suffix minimum <= k
```

That turns what could look like an expensive repeated range query into an efficient $O(n)$ solution.
