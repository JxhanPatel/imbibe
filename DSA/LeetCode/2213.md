# 2213. Longest Substring of One Repeating Character 🔴

**Topics:** Segment Tree, String, Range Query, Point Update

## Intuition

Imagine the string as a long row of blocks, where each block contains a character.

We repeatedly change one block and after every change we need to answer:

> What is the longest consecutive sequence containing the same character?

Rechecking the entire string after every update would be too slow. With up to $10^5$ updates, we need something closer to $O(\log n)$ per update.

A **segment tree** works well here because changing one character is a **point update**, while the answer for the entire string can be maintained at the root.

The important part is deciding what information each segment should store.

For every segment, the code stores:

```text
[lc, rc, pref, suf, best, total]
```

where:

* `lc` = leftmost character
* `rc` = rightmost character
* `pref` = longest repeating prefix
* `suf` = longest repeating suffix
* `best` = longest repeating substring anywhere in the segment
* `total` = length of the segment

The `pref` and `suf` values allow us to connect repeating sequences when two child segments are merged.

## Approach

We use a **segment tree with point updates**.

### 1. Leaf representation

Each individual character is a segment of length `1`.

For example:

```text
"a"
```

is stored as:

```python
['a', 'a', 1, 1, 1, 1]
```

Meaning:

```text
lc    = 'a'
rc    = 'a'
pref  = 1
suf   = 1
best  = 1
total = 1
```

### 2. Merging two segments

Suppose the left segment is:

```text
"aaa"
```

and the right segment is:

```text
"aab"
```

Their boundary characters are both `'a'`.

So the suffix of the left segment and the prefix of the right segment can join:

```text
"aaa" + "aab"
```

giving:

```text
"aaaaa"
```

The length of this cross-boundary sequence is:

```python
left[3] + right[2]
```

or:

```text
left.suf + right.pref
```

Therefore:

```python
best = max(best, left[3] + right[2])
```

### 3. Updating the prefix

Normally, the prefix of the combined segment is simply the prefix of the left segment.

But there is one special case.

If the **entire left segment** consists of the same character and both boundary characters match, the prefix can extend into the right segment.

The code checks:

```python
if left[2] == left[5]:
    pref = left[2] + right[2]
```

Here:

```text
left[2] = prefix
left[5] = total length
```

So:

```text
prefix == length
```

means the entire left segment is one repeating character.

### 4. Updating the suffix

The same idea applies from the right side.

If the entire right segment consists of one repeating character:

```python
if right[3] == right[5]:
    suf = left[3] + right[3]
```

This allows the suffix of the left segment to continue into the right segment.

### 5. Maintaining the best answer

There are three possibilities for the longest repeating substring after merging:

1. It is completely inside the left segment.
2. It is completely inside the right segment.
3. It crosses the boundary.

Therefore:

```python
best = max(
    left[4],
    right[4],
    left[3] + right[2]
)
```

The code handles the first two initially:

```python
best = max(left[4], right[4])
```

and then checks the cross-boundary case.

### 6. Point update

For every query:

```text
index -> new character
```

we travel down the segment tree until we reach that index.

At the leaf:

```python
tree[node] = [ch, ch, 1, 1, 1, 1]
```

Then, while returning from recursion, we merge the updated node with its sibling.

Only $O(\log n)$ nodes are affected.

The root represents the complete string, so:

```python
tree[1][4]
```

is always the longest repeating substring in the current string.

## Example Walkthrough

Consider:

```text
s = "babacc"
```

and:

```text
queryCharacters = "bcb"
queryIndices = [1, 3, 3]
```

### Query 1

Update index `1`:

```text
"babacc"
   ↓
"bbbacc"
```

The longest repeating substring is:

```text
"bbb"
```

So:

```text
answer = 3
```

### Query 2

Update index `3` to `'c'`:

```text
"bbbacc"
     ↓
"bbbccc"
```

There are two longest repeating substrings:

```text
"bbb"
"ccc"
```

Both have length `3`.

So:

```text
answer = 3
```

### Query 3

Update index `3` to `'b'`:

```text
"bbbccc"
     ↓
"bbbbcc"
```

Now the longest repeating substring is:

```text
"bbbb"
```

Therefore:

```text
answer = 4
```

Final result:

```text
[3, 3, 4]
```

## Code

```python
from typing import List

class Solution:
    def longestRepeating(self, s: str, queryCharacters: str, queryIndices: List[int]) -> List[int]:
    
        n = len(s)
        tree = [None] * (4*n)

        def merge(left, right):
            if not left:
                return right

            if not right:
                return left


            lc, rc = left[0], right[1]
            pref, suf = left[2], right[3]
            best = max(left[4], right[4])

            if left[1] == right[0]:

                if left[2] == left[5]:
                    pref = left[2] + right[2]

                if right[3] == right[5]:
                    suf = left[3] + right[3]

                best = max(best, left[3] + right[2])

            total = left[5] + right[5]

            return [lc, rc, pref, suf, best, total]


        def build(node, lo, hi):
            if lo==hi:
                tree[node] = [s[lo], s[lo],1,1,1,1]
                return


            mid = (lo+hi)//2

            build(node*2, lo, mid)
            build(node*2+1, mid+1, hi)

            tree[node] = merge(tree[node*2], tree[node*2+1])


        def update(node, lo, hi, pos, ch):
            if lo == hi:
                tree[node] = [ch, ch, 1, 1, 1, 1]
                return

            mid = (lo+hi)//2
            if pos <= mid:
                update(node * 2, lo, mid, pos, ch)

            else:
                update(node * 2+1, mid+1, hi, pos, ch)
            tree[node] = merge(tree[node * 2], tree[node * 2+1])

        build(1, 0, n-1)

        ans=[]
        for ch, pos in zip(queryCharacters, queryIndices):
            update(1, 0, n - 1, pos, ch)
            ans.append(tree[1][4])

        return ans
```

## Complexity

Building the segment tree processes all characters:

$$
O(n)
$$

Each point update travels through the height of the tree:

$$
O(\log n)
$$

For $k$ queries:

$$
O(k\log n)
$$

Therefore, the total time complexity is:

$$
O(n + k\log n)
$$

The segment tree uses:

$$
O(n)
$$

space.

## Edge Cases

### 1. Single-character string

```text
s = "a"
```

The only possible repeating substring has length `1`.

### 2. Entire string has the same character

```text
s = "aaaaa"
```

The root stores:

```text
prefix = 5
suffix = 5
best   = 5
```

So the answer is `5`.

### 3. No adjacent characters are equal

```text
s = "abcdef"
```

Every repeating substring has length `1`.

Therefore:

```text
best = 1
```

### 4. Update does not change the character

For example:

```text
s = "aabb"
index = 1
new character = 'a'
```

The character remains unchanged, and the tree still produces the correct result.

## Lessons

* **Point updates + maintaining a global/range property** is a strong signal for a segment tree.
* The hardest part of a segment tree problem is often designing the information stored at each node.
* `prefix` and `suffix` are essential when an answer can cross the boundary between two segments.
* When merging two nodes, always consider:

  * Answer from the left.
  * Answer from the right.
  * Answer crossing the boundary.
* The root represents the entire string, so `tree[1][4]` gives the answer immediately after every update.
* A useful segment-tree pattern is:

```text
Store enough information about each segment
        ↓
Define how two segments merge
        ↓
Update only the affected path
        ↓
Read the answer from the root
```

This is the key idea to remember from this problem, rather than memorizing the exact `merge()` function.
