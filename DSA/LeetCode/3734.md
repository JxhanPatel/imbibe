# 3734. Lexicographically Smallest Palindromic Permutation Greater Than Target 🔴

**Topics:** String, Greedy, Sorting, Palindrome, Lexicographical Order

## Intuition

Imagine building a palindrome from the outside toward the center.

Once we choose the left half, the right half is completely forced because it must be its mirror image. So instead of permuting all `n` characters, we only need to decide the order of roughly `n / 2` characters.

For example:

```text
Left half:  a b
Middle:     c
Right half: b a

Palindrome: abcba
```

This gives us an important observation:

> The lexicographical order of palindromes is determined by their left halves.

So the problem becomes:

1. Check whether `s` can form a palindrome.
2. Extract the characters needed for the left half.
3. Find the lexicographically smallest permutation of that half that produces a palindrome strictly greater than `target`.

The tricky part is that we cannot simply compare the left half with the first half of `target` in every case.

If the constructed left half is exactly equal to `target[:half]`, the middle character and mirrored right half determine whether the palindrome is actually greater than `target`.

So we use a greedy strategy similar to finding the next lexicographical permutation, but with duplicate characters.

## Approach

Let:

```text
n = len(s)
half = n // 2
```

### Step 1: Check if a palindromic permutation is possible

For a string to be rearranged into a palindrome:

* At most one character can have an odd frequency.

For every character:

* `freq // 2` copies go into the left half.
* If `freq` is odd, that character becomes the middle character.

For example:

```text
s = "aabbc"

frequencies:
a = 2
b = 2
c = 1

left half = "ab"
middle = "c"
```

Any valid palindrome has the form:

```text
left + middle + reversed(left)
```

### Step 2: Start with the smallest possible palindrome

Sort the left-half characters.

This creates the lexicographically smallest palindromic permutation.

For:

```text
s = "baba"
```

The half characters are:

```text
"a", "b"
```

Smallest palindrome:

```text
abba
```

If this is already strictly greater than `target`, return it.

### Step 3: Find the next lexicographical permutation

Otherwise, we need the next larger permutation of the left half.

Why?

Because changing the left half to its next lexicographical permutation gives the smallest possible larger palindrome.

We repeatedly generate the next permutation until the resulting palindrome becomes greater than `target`.

Since the alphabet has only 26 characters and `n <= 300`, we can do this efficiently using a direct greedy construction instead of enumerating all permutations.

We scan from left to right while trying to stay equal to `target`.

At each position, we try:

1. The same character as the corresponding position of `target`, if available.
2. If continuing exactly is impossible, place the smallest available character greater than the target character.
3. Fill all remaining positions with the smallest possible characters.

Then construct the full palindrome and verify that it is strictly greater than `target`.

## Example Walkthrough

### Input

```text
s = "baba"
target = "abba"
```

### Step 1: Count characters

```text
a = 2
b = 2
```

Both frequencies are even, so a palindrome is possible.

Half characters:

```text
a, b
```

### Step 2: Smallest left half

```text
left = "ab"
```

Construct the palindrome:

```text
ab + "" + ba = "abba"
```

But:

```text
"abba" == target
```

We need a strictly greater palindrome.

### Step 3: Increase the left half

The next permutation of:

```text
"ab"
```

is:

```text
"ba"
```

Construct:

```text
ba + "" + ab = "baab"
```

Now:

```text
"baab" > "abba"
```

So the answer is:

```text
"baab"
```

## Code

```python
from collections import Counter
class Solution:
    def lexPalindromicPermutation(self, s: str, target: str) -> str:
        
        cnt = Counter(s)

        odds = [c for c in cnt if cnt[c]%2]
        if len(odds) > 1:
            return ""

        half=[]
        mid = ""

        for c in sorted(cnt):
            half.extend([c] * (cnt[c]//2))

            if cnt[c] % 2:
                mid = c

        n = len(half)

        def make(left):
            return "".join(left) + mid + "".join(reversed(left))

        best_small = make(half)

        if best_small > target:
            return best_small

        target_half = target[:n]

        base_count = Counter(half)

        count = base_count.copy()
        matched = []
        ok = True

        for ch in target_half:
            if count[ch] <= 0:
                ok = False
                break

            matched.append(ch)
            count[ch] -= 1

        if ok:
            cand = make(matched)

            if cand > target:
                return cand

        i = n-1
        while i >= 0:
            prefix = target_half[:i]
            avail = base_count.copy()
            good = True

            for ch in prefix:
                if avail[ch] <= 0:
                    good = False
                    break

                avail[ch] -= 1

            if not good:
                i -= 1
                continue

            bumped = False
            for code in range(ord(target_half[i]) + 1, ord('z') + 1):
                ch = chr(code)
                if avail.get(ch, 0) <= 0:
                    continue

                avail[ch] -= 1
                rest=[]

                for c in sorted(avail):
                    rest.extend([c] * avail[c])
                left = prefix + ch + "".join(rest)
                cand = make(left)
                
                if cand > target:
                    return cand
                avail[ch] += 1  # undo, keep looking

            i -= 1

        return ""
```

## Complexity

Let $n$ be the length of `s`.

Building the frequency counts and palindrome takes:

$$
O(n)
$$

The greedy search checks at most $n / 2$ positions, and each step works with only 26 lowercase letters.

Therefore:

**Time Complexity**

$$
O(n^2)
$$

With `n <= 300`, this is easily fast enough.

**Space Complexity**

$$
O(n)
$$

We store the half characters and frequency counts.

## Edge Cases

### 1. No palindromic permutation exists

```text
s = "abc"
target = "abb"
```

All three characters have odd frequencies.

```text
a = 1
b = 1
c = 1
```

More than one odd frequency means forming a palindrome is impossible.

Output:

```text
""
```

### 2. Only one possible palindrome

```text
s = "aac"
target = "abb"
```

The only palindrome is:

```text
"aca"
```

Since:

```text
"aca" > "abb"
```

Return:

```text
"aca"
```

### 3. Largest palindrome is still not enough

```text
s = "baba"
target = "bbaa"
```

Possible palindromes:

```text
abba
baab
```

Both are smaller than or equal to `"bbaa"`.

Output:

```text
""
```

### 4. Single character

```text
s = "a"
target = "a"
```

The only palindrome is `"a"`.

It is not strictly greater than the target.

Output:

```text
""
```

## Lessons

* For palindrome permutation problems, at most one character may have an odd frequency.
* A palindrome is completely determined by its left half and optional middle character.
* This lets us reduce a permutation problem of length $n$ into one involving only about $n / 2$ characters.
* Lexicographical construction problems often use a greedy strategy:

  * Match the target as long as possible.
  * Increase the rightmost position where possible.
  * Fill everything afterward with the smallest available characters.
* When duplicates are involved, frequency counts are often more useful than generating permutations.
* Always remember that the comparison must be against the full constructed palindrome, not just its left half.
