# 301. Remove Invalid Parentheses 🔴

**Topics:** String, Backtracking, DFS

## Intuition

Imagine checking a sentence from left to right while making sure every opening bracket has a matching closing bracket.

If we ever reach a point where we have more closing parentheses than opening parentheses:

```text
)(
```

the string is already invalid at that position.

Instead of trying to remove every possible parenthesis, we remove only the **extra closing parentheses** that can fix the current invalid position.

There is an important trick here.

After fixing the string from left to right, we reverse it and run the same logic again with the parentheses swapped.

This lets the same algorithm handle both:

* Extra `)`
* Extra `(`

So we do not need separate logic for the two cases.

## Approach

We use a **stack-based DFS approach**, where each state contains:

```python
(text, start_i, start_j, opener, closer)
```

These values mean:

* `text`: current version of the string.
* `start_i`: where we should continue scanning.
* `start_j`: where we should start looking for a removable parenthesis.
* `opener`: the opening parenthesis for the current pass.
* `closer`: the closing parenthesis for the current pass.

### 1. Scan the string

We maintain a `balance`.

```python
if text[i] == opener:
    balance += 1
elif text[i] == closer:
    balance -= 1
```

A valid prefix can never have:

```text
balance < 0
```

because that means we have encountered a closing parenthesis without a matching opening parenthesis.

### 2. Find the first invalid position

When:

```python
balance < 0
```

we know that at least one `closer` before or at this position must be removed.

For example:

```text
()())
```

The scan reaches:

```text
balance = -1
```

at the final `)`.

Now we try removing each `)` from the relevant range.

### 3. Skip duplicate removals

Suppose we have:

```text
)))
```

Removing the first `)` or the second `)` can produce the same result.

So we only consider the first `)` in a consecutive group:

```python
if text[j] == closer and (j == start_j or text[j - 1] != closer):
```

This prevents duplicate states.

### 4. Continue scanning from the changed position

After removing a parenthesis:

```python
text[:j] + text[j + 1:]
```

we push the new string into `todo`.

The new state starts scanning from:

```python
i
```

because everything before this point has already been validated.

### 5. Reverse and flip the parentheses

If the complete scan finishes without finding an invalid prefix, the string is valid for the current direction.

But we may still have extra opening parentheses.

For example:

```text
((a)
```

There is no prefix where the balance becomes negative, but one `(` is unmatched.

The trick is to reverse the string:

```python
flipped = text[::-1]
```

and swap:

```text
(  <->  )
```

So the problem of finding extra opening parentheses becomes the same problem as finding extra closing parentheses.

If we are checking:

```python
opener == "("
```

we push:

```python
(")", "(")
```

For the second pass, if the scan finishes successfully, the string is fully valid.

We then add the reversed string to the answer.

## Example Walkthrough

Consider:

```text
s = "()())()"
```

Initially:

```python
todo = [(s, 0, 0, "(", ")")]
```

We scan from left to right:

```text
(  -> balance = 1
)  -> balance = 0
(  -> balance = 1
)  -> balance = 0
)  -> balance = -1
```

We found an invalid prefix.

The problematic character is `)`.

We try removing the possible `)` characters:

```text
()()()
(())()
```

These new strings are pushed into `todo`.

### Second pass

Suppose we get:

```text
()()()
```

The complete scan succeeds.

Now reverse it:

```text
()()()
```

and swap the roles of the parentheses.

The second scan also succeeds.

Therefore:

```text
()()()
```

is added to `out`.

The same process produces:

```text
(())()
```

Both are valid and require only one removal.

## Code

```python
class Solution:
    def removeInvalidParentheses(self, s: str) -> List[str]:
        out = []
        todo = [(s,0,0, "(", ")")]

        while todo:
            text, start_i, start_j, opener, closer = todo.pop()
            balance = 0
            broke = False

            for i in range(start_i, len(text)):
                if text[i] == opener:
                    balance += 1

                elif text[i] == closer:
                    balance -= 1

                if balance >= 0:
                    continue

                j = start_j
                while j <= i:
                    if text[j] == closer and (j == start_j or text[j-1] != closer):
                        todo.append((text[:j] + text[j + 1:], i, j, opener, closer))
                    j += 1

                broke = True
                break

            if broke:
                continue

            flipped = text[::-1]
            if opener == "(":
                todo.append((flipped, 0, 0, ")", "("))
            else:
                out.append(flipped)

        return out
```

## Complexity

Let $n$ be the length of the string.

The algorithm explores different strings produced by removing parentheses. In the worst case, the search can be exponential.

The time complexity is approximately:

$$
O(2^n \cdot n)
$$

The extra space used by the search is also potentially exponential:

$$
O(2^n \cdot n)
$$

The actual search is much smaller in practice because:

* Only removals that fix an invalid prefix are considered.
* Consecutive duplicate parentheses are skipped.
* The second pass handles the opposite parenthesis using the same logic.

## Edge Cases

### 1. Already valid

```text
s = "()()"
```

The first scan succeeds immediately.

The reverse pass also succeeds.

Output:

```text
["()()"]
```

### 2. Only closing parentheses

```text
s = ")))"
```

The first invalid position is immediately detected.

The algorithm removes the necessary `)` characters and eventually reaches:

```text
""
```

Output:

```text
[""]
```

### 3. Extra opening parentheses

```text
s = "((("
```

The first pass does not detect a negative balance because every character is an opener.

After reversing and swapping the parentheses, the second pass detects the unmatched opening parentheses.

The result is:

```text
[""]
```

## Lessons

* When a problem has symmetric cases, try to solve one case and **transform the other case into it**.

* A negative parenthesis balance tells us exactly where the string first becomes invalid.

* Once an invalid position is found, we only need to consider removing parentheses that can fix that position.

* Skipping consecutive identical parentheses is an important duplicate-pruning technique.

* The reverse-and-flip trick is the key idea in this solution:

  ```text
  Extra ')'  -> solve normally
  Extra '('  -> reverse + swap parentheses
  ```

* This approach avoids generating every possible string and checking each one independently.
