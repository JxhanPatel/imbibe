# 3310. Remove Methods From Project 🟡

**Topics:** Graph, Depth-First Search (DFS), Hash Table

## Intuition

Imagine a company where one employee is known to spread incorrect information.

Anyone who learns directly or indirectly from that employee also becomes unreliable. These employees form the **suspicious group**.

Now suppose management wants to remove all of them. This is only possible if **no trustworthy employee depends on any suspicious employee**. If even one trustworthy employee still relies on someone in the suspicious group, removing them would break the workflow, so nobody can be removed.

The problem naturally splits into two parts:

1. Find every suspicious method.
2. Check whether any non-suspicious method still invokes a suspicious one.


## Approach

We model the project as a **directed graph**.

* Each method is a node.
* An invocation `u -> v` means method `u` calls method `v`.

### Step 1: Build the graph

Store every invocation in an adjacency list.

```text
u ---> v
```

This lets us quickly find every method called by another method.

### Step 2: Find all suspicious methods

Start a DFS from the buggy method `k`.

Maintain:

* `bad` : all suspicious methods.
* `stack` : methods waiting to be explored.

Whenever we visit a method, we mark every method it invokes as suspicious and continue the search.

By the end, `bad` contains every method reachable from `k`.

### Step 3: Check whether removal is valid

Scan every invocation once more.

If we ever find an edge:

```text
non-suspicious ---> suspicious
```

then the suspicious group cannot be removed because an outside method still depends on it.

In that case, return every method.

### Step 4: Remove the suspicious group

If no outside method invokes a suspicious one, simply return every method that is **not** in `bad`.


## Example Walkthrough

**Input**

```text
n = 5
k = 0
invocations = [[1,2],[0,2],[0,1],[3,4]]
```

### Step 1: Build the graph

```text
0 -> 2
0 -> 1
1 -> 2
3 -> 4
```

### Step 2: DFS from method 0

Initially:

```text
bad = {0}
stack = [0]
```

Visit `0`

```text
bad = {0,1,2}
stack = [2,1]
```

Visit `1`

```text
2 is already visited
```

Visit `2`

```text
No outgoing methods
```

Final suspicious set:

```text
{0,1,2}
```

### Step 3: Check incoming calls

Inspect every invocation.

```text
1 -> 2
0 -> 2
0 -> 1
3 -> 4
```

There is no invocation from a non-suspicious method into the suspicious set.

So removal is valid.

### Step 4: Return remaining methods

```text
[3,4]
```


## Code

```python
from collections import defaultdict
from typing import List
class Solution:
    def remainingMethods(self, n: int, k: int, invocations: List[List[int]]) -> List[int]:

        adj = defaultdict(list)

        for u, v in invocations:
            adj[u].append(v)

        bad={k}
        stack=[k]

        while stack:
            curr = stack.pop()
            
            for neighbor in adj[curr]:
                if neighbor not in bad:
                    bad.add(neighbor)
                    stack.append(neighbor)

        for src, dst in invocations:
            if src not in bad and dst in bad:
                return list(range(n))

        return [i for i in range(n) if i not in bad]
```


## Complexity

**Time Complexity**

* Building the graph: $O(m)$
* DFS traversal: $O(n + m)$
* Validity check: $O(m)$
* Constructing the answer: $O(n)$

Overall:

$$
O(n + m)
$$

where:

* $n$ = number of methods
* $m$ = number of invocations

**Space Complexity**

$$
O(n + m)
$$

* Adjacency list stores all invocations.
* The `bad` set and DFS stack can each hold up to `n` methods.


## Edge Cases

1. **Only the buggy method exists**

```text
n = 1
k = 0
invocations = []
```

The only method is suspicious and can be removed.

Output:

```text
[]
```


2. **External invocation prevents removal**

```text
n = 4
k = 1
invocations = [[1,2],[0,1],[3,2]]
```

Method `0` and method `3` both invoke suspicious methods.

Output:

```text
[0,1,2,3]
```


3. **Every method is suspicious**

```text
n = 3
k = 2
invocations = [[2,0],[0,1],[1,2]]
```

DFS reaches every method, so all methods are removed.

Output:

```text
[]
```


## Lessons

* Reachability in a directed graph is a classic application of DFS or BFS.
* A hash set is an efficient way to keep track of visited or suspicious nodes.
* Sometimes graph problems require two passes: one to identify a component and another to validate whether it satisfies a given condition.
* Separating the discovery phase (finding suspicious methods) from the validation phase (checking incoming edges) leads to a clean and efficient solution.
