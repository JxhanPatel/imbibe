# 1621. Number of Sets of K Non-Overlapping Line Segments 🟡

**Topics:** Combinatorics, Dynamic Programming, Math

## Intuition

Imagine you have `n` points arranged in a row:

```text
0   1   2   3   4
•   •   •   •   •
```

You want to choose exactly `k` line segments.

Each segment needs at least two points, so a segment is determined by choosing its **left endpoint** and **right endpoint**.

The tricky part is that segments:

* cannot overlap
* can share endpoints
* do not need to cover every point

For example:

```text
(0,2) and (2,4)
```

is valid because they only touch at point `2`.

A useful way to think about the problem is to count how many endpoint choices are possible after accounting for the gaps between segments.

This leads to the formula:

$$
\boxed{\binom{n+k-1}{2k}}
$$

So the problem becomes calculating one binomial coefficient.


## Approach

We need to calculate:

$$
\binom{n+k-1}{2k}
$$

which means:

$$
\frac{(n+k-1)!}{(2k)!(n-k-1)!}
$$

But `n` can be `1000`, so directly calculating factorials would produce extremely large numbers.

Instead, we can build combinations using Pascal's identity:

$$
\binom{a}{b}=
\binom{a-1}{b-1}+
\binom{a-1}{b}
$$

We create a DP table where:

```text
dp[i][j] = C(i, j)
```

Then:

```python
dp[i][j] = dp[i-1][j-1] + dp[i-1][j]
```

We only need:

```text
C(n + k - 1, 2k)
```

Since `n <= 1000`, this is easily manageable.

### Why does `C(n+k-1, 2k)` work?

Suppose the `k` segments have endpoints:

```text
l1 <= r1 <= l2 <= r2 <= ... <= lk <= rk
```

Because segments may share endpoints, equality is allowed.

Each segment must have positive length:

```text
li < ri
```

A transformation can convert these endpoint choices into selecting `2k` positions from `n+k-1` positions.

Therefore the number of valid configurations is:

$$
\binom{n+k-1}{2k}
$$

For example, with `n = 4` and `k = 2`:

$$
\binom{4+2-1}{4}=
\binom{5}{4}=
5
$$

which matches the example.


## Example Walkthrough

### Input

```text
n = 4
k = 2
```

We need:

$$
\binom{n+k-1}{2k}
$$

Substitute the values:

$$
\binom{4+2-1}{2(2)}=
\binom{5}{4}
$$

There are 5 ways.

They are:

```text
(0,1), (1,2)
(0,1), (2,3)
(0,2), (2,3)
(0,2), (1,3)
(1,2), (2,3)
```

Therefore:

```text
Output = 5
```


## Code

```python
class Solution:
    def numberOfSets(self, n: int, k: int) -> int:
        MOD = 10**9 + 7

        target = 2*k
        total = n+k-1

        dp = [0] * (target+1)
        dp[0] = 1

        for i in range(1, total+1):
            for j in range(min(i, target), 0, -1):
                dp[j] = (dp[j] + dp[j-1]) % MOD

        return dp[target]
```

### Understanding the DP

Initially:

```text
dp[0] = 1
```

This represents:

$$
\binom{0}{0}=1
$$

For every `i`, we update combinations using:

```python
dp[j] = dp[j] + dp[j - 1]
```

This is Pascal's triangle:

```text
        1
       1 1
      1 2 1
     1 3 3 1
    1 4 6 4 1
```

After processing `n + k - 1` rows:

```text
dp[2 * k]
```

contains:

$$
\binom{n+k-1}{2k}
$$

### Why iterate backwards?

We use:

```python
for j in range(min(i, target), 0, -1):
```

instead of going forward.

This lets us reuse the same `dp` array without accidentally using values from the current iteration.


## Complexity

Let:

$$
m = n+k-1
$$

We calculate combinations up to `2k`.

**Time Complexity**

$$
O(nk)
$$

**Space Complexity**

$$
O(k)
$$

because we only store one row of Pascal's triangle.


## Edge Cases

### 1. One segment

```text
n = 3
k = 1
```

We calculate:

$$
\binom{3+1-1}{2}=
\binom{3}{2}=
3
$$

The three segments are:

```text
(0,1)
(0,2)
(1,2)
```


### 2. Maximum possible number of segments

```text
n = 4
k = 3
```

Each segment needs at least two points, but segments can share endpoints:

```text
(0,1), (1,2), (2,3)
```

There is exactly one way.

Formula:

$$
\binom{4+3-1}{6}=
\binom{6}{6}=
1
$$


### 3. Large values

```text
n = 1000
k = 500
```

The actual answer is enormous, so we take every DP value modulo:

```text
10^9 + 7
```

This keeps the numbers manageable.


## Lessons

* A difficult geometric-looking problem can sometimes become a **combinatorics problem**.
* When the answer can be represented as a binomial coefficient, Pascal's triangle is a useful way to calculate it.
* The important formula here is:

$$
\boxed{\text{Answer} = \binom{n+k-1}{2k}}
$$

* A 2D Pascal DP can be optimized to a **1D DP** by iterating backwards.
* Allowing segments to **share endpoints** is important. It is what makes configurations like `(0,2)` and `(2,3)` valid.
