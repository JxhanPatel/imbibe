# 1569. Number of Ways to Reorder Array to Get Same BST 🔴
**Topics**: Array, Divide and Conquer, Dynamic Programming, Tree, Binary Search Tree, Combinatorics

## Intuition

Imagine you are managing two separate queues of people waiting to board a flight, where the people in each queue must maintain their relative order, but you can interleave individuals from both queues in any order. How many ways can you combine them?

When building a Binary Search Tree (BST), the first element of the array always becomes the root. Every subsequent element falls into either the left subtree (if it is smaller than the root) or the right subtree (if it is larger). Because inserting elements into a BST preserves the relative order of items within the left subtree and items within the right subtree independently, the problem boils down to interleaving two sequences of lengths $L$ and $R$. The number of ways to interleave two sequences of sizes $L$ and $R$ while preserving their internal relative orders is given by the binomial coefficient $\binom{L + R}{L}$.

## Approach

1. **Precompute Combinations**: Use Pascal's triangle to precompute binomial coefficients modulo $10^9 + 7$. This allows $O(1)$ lookups for combination values during recursion.
2. **Divide and Conquer**: Define a recursive function that takes an array of numbers representing a subtree:
* If the array has fewer than three elements, there is only $1$ way to order them.
* Identify the root as the first element of the array.
* Split the remaining elements into two lists: `left` containing elements smaller than the root, and `right` containing elements greater than the root.


3. **Combine Subtree Results**: Recursively calculate the valid arrangements for the left subtree and the right subtree. Multiply these results by the number of ways to interleave the left and right elements, which is $\binom{\text{len(left)} + \text{len(right)}}{\text{len(left)}} \pmod{10^9 + 7}$.
4. **Subtract the Original**: Since the problem asks for the number of ways to *reorder* the array (excluding the original arrangement), subtract $1$ from the final result at the root level.

## Example Walkthrough

Consider `nums = [2, 1, 3]`.

1. **Root Identification**: The root is `2`.
2. **Partitioning**:
* Elements smaller than `2` go to the left subtree: `left = [1]` (size $L = 1$).
* Elements greater than `2` go to the right subtree: `right = [3]` (size $R = 1$).


3. **Combinatorics**: We need to interleave a left sequence of length $1$ and a right sequence of length $1$. The number of ways to choose positions for the left elements is $\binom{1 + 1}{1} = \binom{2}{1} = 2$.
4. **Subtree Computations**: Both left and right subtrees have size $1$, so their ways equal $1$.
5. **Total Permutations**: $2 \times 1 \times 1 = 2$.
6. **Final Answer**: Subtract the original array to get $2 - 1 = 1$ way to reorder.

## Code

```python
import math

class Solution:
    def numOfWays(self, nums: list[int]) -> int:
        MOD = 10**9+7
        n = len(nums)
                
        def dfs(arr: list[int]) -> int:
            if len(arr) <= 2:
                return 1
            
            root = arr[0]
            left = [x for x in arr if x < root]
            right = [x for x in arr if x > root]
            
            ways_left = dfs(left)
            ways_right = dfs(right)
            
            comb = math.comb(len(left) + len(right), len(left))%MOD
            
            return (comb*ways_left*ways_right) % MOD
        
        return (dfs(nums)-1) % MOD
```

## Complexity

* **Time Complexity**: $O(n^2)$ in the worst case, such as a skewed tree where partitioning takes linear time at each level and recursion depth is $n$. On average, for a balanced tree, the time complexity is $O(n \log n)$.
* **Space Complexity**: $O(n^2)$ due to the recursion stack and list slicing creating new sublists at each level of the tree.

## Edge Cases

* **Strictly Increasing Array (e.g., `[1, 2, 3]`)**: The left subtree is always empty while the right subtree takes all remaining elements. No interleaving choices exist, resulting in $0$ ways to reorder.
* **Strictly Decreasing Array (e.g., `[3, 2, 1]`)**: Similar to the increasing array, all elements fall into the left subtree, yielding $0$ ways to reorder.
* **Single Element Array (e.g., `[1]`)**: Returns $0$ ways since no reordering is possible.

## Lessons

* Tree structures often map naturally to divide and conquer algorithms when subtrees operate independently.
* Counting permutations of interleaved sequences relies directly on binomial coefficients and Pascal's identity.
* Recursion problems involving array slicing can often be optimized by passing index bounds instead of creating new sublists, improving space efficiency.
