## 3942. Minimum Operations to Sort a Permutation 🟡

**Topics:** Array, Math, Permutation


### Intuition

Imagine you have a circular track containing numbers from $0$ to $n-1$. You are allowed to take the entire track and flip its direction using a reverse operation, or slide every element one position to the left using a left rotation. Because these operations preserve the cyclic adjacency of elements, any valid sorted arrangement must either increase clockwise or increase counterclockwise around the circle.

Instead of searching through every possible sequence of operations using a slow breadth-first search, we can inspect the position of the element $0$. Since $0$ must end up at the first position in the sorted array, its location tells us exactly how many rotations are needed. We can test whether the array forms a valid ascending cycle or a valid descending cycle, and then calculate the exact number of operations required for each valid configuration.


### Approach

1. **Locate Zero:** Find the index of the number $0$ in the array, and store it in a variable named `zero`.
2. **Define Cycle Checks:** Create a helper function to verify if the array represents a valid rotated sequence. A step of `1` checks for an increasing sequence moving forward, while a step of `-1` checks for a sequence that becomes increasing when reversed.
3. **Evaluate Ascending Order (`step = 1`):**
* If `check(1)` returns true, the array is a standard rotation of the sorted sequence. We can sort it using either `zero` left rotations or by applying a reverse-rotate-reverse sequence taking `n - zero + 2` operations.


4. **Evaluate Descending Order (`step = -1`):**
* If `check(-1)` returns true, the array is a rotation of the reversed sequence. We can sort it using either `zero + 2` operations or `n - zero` operations.


5. **Return Minimum:** Track the minimum operation count across all valid paths. If no path is valid, return `-1`.


### Example Walkthrough

Consider `nums = [1, 0, 2]` with $n = 3$.

1. **Find Zero:** The number $0$ is at index `zero = 1`.
2. **Check Step 1:** Moving forward from index $1$ with step $1$, the sequence of indices is `1 -> 2 -> 0`, corresponding to values `[0, 2, 1]`. Since $0 \le 2$ but $2 > 1$, `check(1)` is false.
3. **Check Step -1:** Moving backward from index $1$ with step `-1`, the sequence of indices is `1 -> 0 -> 2`, corresponding to values `[0, 1, 2]`. Since $0 \le 1$ and $1 \le 2$, `check(-1)` is true.
4. **Calculate Operations:** For `step = -1`, the valid candidate operations are `zero + 2 = 1 + 2 = 3` or `n - zero = 3 - 1 = 2`. The minimum is `2`.
5. **Result:** Return `2`. (Operation 1: Reverse the array to get `[2, 0, 1]`. Operation 2: Rotate left by one to get `[0, 1, 2]`.)


### Code

```python
from typing import List
import math

class Solution:
    def minOperations(self, nums: List[int]) -> int:
        n = len(nums)
        zero = nums.index(0)
        
        def check(step: int) -> bool:

            for i in range(1, n):
                prev = (zero + (i-1) * step) % n
                curr = (zero + i * step) % n
                if nums[prev] > nums[curr]:
                    return False
            return True
            
        ans = math.inf
        

        if check(1):
            ans = min(ans, zero)
            ans = min(ans, n - zero + 2)
            

        if check(-1):
            ans = min(ans, zero + 2)
            ans = min(ans, n - zero)
            
        return ans if ans != math.inf else -1

```


### Complexity

* **Time Complexity:** $O(n)$, because finding the index of $0$ takes linear time, and the `check` function inspects each of the $n$ elements a constant number of times.
* **Space Complexity:** $O(1)$, since only a few primitive variables are stored regardless of the input array size.


### Edge Cases

* **Already Sorted Array (`nums = [0, 1, 2]`):** `zero` is $0$ and `check(1)` is true. The minimum operations evaluate to $0$, which is correct.
* **Fully Reversed Array (`nums = [2, 1, 0]`):** `zero` is $2$ and `check(-1)` is true. The minimum operations evaluate to $1$ (a single reverse operation).
* **Impossible Arrangement (`nums = [2, 0, 1, 3]`):** Neither `check(1)` nor `check(-1)` evaluates to true, so the function correctly returns `-1`.


### Lessons

* When a problem involves cyclic shifts and reversals on permutations, avoid simulation or graph search algorithms like breadth-first search when the array length is large ($n \le 10^5$). Instead, analyze the structural properties of rotations.
* Tracking a specific anchor element like `0` simplifies the task of aligning indices modularly.
