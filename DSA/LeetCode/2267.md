# 2267. Check if There Is a Valid Parentheses String Path 🔴

**Topics:** Dynamic Programming, Grid, String, Set

## Intuition

Think of every path as a person walking through a sequence of parentheses.

We keep a **balance**:

* `'('` increases the balance by `1`
* `')'` decreases the balance by `1`

For a parentheses string to be valid:

1. The balance can **never become negative** while reading the string.
2. The final balance must be exactly `0`.

For example:

```text
(()())
```

The balances are:

```text
(  -> 1
(  -> 2
)  -> 1
(  -> 2
)  -> 1
)  -> 0
```

So it is valid.

The challenge is that there can be many different paths through the grid. Instead of remembering every complete path, we only need to remember **which balance values are possible at each cell**.

This is the key DP idea.

## Approach

We use **dynamic programming with a set of possible balances**.

For every cell `(r, c)`, store all balance values that can be achieved when reaching that cell.

Let:

```text
dp[r][c] = set of possible balances
```

### 1. Start at `(0, 0)`

If the first character is `'('`:

```text
balance = 1
```

If it is `')'`, the path is immediately invalid because the balance would become negative.

### 2. Move from the top or left

For every reachable balance:

```text
new_balance = balance + 1   if grid[r][c] == '('
new_balance = balance - 1   if grid[r][c] == ')'
```

If:

```text
new_balance < 0
```

we discard that state.

A negative balance means we have encountered more closing parentheses than opening parentheses, so that path can never become valid later.

### 3. Check the destination

At the bottom-right cell, we need:

```text
balance == 0
```

If `0` is one of the reachable balances, a valid path exists.

### Important pruning

There are two useful observations.

First, a valid parentheses string must have even length.

The path contains:

```text
m + n - 1
```

cells.

So if:

```text
(m + n - 1) % 2 == 1
```

we can immediately return `False`.

Second, the starting cell must be `'('` and the ending cell must be `')'`.

The DP naturally handles the first condition, while the final balance handles the second.

## Example Walkthrough

Consider:

```text
grid = [
    ["(", "("],
    [")", ")"]
]
```

The path length is:

```text
2 + 2 - 1 = 3
```

Since `3` is odd, it is impossible for the resulting string to contain equal numbers of `'('` and `')'`.

So we immediately return:

```text
False
```

Now consider a valid path:

```text
(
( )
)
```

The balances become:

```text
1 -> 2 -> 1 -> 0
```

The balance never becomes negative and finishes at `0`.

Therefore:

```text
True
```

### How DP behaves

Suppose a cell can be reached with:

```text
{1, 3}
```

and the current cell contains `')'`.

Both possibilities are processed:

```text
1 -> 0
3 -> 2
```

So the new cell stores:

```text
{0, 2}
```

We do not care which exact path produced each balance. We only care that the balance is reachable.

## Code

```python
class Solution:
    def hasValidPath(self, grid: list[list[str]]) -> bool:
        m, n = len(grid), len(grid[0])

        if (m+n-1) % 2:
            return False

        if grid[0][0] == ')':
            return False

        dp = [[set() for _ in range(n)] for _ in range(m)]
        dp[0][0].add(1)

        for r in range(m):
            for c in range(n):
                if r==0 and c==0:
                    continue

                change = 1 if grid[r][c] == '(' else -1

                if r>0:
                    for balance in dp[r - 1][c]:
                        new_balance = balance + change

                        if new_balance >= 0:
                            dp[r][c].add(new_balance)

                if c>0:
                    for balance in dp[r][c-1]:
                        new_balance = balance + change

                        if new_balance >= 0:
                            dp[r][c].add(new_balance)

        return 0 in dp[m-1][n-1]
```

## Complexity

There are at most `m * n` cells.

The balance can range from `0` to roughly `m + n`, so each cell can contain up to $O(m+n)$ different balances.

Therefore:

### Time Complexity

$$
O(mn(m+n))
$$

### Space Complexity

$$
O(mn(m+n))
$$

The DP stores a set of possible balances for every cell.

## Edge Cases

### 1. Starting with `')'`

```text
[
    [")", "("],
    ["(", ")"]
]
```

The first balance would be `-1`, so the answer is immediately:

```text
False
```

### 2. Odd path length

If:

```text
m + n - 1
```

is odd, the path cannot contain an equal number of opening and closing parentheses.

For example:

```text
m = 2
n = 2
```

Path length:

```text
3
```

So the answer is:

```text
False
```

### 3. Balance becomes negative

A path might start correctly but encounter too many `')'` characters:

```text
( )
)
```

Balances:

```text
1 -> 0 -> -1
```

Once the balance becomes negative, that state is discarded.

### 4. Valid balance but wrong final value

A path can keep its balance non-negative but still finish with:

```text
balance = 2
```

That is not valid.

We specifically need:

```text
balance = 0
```

at the destination.

## Lessons

* For parentheses problems, track a **balance** rather than constructing the entire string.
* A valid parentheses sequence must never have a negative balance.
* The final balance must be `0`.
* In grid DP, when multiple paths reach the same cell, store the **different states that matter**, not every complete path.
* Here, the important state is the current balance.
* Sets are useful when several paths can produce the same state.
* Before running DP, look for mathematical pruning such as the **even-length requirement**.
* This is a useful pattern: **grid path + state tracking**. Instead of asking only "can I reach this cell?", ask "which states can I have when I reach this cell?"
