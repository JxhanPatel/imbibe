## 1352. Product of the Last K Numbers 🟡

**Topics:** Array, Math, Design, Data Stream, Prefix Sum

## Intuition

Think of keeping a running tally of how much money you have left in your wallet as you buy items one after another. If you want to know how much you spent over the last $k$ purchases, you don't have to add up the last $k$ receipts every time when you have a cumulative total. You just divide (or subtract, in the money case) the latest total by the total right before those $k$ items started.

Products have one classic catch that money doesn't: zero. Multiplying by $0$ wipes out everything that came before it, and you can't divide by $0$ later without running into trouble. Instead of fighting zeros with division, you can reset your running product list whenever a $0$ shows up and start fresh with `[1]`. Then any query asking for a window that crosses a zero naturally sees fewer items than needed and returns `0`.

## Approach

We maintain a list of running (prefix) products for the current non-zero segment:

1. **Initialize (`__init__`)**: Start the prefix list with `[1]`. Having `1` at the front acts as a clean multiplicative identity so that even when $k$ equals the full length of the active segment, indexing `len(list) - 1 - k` points right to `1`.
2. **Add a number (`add(num)`)**:
* If `num == 0`, reset the prefix list back to `[1]`. Any previous numbers before this zero are dead weight for future products.
* If `num != 0`, multiply the last value in the prefix list by `num` and append the new running product.


3. **Query the last $k$ numbers (`getProduct(k)`)**:
* Since each non-zero item adds one entry to our prefix list, the number of non-zero elements since the last reset is `len(prefix) - 1`.
* If `k` is greater than `len(prefix) - 1`, the last `k` elements of the overall stream must include at least one `0` (or a reset boundary), so return `0`.
* Otherwise, return the latest prefix product divided by the prefix product right before the window of size `k`: `prefix[-1] // prefix[-1 - k]`. Because the problem guarantees every contiguous product fits in a 32-bit integer, integer division is exact.



## Example Walkthrough

Trace the example step by step using a list `prods`:

* `ProductOfNumbers()`: `prods = [1]`
* `add(3)`: `3 != 0`, so `1 * 3 = 3` -> `prods = [1, 3]`
* `add(0)`: `0 == 0`, reset -> `prods = [1]`
* `add(2)`: `2 != 0`, so `1 * 2 = 2` -> `prods = [1, 2]`
* `add(5)`: `5 != 0`, so `2 * 5 = 10` -> `prods = [1, 2, 10]`
* `add(4)`: `4 != 0`, so `10 * 4 = 40` -> `prods = [1, 2, 10, 40]`
* `getProduct(2)`: `2 <= len(prods) - 1` (which is `3`). `prods[-1] // prods[-1 - 2] = 40 // prods[-3] = 40 // 2 = 20`. Output: `20`.
* `getProduct(3)`: `3 <= 3`. `prods[-1] // prods[-4] = 40 // prods[0] = 40 // 1 = 40`. Output: `40`.
* `getProduct(4)`: `4 > 3`, meaning our active non-zero streak only has `3` items and a zero lies within the last `4` numbers. Output: `0`.
* `add(8)`: `8 != 0`, so `40 * 8 = 320` -> `prods = [1, 2, 10, 40, 320]`
* `getProduct(2)`: `2 <= 4`. `prods[-1] // prods[-3] = 320 // 10 = 32`. Output: `32`.

## Code

```python
class ProductOfNumbers:
    def __init__(self):
        self.stash = [1]


    def add(self, num: int) -> None:
        if num == 0:
            self.stash = [1]
        else:
            self.stash.append(self.stash[-1] * num)


    def getProduct(self, k: int) -> int:
        if k >= len(self.stash):
            return 0
        return self.stash[-1] // self.stash[-1-k]
```

## Complexity

* **Time Complexity:** $O(1)$ per `add` and $O(1)$ per `getProduct` call. Appending to a list, resetting a reference, and indexing or integer-dividing take constant time. Across up to $n$ calls, total time is $O(n)$.
* **Space Complexity:** $O(n)$ in the worst case, where $n$ is the number of `add` operations without zeros. Each non-zero `add` appends one integer to the prefix list.

## Edge Cases

1. **Stream starts with or contains only zeros**:
* Calls: `add(0)`, `add(0)`, `getProduct(1)`, `getProduct(2)`
* Behavior: Both zeros reset `stash` to `[1]`, so `len(stash) - 1` is `0`. Any `k` greater than or equal to `1` returns `0`.


2. **Querying exact length of the non-zero streak**:
* Calls: `add(2)`, `add(3)`, `add(5)`, `getProduct(3)`
* Behavior: `stash` is `[1, 2, 6, 30]`. `k = 3` equals `len(stash) - 1`, so we divide `30 // 1 = 30`, giving the full streak product `2 * 3 * 5 = 30`.


3. **Single element stream**:
* Calls: `add(7)`, `getProduct(1)`
* Behavior: `stash` is `[1, 7]`. `k = 1` is valid (`1 < 2`), and `7 // 1 = 7`.



## Lessons

* **Prefix products mirror prefix sums**: Whenever you need range queries over an associative operation on a stream, precomputing cumulative values often turns $O(k)$ scans into $O(1)$ lookups.
* **Sentinel values simplify boundaries**: Starting with `[1]` lets you divide by `stash[-1 - k]` uniformly even when the slice starts at index `0`.
* **Zeros act as natural stream dividers**: Because any range containing `0` evaluates to `0`, resetting state at `0` avoids division-by-zero bugs and keeps active numbers clean.
