# 3886. Sum of Sortable Integers 🔴

**Topics:** Array, Math, Divide and Conquer

## Intuition

Imagine you have a long chain of blocks of total length $N$, and you want to slice the chain into equal contiguous segments of length $K$. For each segment of length $K$, you are allowed to perform cyclic shifts on its elements.

The goal is to determine if you can sort each segment internally using cyclic shifts, and whether the elements across all segments end up globally sorted from left to right.

If a block can be converted into a sorted array by a cyclic shift, it means that when looking at the elements in a circle, there is at most one place where a larger element is followed by a smaller element. Furthermore, to keep the entire array sorted across segment boundaries, every element in the current segment must be less than or equal to every element in the next segment.

If a chunk size $K$ allows the entire array to become completely sorted under these rules, $K$ is called a valid size. We want to find all valid block sizes $K$ that divide $N$ and compute their sum.

## Approach

Since $K$ must divide $N$, we can solve this problem in three distinct stages:

1. **Find Divisors**: Compute all positive factors $K$ of $N$.
2. **Check Each Chunk Size $K$**:
* Divide the array into $N / K$ contiguous subarrays of length $K$.
* For each subarray, verify if it can be sorted via cyclic shifts. A contiguous cyclic segment can be sorted if it contains at most **one inversion** (a position where `nums[j] > nums[j + 1]`, wrapping around from the end of the block to the start).
* Track the minimum (`lo`) and maximum (`hi`) values within each chunk.
* Verify that the blocks are ordered globally: the maximum element of chunk $i$ must not exceed the minimum element of chunk $i + 1$.


3. **Aggregate Results**: Sum all block sizes $K$ that satisfy both local and global sorting conditions.

## Example Walkthrough

Consider $nums = [3, 4, 1, 2, 5, 6]$ with length $N = 6$.

### Step 1: Find Divisors

The divisors of $6$ are $1, 2, 3, 6$.

### Step 2: Check $K = 2$

Number of chunks = $6 / 2 = 3$.

* **Chunk 1: `[3, 4]**`
* Cyclic pairs: $(3, 4)$ and $(4, 3)$.
* Inversions: `4 > 3` (1 inversion). Valid cyclic sort.
* Range: $\text{lo} = 3, \text{hi} = 4$.


* **Chunk 2: `[1, 2]**`
* Cyclic pairs: $(1, 2)$ and $(2, 1)$.
* Inversions: `2 > 1` (1 inversion). Valid cyclic sort.
* Range: $\text{lo} = 1, \text{hi} = 2$.


* **Chunk 3: `[5, 6]**`
* Cyclic pairs: $(5, 6)$ and $(6, 5)$.
* Inversions: `6 > 5` (1 inversion). Valid cyclic sort.
* Range: $\text{lo} = 5, \text{hi} = 6$.



**Global Order Check:**

* Chunk 1 bounds $(3, 4)$ vs Chunk 2 bounds $(1, 2)$: $\text{hi}_1 = 4 > \text{lo}_2 = 1$.
* Global ordering fails because chunk 1 contains larger values than chunk 2. Thus, $K = 2$ is **invalid**.

### Step 3: Check $K = 3$

Number of chunks = $6 / 3 = 2$.

* **Chunk 1: `[3, 4, 1]**`
* Cyclic pairs: $(3, 4)$, $(4, 1)$, $(1, 3)$.
* Inversions: `4 > 1` (1 inversion). Valid cyclic sort.
* Range: $\text{lo} = 1, \text{hi} = 4$.


* **Chunk 2: `[2, 5, 6]**`
* Cyclic pairs: $(2, 5)$, $(5, 6)$, $(6, 2)$.
* Inversions: `6 > 2` (1 inversion). Valid cyclic sort.
* Range: $\text{lo} = 2, \text{hi} = 6$.



**Global Order Check:**

* Chunk 1 bounds $(1, 4)$ vs Chunk 2 bounds $(2, 6)$: $\text{hi}_1 = 4 > \text{lo}_2 = 2$.
* Global ordering fails, so $K = 3$ is **invalid**.

Check $K = 6$: valid since it spans the whole array and has only 1 cyclic inversion (`6 > 3`).

Sum of valid $K$ values = $6$.

## Code

```python
class Solution:
    def sortableIntegers(self, nums: list[int]) -> int:
        n = len(nums)
        if n <= 1:
            return n

        divs = []
        d=1
        while d*d <= n:
            if n % d == 0:
                divs.append(d)

                if d != n // d:
                    divs.append(n // d)
            d+= 1

        def check(k):
            c_count = n // k
            bounds = []
            
            for i in range(c_count):
                start = i*k
                inv = 0
                lo = float('inf')
                hi = float('-inf')

                for j in range(k):
                    cur = nums[start + j]
                    nxt = nums[start + (j+1) % k]

                    if cur > nxt:
                        inv += 1
                        if inv > 1:
                            return False

                    if cur < lo:
                        lo = cur

                    if cur > hi:
                        hi = cur
                
                bounds.append((lo, hi))

            for i in range(c_count - 1):
                if bounds[i][1] > bounds[i+1][0]:
                    return False

            return True

        total=0
        for k in divs:
            if check(k):
                total += k

        return total

```

## Complexity

* **Time Complexity:** $O(d(N) \cdot N)$, where $d(N)$ is the number of divisors of $N$.
* Finding all divisors takes $O(\sqrt{N})$ time.
* For each divisor $K$, we iterate through all $N$ elements once in $O(N)$ time.
* Since $d(N)$ is small for typical constraints, the algorithm executes efficiently.


* **Space Complexity:** $O(d(N) + N / K) \approx O(N)$ auxiliary space to store the list of divisors and the chunk boundary pairs.

## Edge Cases

1. **$N \le 1$:** Arrays of length $0$ or $1$ are trivially sorted, returning $N$ directly.
2. **Already Sorted Array:** All divisors $K$ pass validation because every chunk has $0$ internal drops and non-overlapping boundary bounds.
3. **Strictly Decreasing Array:** Single-element cyclic shifts cannot fix chunks of size $K > 1$ with multiple drops, failing early.

## Lessons

* **Cyclic Order Property:** A sequence can be cyclically sorted into ascending order if and only if there is at most one pair of adjacent elements where `curr > next` when treated circularly.
* **Chunk Partitioning:** When breaking a global problem into equal chunks, validate both the **internal property** of each chunk and the **inter-chunk ordering constraint** ($\text{max}(C_i) \le \text{min}(C_{i+1})$).
