# 2089. Find Target Indices After Sorting Array 🟢

**Topics:** Array, Sorting, Counting


## Intuition

Imagine organizing a line of students by height. If you want to find the exact positions where students of a specific target height will stand after sorting everyone from shortest to tallest, you do not actually need to sort the entire line.

Instead, you only need to answer two simple questions:

1. How many students are shorter than our target height?
2. How many students share the exact same target height?

All students shorter than the target will occupy the front of the line. The students with our target height will immediately follow them in a continuous block. By counting these groups, we can compute the exact starting and ending positions instantly without doing any sorting.


## Approach

1. **Count Smaller Elements:** Iterate through the array and count how many numbers are strictly less than `target`. This gives us the exact starting index of `target` in the sorted array.
2. **Count Target Elements:** Count how many numbers in the array are equal to `target`. This gives us the total frequency of the target value.
3. **Generate Indices:** Construct a sequence of indices starting from the count of smaller elements, spanning a length equal to the frequency of the target.


## Example Walkthrough

Consider `nums = [1, 2, 5, 2, 3]` and `target = 2`.

* **Step 1: Count smaller elements.** The numbers strictly less than `2` are `[1]`. Thus, `smaller_count = 1`.
* **Step 2: Count target elements.** The numbers equal to `2` are `[2, 2]`. Thus, `target_count = 2`.
* **Step 3: Generate indices.** Starting at index `1` and taking `2` consecutive indices gives `[1, 2]`.

The result is `[1, 2]`.


## Code

```python
class Solution:
    def targetIndices(self, nums: list[int], target: int) -> list[int]:

        smaller_count=0
        target_count=0
        
        for num in nums:
            if num < target:
                smaller_count += 1

            elif num == target:
                target_count += 1
                
        return list(range(smaller_count, smaller_count + target_count))

```


## Complexity Analysis

* **Time Complexity:** $O(n)$, where $n$ is the length of `nums`. We iterate through the array twice (or once with conditions), avoiding the $O(n \log n)$ overhead of explicit sorting.
* **Space Complexity:** $O(1)$ auxiliary space, excluding the output list required to return the indices.


## Edge Cases

1. **Target Not Present:** If `target_count` is zero, the range function produces an empty list, which correctly returns `[]`.
2. **All Elements Match Target:** If every element in `nums` equals `target`, `smaller_count` is zero and `target_count` equals $n$, returning all indices from `0` to $n - 1$.
3. **Single Element Array:** For `nums = [3]` and `target = 3`, it correctly evaluates to `[0]`.


## Lessons

* **Avoid Unnecessary Sorting:** When a problem asks for positions after sorting, check if counting or bucket frequency can bypass the sorting step entirely to achieve linear time complexity.
* **Contiguous Ranges:** Equal elements always group together in a sorted array, making arithmetic ranges sufficient for index generation.
