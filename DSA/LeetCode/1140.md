# 1140. Stone Game II 🟡
**Topics:** Array, Dynamic Programming, Game Theory, Prefix/Suffix Sum

## Intuition

Imagine Alice and Bob are taking stones from a row of piles.

On each turn, a player can take between `1` and `2 * M` piles. After taking `X` piles:

```text
M = max(M, X)
```

The important part is that every move changes `M`, which affects how many piles the opponent can take next.

So we cannot simply take the largest possible number of piles every time.

Instead, we ask:

> "If it is my turn at position `idx` with the current `M`, what is the maximum number of stones I can eventually collect?"

The answer to this question can be reused for the same `(idx, M)` state, which makes this a natural **Dynamic Programming** problem.


## Approach

We use **memoized recursion** with a suffix sum array.

### 1. Build suffix sums

The array `suf` stores the total number of stones from each index to the end.

For example:

```text
piles = [2, 7, 9, 4, 4]

suf = [26, 24, 17, 8, 4, 0]
```

So:

```python
suf[idx]
```

gives us the total number of stones remaining from `idx`.

This allows us to calculate the current player's score quickly.


### 2. Define the DP state

The function:

```python
dp(idx, m)
```

means:

> Maximum stones the current player can collect starting from `idx` when the current value of `M` is `m`.

We use `@lru_cache` so that each state is calculated only once.


### 3. Try every possible move

The player can take at most:

```python
max_take = min(2 * m, n - idx)
```

piles.

For every possible number of piles `x`:

```python
for x in range(1, max_take + 1):
```

we calculate the opponent's best score:

```python
opp_score = dp(idx + x, max(m, x))
```

After taking `x` piles, the next player starts at:

```text
idx + x
```

and the new `M` becomes:

```text
max(m, x)
```


### 4. Calculate our score

There are `suf[idx]` stones remaining in total.

If the opponent eventually gets `opp_score`, then the current player must get:

```python
my_score = suf[idx] - opp_score
```

This is the key game-DP idea:

```text
My score = Total remaining stones - Opponent's best score
```

We try every possible move and keep the maximum:

```python
if my_score > best:
    best = my_score
```


## Example Walkthrough

Consider:

```text
piles = [2, 7, 9, 4, 4]
```

Initially:

```text
idx = 0
m = 1
```

So Alice can take:

```text
1 <= x <= 2
```

### Option 1: Take 1 pile

Alice takes:

```text
[2]
```

Her immediate gain is `2`.

The next state becomes:

```text
idx = 1
m = max(1, 1) = 1
```

Bob now plays optimally from this state.

The DP function calculates the best score Bob can obtain and Alice's final score becomes:

```text
total remaining - Bob's best score
```


### Option 2: Take 2 piles

Alice takes:

```text
[2, 7]
```

Now:

```text
idx = 2
m = max(1, 2) = 2
```

Bob can now take up to:

```text
2 * 2 = 4
```

piles.

Since only three piles remain, Bob can take all of them.

Alice gets:

```text
2 + 7 = 9
```


The DP compares all possible choices and finds that Alice can do better by taking only one pile initially.

Therefore:

```text
Output = 10
```


## Code

```python
from functools import lru_cache
from typing import List

class Solution:
    def stoneGameII(self, piles: List[int]) -> int:
        
        n = len(piles)

        suf = [0] * (n+1)
        for i in range(n-1,-1,-1):
            suf[i] = suf[i+1] + piles[i]

        @lru_cache(maxsize=None)
        def dp(idx, m):
            if idx >= n:
                return 0

            best=0
            max_take = min(2*m, n-idx)
            for x in range(1, max_take+1):
                opp_score = dp(idx + x, max(m, x))
                my_score = suf[idx] - opp_score
                if my_score > best:
                    best = my_score

            return best

        result = dp(0, 1)
        dp.cache_clear()
        return result
```

## Complexity

There are multiple possible `(idx, m)` states, and for each state we may try several values of `x`.

**Time Complexity**

$$
O(n^3)
$$

**Space Complexity**

$$
O(n^2)
$$

The suffix sum array itself requires:

$$
O(n)
$$

space.

The memoization table is the main source of additional space.


## Edge Cases

### 1. Single pile

```text
piles = [5]
```

Alice can take the only pile.

```text
Output = 5
```


### 2. Two piles

```text
piles = [2, 7]
```

Initially `M = 1`, so Alice can take up to `2` piles.

She can take both:

```text
2 + 7 = 9
```

```text
Output = 9
```


### 3. Large `M`

Suppose:

```text
m = 2
x = 4
```

After taking four piles:

```text
m = max(2, 4)
  = 4
```

The opponent can now take up to:

```text
2 * 4 = 8
```

piles.

This is why `m` must be included in the DP state.


## Lessons

* When both players play optimally, **Dynamic Programming** is often useful.
* Include every variable that can affect future decisions in the DP state.
* Here, the state is:

```text
(idx, m)
```

* Suffix sums let us calculate the total remaining stones in $O(1)$.
* `lru_cache` avoids recalculating the same state.
* Taking the maximum possible number of piles is not always optimal because increasing `M` can give the opponent more freedom on their next turn.
