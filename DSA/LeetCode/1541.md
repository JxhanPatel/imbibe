# 1541. Minimum Insertions to Balance a Parentheses String 🟡

Topics: String, Greedy, Stack

## Intuition

Imagine every opening parenthesis `(` is a person who requires two closing parentheses `))` to complete their task.

For example, `())` is balanced because the opening parenthesis has exactly two closing parentheses.

Now consider `(()))`. The first `(` has two closing parentheses available, but the second `(` has only one. We need to insert one more `)` to balance the string.

The key idea is to keep track of how many closing parentheses are still needed. Whenever we encounter an opening parenthesis, we need two closing parentheses. Whenever we encounter a closing parenthesis, we use one of those required parentheses.

If a closing parenthesis appears when no opening parenthesis is waiting for it, we must insert an opening parenthesis.

## Approach

We will use a greedy approach that tracks the number of closing parentheses required.

Maintain two variables:

* `insertions`: the number of parentheses we need to insert.

* `need`: the number of closing parentheses still required to balance the opening parentheses we have encountered.

### Step 1: Process each character

If the character is `(`, it requires two closing parentheses, so increase `need` by `2`.

If the character is `)`, it satisfies one required closing parenthesis, so decrease `need` by `1`.

### Step 2: Handle consecutive closing parentheses

The closing parentheses must appear in pairs `))`.

If `need` becomes odd, it means the closing parentheses required so far cannot be completed using pairs alone.

We insert one `)` to make the number even, increase `insertions` by `1`, and decrease `need` by `1` to account for the inserted character.

### Step 3: Handle unmatched closing parentheses

If `need` becomes negative, we have encountered a `)` without an opening parenthesis that can use it.

We insert an opening parenthesis `(`, which requires one more closing parenthesis pair. Since the current `)` already satisfies one of those two closing parentheses, we set `need = 1` and increase `insertions` by `1`.

### Step 4: Handle remaining requirements

After processing the string, any remaining `need` represents missing closing parentheses. Add that number to `insertions`.

Return `insertions`.

## Example Walkthrough

Input

```
s = "(()))"
```

Initially:

```
insertions = 0
need = 0
```

| Character | Action                           | `insertions` | `need` |
| --------- | -------------------------------- | ------------ | ------ |
| `(`       | Need two `)`                     | 0            | 2      |
| `(`       | Need two more `)`                | 0            | 4      |
| `)`       | Use one `)`                      | 0            | 3      |
| `)`       | Odd `need`, insert one `)` first | 1            | 2      |
| `)`       | Use one `)`                      | 1            | 1      |

After processing all characters, `need = 1`, so we need one additional closing parenthesis.

```
insertions = 1 + 1 = 2
```

However, this trace highlights an important implementation detail: when `need` is odd, the inserted `)` is used to satisfy one outstanding requirement before processing the current `)`. The corrected progression for this input is:

| Character | Action                                                | `insertions` | `need` |
| --------- | ----------------------------------------------------- | ------------ | ------ |
| `(`       | Need two `)`                                          | 0            | 2      |
| `(`       | Need two more `)`                                     | 0            | 4      |
| `)`       | Use one `)`                                           | 0            | 3      |
| `)`       | Insert `)` to complete the pair, then use current `)` | 1            | 1      |
| `)`       | Insert `(`, then use current `)`                      | 2            | 1      |

Finally, one closing parenthesis is still required, giving a total of 3 insertions for this trace. The example's correct minimum is actually 1, because inserting one `)` at the end makes `(())))` balanced. Therefore, the simpler and reliable implementation below is the one to use.

## Code


```python
class Solution:
    def minInsertions(self, s: str) -> int:
        insertions=0
        need=0

        for ch in s:
            if ch == '(':
                need += 2

                if need%2:
                    insertions += 1
                    need -= 1

            else:
                need -= 1


                if need<0:
                    insertions += 1
                    need = 1

        return insertions + need
```

## Complexity

Let nnn be the length of the string.

Time complexity

O(n)

We process every character exactly once.

Space complexity

O(1)

We use only two variables, regardless of the input size.

## Edge Cases

### 1. Already balanced

```
Input:  "())"
Output: 0
```

The opening parenthesis already has its required pair of closing parentheses.

### 2. Missing one closing parenthesis

```
Input:  "(()))"
Output: 1
```

Insert one `)` at the end to balance the string.

### 3. Closing parentheses without an opening parenthesis

```
Input:  "))())("
Output: 3
```

We need to insert opening parentheses for unmatched closing parentheses and closing parentheses for the final opening parenthesis.

### 4. Only opening parentheses

```
Input:  "((("
Output: 6
```

Each opening parenthesis requires two closing parentheses.

## Lessons

* Greedy counting can solve parentheses problems without using a stack.

* Track what is still required rather than trying to construct the balanced string.

* Because each `(` requires two `)`, the number of required closing parentheses must remain even after processing each opening parenthesis.

* When the required count becomes negative, an opening parenthesis must be inserted.

* Carefully handle odd counts and unmatched closing parentheses. These are the two key details that make this solution work.
