# 3483. Unique 3-Digit Even Numbers 🟢

**Topics:** Array, Hash Table, Enumeration

## Intuition

Imagine you have a box containing digit cards. You want to pick **three cards** to create a three-digit number.

There are three rules:

1. The first digit cannot be `0`.
2. The last digit must be even: `0, 2, 4, 6, 8`.
3. You can only use each physical copy of a digit once.

For example, if you have `[0, 2, 2]`, you can create:

```text
202
220
```

You cannot create `222` because there are only two copies of `2`.

Since there are only 10 possible digits, we can simply try every possible three-digit number from `100` to `999` and check whether its digits can be formed from the given array.

This also automatically handles duplicate digits correctly.

## Approach

We use **enumeration with digit frequencies**.

### Step 1: Count each digit

Create a frequency array of size `10`.

For:

```text
digits = [0, 2, 2]
```

we get:

```text
count[0] = 1
count[2] = 2
```

### Step 2: Try every three-digit number

We check every number from:

```text
100 to 999
```

For each number:

* Extract its hundreds digit.
* Extract its tens digit.
* Extract its units digit.
* Make sure the units digit is even.
* Check whether we have enough copies of all three digits.

Because the number is already between `100` and `999`, it cannot have a leading zero.

### Step 3: Count valid numbers

Every valid number is automatically distinct because we are checking each number only once.

## Example Walkthrough

**Input**

```text
digits = [1, 2, 3, 4]
```

The available digits are:

```text
1, 2, 3, 4
```

We need the last digit to be even, so it can only be:

```text
2 or 4
```

For example:

```text
124
```

is valid because:

* `1` is available.
* `2` is available.
* `4` is available and even.

Similarly:

```text
132
134
142
214
234
...
```

are valid.

After checking every three-digit number, we get:

```text
12
```

**Output**

```text
12
```

### Example with duplicates

For:

```text
digits = [0, 2, 2]
```

the only possible valid numbers are:

```text
202
220
```

`222` is impossible because we only have two copies of `2`.

**Output**

```text
2
```

## Code

```python
class Solution:
    def totalNumbers(self, digits: List[int]) -> int:

        avail = [0]*10

        for d in digits:
            avail[d] += 1

        total=0

        for n in range(100, 1000):
            h = n//100
            t = (n//10) % 10
            o = n % 10


            if o%2:
                continue

            avail[h] -= 1
            avail[t] -= 1
            avail[o] -= 1


            if avail[h] >= 0 and avail[t] >= 0 and avail[o] >= 0:
                total += 1

            avail[h] += 1
            avail[t] += 1
            avail[o] += 1

        return total
```

## Complexity

There are only `900` three-digit numbers, from `100` to `999`.

For each number, we perform a constant number of operations.

Therefore:

$$
O(900) = O(1)
$$

**Space Complexity**

The frequency array always contains exactly 10 elements:

$$
O(10) = O(1)
$$

## Edge Cases

### 1. No even digit

```text
digits = [1, 3, 5]
```

There is no possible even last digit.

Answer:

```text
0
```

### 2. All digits are the same

```text
digits = [6, 6, 6]
```

Only:

```text
666
```

can be created.

Answer:

```text
1
```

### 3. Zero is available

```text
digits = [0, 2, 2]
```

Zero can be used in the tens or units position, but never as the hundreds digit.

Valid numbers:

```text
202
220
```

Answer:

```text
2
```

### 4. Duplicate digits

```text
digits = [2, 2, 4]
```

A number can use `2` twice because two copies are available.

For example:

```text
224
242
422
```

are all valid.

## Lessons

* When the input domain is very small, **brute-force enumeration** can be the cleanest solution.
* A frequency array is useful when duplicate values matter.
* Checking digit availability prevents using the same copy more times than allowed.
* For numbers with digit-based restrictions, `% 10` and integer division are useful for extracting digits.
* Always check special positional rules separately, such as the requirement that the first digit cannot be zero.
* Since there are only `900` possible three-digit numbers, enumeration is easily fast enough.
