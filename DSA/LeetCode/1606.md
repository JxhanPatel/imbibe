## 1606. Find Servers That Handled Most Number of Requests 🔴

**Topics:** Array, Greedy, Heap, Simulation

### Intuition

Imagine managing a circular row of $k$ service desks. When customers arrive at specific timestamps with varying service times, each customer prefers to go to desk number $(i \pmod k)$. If that desk is busy, they look at the next desks in numerical order around the circle. If all desks are occupied, the customer is turned away.

To make this simulation lightning fast without scanning desks linearly, we can use a min-heap. Instead of storing just the raw server IDs in our heap of available servers, we can use a clever mathematical key: `i + (server_id - i) % k`. This trick shifts the server IDs relative to the current request index $i$, allowing a standard min-heap to always pop the closest available server starting from or after $i \pmod k$ in circular order.

### Approach

1. Initialize `open_boxes` as a list containing integers from $0$ to $k-1$, and convert it into a min-heap.
2. Maintain a `busy` min-heap to track active servers storing tuples of `(free_time, server_id)` and a `log` list to record which server handles each request.
3. Iterate through each request using `enumerate(zip(arrival, load))`, where $i$ is the request index, $t$ is the arrival time, and $d$ is the load duration.
4. Before processing the current arrival time $t$, clear out any servers from the `busy` heap whose release time is less than or equal to $t$. When a server is freed, push its adjusted value `i + (server_id - i) % k` back into `open_boxes`.
5. If `open_boxes` is not empty, pop the smallest value, take its modulo with $k$ to recover the actual server ID, push the completion time and server ID into `busy`, and record the server ID in `log`.
6. Finally, use `statistics.multimode` to find and return all server IDs that handled the maximum number of requests.

### Example Walkthrough

Consider $k = 3$, `arrival = [1, 2, 3]`, `load = [10, 12, 11]`.

* **Initial state:** `open_boxes = [0, 1, 2]`, `busy = []`, `log = []`.
* **Request 0 ($i = 0, t = 1, d = 10$):**
* `open_boxes` is not empty. Pop min value `0`. Actual server is `0 % 3 = 0`.
* Push `(1 + 10, 0) = (11, 0)` to `busy`. Log gets `0`.


* **Request 1 ($i = 1, t = 2, d = 12$):**
* No servers are freed because the earliest busy server frees at time 11 ($11 > 2$).
* `open_boxes` has `[1, 2]`. Pop min value `1`. Actual server is `1 % 3 = 1`.
* Push `(2 + 12, 1) = (14, 1)` to `busy`. Log gets `1`.


* **Request 2 ($i = 2, t = 3, d = 11$):**
* `open_boxes` has `[2]`. Pop min value `2`. Actual server is `2 % 3 = 2`.
* Push `(3 + 11, 2) = (14, 2)` to `busy`. Log gets `2`.


* **Final Result:** Each server handled one request, so `multimode` returns `[0, 1, 2]`.

### Code & Comments

```python
class Solution:
    def busiestServers(self, k: int, arrival: list[int], load: list[int]) -> list[int]:
        open_boxes = list(range(k))
        busy, log = [], []
        
        for i, (t, d) in enumerate(zip(arrival, load)):
            while busy and busy[0][0] <= t:
                heappush(open_boxes, i + (heappop(busy)[1]-i) % k)

            if open_boxes:
                s = heappop(open_boxes) % k
                heappush(busy, (t+d, s))
                log.append(s)
                
        return multimode(log)

```

### Complexity

* **Time Complexity:** $O(n \log k)$, where $n$ is the number of requests and $k$ is the number of servers. Each request performs push and pop operations on heaps of size at most $k$, taking logarithmic time per operation.
* **Space Complexity:** $O(k)$ to store the available servers in the `open_boxes` heap and active servers in the `busy` heap.

### Edge Cases

* **All servers busy:** When all servers are occupied and new requests arrive, `open_boxes` is empty, and requests are dropped.
* **Single server ($k = 1$):** All requests are handled by server 0 if available, or dropped if busy.
* **Multiple busiest servers:** When multiple servers handle the same maximum number of requests, `statistics.multimode` correctly returns all of them in any order.

### Lessons

* Using a heap combined with a relative indexing formula (`i + (server_id - i) % k`) eliminates the need for binary search or balanced tree structures, making the solution extremely compact and efficient in Python.
* Leveraging standard library functions like `statistics.multimode` simplifies post-processing when finding items with the maximum frequency.
