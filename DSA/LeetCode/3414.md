# 3414. Maximum Score of Non-overlapping Intervals 🔴

**Topics:** Dynamic Programming, Sorting, Binary Search, Intervals

## Intuition

Imagine you are choosing up to **4 events** for your calendar.

Each event has:

* a start position
* an end position
* a reward

You want to collect the maximum possible reward, but two events cannot overlap.

For example:

```text
[1, 3] and [3, 5]
```

cannot both be selected because they share point `3`.

The difficult part is that choosing one interval affects which intervals can be chosen next.

So instead of trying to greedily pick the interval with the largest weight, we consider two choices at every interval:

1. **Skip** the current interval.
2. **Take** the current interval and jump to the next interval that does not overlap.

We use dynamic programming to remember the best result for these choices.

## Approach

We use **sorting + binary search + dynamic programming**.

### 1. Store the original indices

First, we create tuples containing:

```text
(start, end, weight, original_index)
```

```python
events = sorted(
    (l, r, w, idx)
    for idx, (l, r, w) in enumerate(intervals)
)
```

The intervals are sorted by their start position.

We keep the original index because the final answer must contain indices from the original input.

### 2. Store all start positions

```python
starts = [e[0] for e in events]
```

Since `events` is sorted by starting position, `starts` is also sorted.

This lets us use binary search.

### 3. Find the next non-overlapping interval

For an interval ending at `r`, the next interval must start **strictly after** `r`.

For example:

```text
Current: [1, 3]
Next must start > 3
```

So we use:

```python
nxt = bisect_right(starts, r)
```

`bisect_right` finds the first position where a value greater than `r` can be inserted.

This is important because an interval starting exactly at `r` overlaps with the current interval.

### 4. Define the DP

We use:

```python
dp[i][k]
```

where:

* `i` = the current interval
* `k` = how many intervals we can still choose
* the value is `(maximum_weight, indices)`

So:

```python
dp[i][k] = (best score, lexicographically smallest indices)
```

There are only `5` possible values of `k`:

```text
0, 1, 2, 3, 4
```

because we can choose at most 4 intervals.

### 5. Skip the current interval

If we do not choose the current interval:

```python
skip = dp[i + 1][k]
```

We simply move to the next interval.

### 6. Take the current interval

If we choose the current interval, we gain its weight:

```python
take_w = w + prev_w
```

Then we jump to the next compatible interval:

```python
prev_w, prev_idx = dp[nxt][k - 1]
```

We reduce `k` by one because we just selected an interval.

The selected indices are:

```python
take_idx = tuple(sorted(prev_idx + (idx,)))
```

We sort them because the final answer must be in increasing index order.

### 7. Choose the better result

We first compare the scores.

If taking the interval gives a larger score:

```python
if take_w > skip[0]:
    best = take
```

we take it.

If skipping gives a larger score:

```python
elif take_w < skip[0]:
    best = skip
```

we skip it.

If both have the same score:

```python
else:
    best = min(take, skip)
```

Python compares the tuples lexicographically.

So when the scores are equal, it automatically chooses the lexicographically smaller index tuple.

## Example Walkthrough

Consider:

```text
intervals = [
    [1,3,2],
    [4,5,2],
    [1,5,5],
    [6,9,3],
    [6,7,1],
    [8,9,1]
]
```

The original indices are:

```text
0 -> [1,3,2]
1 -> [4,5,2]
2 -> [1,5,5]
3 -> [6,9,3]
4 -> [6,7,1]
5 -> [8,9,1]
```

After sorting by start position:

```text
[1,3,2,0]
[1,5,5,2]
[4,5,2,1]
[6,9,3,3]
[6,7,1,4]
[8,9,1,5]
```

Suppose we consider:

```text
[1,5,5]
```

with original index `2`.

Its end is `5`.

Using:

```python
bisect_right(starts, 5)
```

we find the first interval whose start is greater than `5`.

That gives us an interval starting at `6`.

The best compatible choice is:

```text
index 3 -> [6,9,3]
```

So we can select:

```text
index 2 -> weight 5
index 3 -> weight 3
```

Total score:

```text
5 + 3 = 8
```

Therefore the result is:

```text
[2, 3]
```

## Code

```python
from bisect import bisect_right
from typing import List

class Solution:
    def maximumWeight(self, intervals: List[List[int]]) -> List[int]:

        n = len(intervals)
        events = sorted((l,r,w,idx) for idx, (l,r,w) in enumerate(intervals))

        starts = [e[0] for e in events]

        dp = [[(0, ()) for _ in range(5)] for _ in range(n + 1)]

        for i in range(n-1, -1, -1):
            l, r, w, idx = events[i]
            nxt = bisect_right(starts, r)


            for k in range(1, 5):
                skip = dp[i+1][k]

                prev_w, prev_idx = dp[nxt][k-1]
                take_w = w + prev_w
                take_idx = tuple(sorted(prev_idx + (idx,)))
                take = (take_w, take_idx)

                if take_w > skip[0]:
                    best = take

                elif take_w < skip[0]:
                    best = skip
                    
                else:
                    best = min(take, skip)

                dp[i][k] = best

        return list(dp[0][4][1])
```

## Complexity

Let `n` be the number of intervals.

### Sorting

Sorting all intervals takes:

$$
O(n \log n)
$$

### Binary Search

For every interval, we perform one binary search:

$$
O(n \log n)
$$

### Dynamic Programming

For every interval, we check only 4 possible values of `k`.

Therefore:

$$
O(4n) = O(n)
$$

The overall time complexity is:

$$
O(n \log n)
$$

### Space Complexity

The DP table contains `n + 1` rows and only 5 columns:

$$
O(n)
$$

## Edge Cases

### 1. Only one interval

```text
intervals = [[1,5,10]]
```

We can select it.

Output:

```text
[0]
```

### 2. Intervals share a boundary

```text
[1,3,5]
[3,5,10]
```

These intervals overlap because both contain point `3`.

Therefore, they cannot both be selected.

This is why we use:

```python
bisect_right(starts, r)
```

instead of searching for a start position greater than or equal to `r`.

### 3. More than four compatible intervals

Even if all intervals are compatible, we can select only four.

The `k` dimension of the DP ensures that we never select more than 4 intervals.

### 4. Same maximum score

If two selections have the same total weight, we need the lexicographically smaller indices.

For example:

```text
[1, 4]
[2, 3]
```

Both may have the same score.

Since:

```text
[1, 4] < [2, 3]
```

we return:

```text
[1, 4]
```

The line:

```python
best = min(take, skip)
```

handles this automatically.

## Lessons

* **Sorting + binary search** is a powerful combination for interval problems.
* When an interval ends at `r`, use `bisect_right` when the next interval must start **strictly greater than `r`**.
* Dynamic programming is useful when every choice affects future choices.
* A small limit such as **at most 4 selections** can be included directly in the DP state.
* When a problem has a tie-breaking rule, store both the optimal value and the corresponding answer.
* Python tuple comparison is useful for lexicographical tie-breaking.
* Always preserve the original indices before sorting the input.
* A useful general pattern is:

```text
Sort
  ↓
Find next compatible position with binary search
  ↓
DP: take or skip
  ↓
Break ties lexicographically
```

This pattern appears frequently in weighted interval scheduling and other optimization problems.
