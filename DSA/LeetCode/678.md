# 678. Valid Parenthesis String 🟡

Topics: String, Dynamic Programming, Greedy, Stack

## Intuition

Imagine you're checking whether a sequence of opening and closing brackets is balanced. Every opening bracket `(` needs a matching closing bracket `)` somewhere after it.

Now introduce a wildcard `*` that can act as:

- An opening bracket `(`
- A closing bracket `)`
- An empty string `""`

The wildcard gives us flexibility. Instead of deciding immediately what each `*` means, we can keep track of the minimum and maximum possible number of unmatched opening brackets.

For example, in `(*)`, we can treat `*` as empty, giving us `()`. The string is valid.

The key idea is to track a range of possibilities rather than committing to one interpretation of each wildcard.

## Approach

We use a greedy range-tracking approach with two variables:

- `low`: The minimum possible number of unmatched opening brackets.
- `high`: The maximum possible number of unmatched opening brackets.

Initially, both are `0` because no brackets have been processed.

For every character:

1. If it is `(`, both `low` and `high` increase by `1`.
2. If it is `)`, both decrease by `1`.
3. If it is `*`:
   - `low` decreases by `1`, treating `*` as `)`.
   - `high` increases by `1`, treating `*` as `(`.

After processing each character:

- If `high < 0`, there are too many closing brackets, even under the most favorable interpretation. Return `False`.
- If `low < 0`, reset it to `0`, because we cannot have fewer than zero unmatched opening brackets. The wildcard could instead be empty.

After processing the entire string, return `True` if `low == 0`. This means at least one valid interpretation exists.

## Example Walkthrough

Input: `s = "(*))"`

Initially:

```
low = 0, high = 0
```

| Character | `low` | `high` | Explanation                          |
| --------- | ----- | ------ | ------------------------------------ |
| `(`       | 1     | 1      | Must open a bracket                  |
| `*`       | 0     | 2      | Could close, open, or disappear      |
| `)`       | 0     | 1      | Decrease both, then clamp `low` to 0 |
| `)`       | 0     | 0      | Decrease both, then clamp `low` to 0 |

The final `low` is `0`, so a valid interpretation exists.

For example, treating `*` as `(` gives:

```
(()) 
```

Output: `true`

## Code

```python
class Solution:
    def checkValidString(self, s: str) -> bool:
        low=high = 0

        for ch in s:
            if ch == '(':
                low += 1
                high += 1

            elif ch == ')':
                low -= 1
                high -= 1

            else:
                low -= 1
                high += 1

            if high < 0:
                return False

            low = max(low,0)

        return low == 0
```

## Complexity

Let $n$ be the length of the string.

Time complexity:

$$
O(n)
$$

We process each character exactly once.

Space complexity:

$$
O(1) 
$$

We use only two variables, regardless of the input size.

## Edge Cases

### 1. No wildcards

```
Input: "()"
Output: true
```

The opening and closing brackets match normally.

### 2. Unmatched opening bracket

```
Input: "("
Output: false
```

There is no closing bracket or wildcard to balance the opening bracket.

### 3. Too many closing brackets

```
Input: "())"
Output: false
```

The maximum possible number of unmatched opening brackets becomes negative, so the string cannot be valid.

### 4. Wildcards can disappear

```
Input: "(*)"
Output: true
```

Treating `*` as an empty string produces `()`.

### 5. All wildcards

```
Input: "***"
Output: true
```

All three wildcards can be treated as empty strings.

## Lessons

- Track possibilities instead of making early decisions. A wildcard may have several valid interpretations.
- Greedy range tracking can replace more complicated dynamic programming when the possible states form a continuous range.
- Clamp impossible negative counts. The minimum number of unmatched opening brackets can never be below zero.
- Reject early when necessary. If `high < 0`, even the most favorable interpretation cannot balance the string.
- Use the right state variables. Tracking only one bracket count would lose the flexibility provided by `*`.

The main takeaway is that you do not need to decide what every wildcard represents. Tracking the range of possible unmatched opening brackets is enough to determine whether a valid interpretation exists.
